# 现成 Windows OCR worker

生产入口为 `worker.py`，宿主按单个物理页交付原件路径、已核对的原件 SHA256、页号及原件坐标变换。PDFium 只渲染所选页；MinerU 4.2.1 接收页 PNG，结果包含文字、区域、原始结构、页图和模型身份。模型通过独立 Windows 环境安装，不进入仓库或安装包。文字解析器和识别器的环境分别管理。

`prepare_windows.ps1` 固定包版本并保存实际环境清单；`prepare_models.py` 按明确的上游 revision 下载模型并保存文件摘要。生产 profile 绑定 worker、渲染器和模型清单摘要。模型能加载、GPU 参与识别和内容经过核对是三个独立结果；只有完成本机实际识别后才设置 `inference_verified`。当前图表、公式和图中关系保留 `needs_review` 问题，科学正确率仍为未核验。

OCR 宿主掌握进程启动、逐页期限、取消和恢复。识别失败仍返回相同原件 SHA256、页号和 geometry，便于宿主保存失败页和准确的问题位置。宿主拒绝不同原件、页号或坐标的产物；原始 OCR 输出不能自行改写证据身份。

`compare.py` 是验证工具，用两套明确版本的现成方案处理同一批冻结 PNG。它复用单进程模型、逐页写结果、采集整机 GPU 读数，并把内容核对与进程成功分开。`run_comparison.ps1` 从独立进程监督默认 600 秒的逐页期限，核对解释器与 launcher 归属后停止超限进程，保存失败页并继续未确认页；Python 内部计时线程另作补充。`--resume` 在加载模型前核对输入清单、原 PNG 和已确认页摘要。生产调度由 Rust 来源库负责，比较工具不替代生产任务。

PaddleOCR 比较使用 3.7.0 / Paddle 3.2.1 CUDA / VL-1.6。当前比较配置将官方 `VLRecognition.batch_size` 从默认 `-1` 改为 `1`，保留官方默认解码上限；原默认配置在一个稠密中文页的长时失败独立保存。批大小是资源策略，不是质量达标声明。生产选择和 32 页真实结果见 [B16-T02 OCR 验证](../../doc/validation/B16-T02-OCR.md)。

比较脚本另保留官方 PP-StructureV3 的可选配置入口，但本项没有为它准备模型或运行页识别，状态为 `not_run`；它不进入双方案数值和质量结论。GPU 数值是整机定时采样；损坏或失败的采样记录保留并单列，不能推成 OCR 单进程的连续显存峰值。

原教材、页 PNG 和 OCR 全文只留在本机忽略的 `.artifacts` 测试目录。仓库验证报告保存页 ID、原件摘要、物理页、问题类别、结果摘要和数值，不收录教材原文。
