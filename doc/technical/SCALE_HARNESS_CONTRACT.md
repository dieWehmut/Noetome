# 规模实测合同（scale-harness-v1）

对应需求：NFR-10（1000 页 / 10000 原子 / 1000 笔记的规模目标）、NFR-12（P95 2 秒）。
本文件说明 `noetome scale measure` 到底测了什么、哪些数字来自真实运行、哪些结论是本轮**没有**达成的。

## 1 边界

- 只读：不写项目、不写 Vault、不改任何来源文件；输出根是唯一写入位置。
- 零模型、零网络：`model_calls` 与 `network_requests` 恒为 0。
- 语料是**合成的**：页面由参数生成，不含任何真实教材原文，也不证明真实教材的抽取质量。
- 不做科学判断：`scientific_status` 恒为 `not_run`。
- 本阶段只测文本分析与章节对齐在千页规模的行为，**不声称规划已达标**（见第 6 节）。

## 2 参数

| 字段 | 范围 | 说明 |
| --- | --- | --- |
| `pages` | 1..=5000 | 生成页数 |
| `headings_per_page` | 1..=12 | 每页标题块数 |
| `paragraphs_per_page` | 1..=12 | 每页每个标题下的段落块数 |

三个参数都是正整数；任何越界或不可解析的取值都在写盘前报 `SCALE_ARGUMENT`（exit 2）。
输出根必须尚不存在；父目录不可访问报 `SCALE_IO`（exit 3）。

## 3 生成规则（确定性）

第 `i` 页的第 `h` 个标题块写成 `## {i}.{h} {概念} 的第 {h} 节` 后跟一个空行；
第 `p` 个段落块写成一行散文（引用两个概念名）后跟一个空行。
概念名取自固定的八个中文名称，按 `(i + h + p)` 轮转。
**同一组参数在任何机器、任何时间都生成同样的字节。**

## 4 真实跑到什么

- 用 `crate::text::analyze` 分析每一页，得到真实的片段数、标题数、段落数与规范化摘要。
- 用 `crate::outline_model::align` 对全部页面做一次章节对齐，得到真实的出现次数与对齐警告。
- 逐页记录在 `structure.json` 的 `pages[]` 里，含 `sha256`、`byte_length`、`span_count`、`headings`。

## 5 两份产物：确定性与挂钟分离

| 文件 | 是否确定 | 内容 |
| --- | --- | --- |
| `structure.json` | 是 | 参数、计数、逐页记录、警告计数、上限、`nfr10_status`、零调用 |
| `manifest.json` | 是 | policy、producer、case_id、参数、结构产物摘要与字节数、计数、`nfr10_status` |
| `report.md` | 是 | 参数、结构产物、上限（未达标项）、边界；**不复制任何耗时读数** |
| `timings.json` | 否 | `analyse_millis`、`align_millis`、`total_millis`、`peak_rss_bytes`、说明 |

- 输出清单**不含** `timings_sha256`：一旦清单依赖耗时，同参数两次运行的清单就不再相同。
- 报告里连一行毫秒都不写。这不是省略，而是把"报告是摘要产物"落成可检查的约束：
  加一行 `分析 306 ms` 就会让 `report.md` 不再确定。
- `timings.total_millis` 必须等于 `analyse_millis + align_millis`；`note` 必须写明不参与确定性比较。
- 峰值内存读 `/proc/self/status` 的 `VmHWM`；平台不支持时写 `null`，不猜。

## 6 规划上限：如实列为未达标

`limits` 四项**直接取自** `crate::plan_model` 的常量（`MAX_TOPICS=4`、`MAX_GOALS=8`、
`MAX_CONCEPTS=64`、`MAX_ATOMS=256`），因此报告不可能与规划动词真实接受的规模脱节。

`nfr10_status` 固定为 `not_met`。理由写在 `limits.detail` 里并由报告与先验逐字复用：
千笔记、万原子的规划在本轮无法达成；本 harness 只证明文本分析与章节对齐在千页规模可用，
**不把页面处理当成规划已经达标**。这条限制既不能绕过，也不能靠调大参数掩盖。

## 7 报告与摘要

`report.md` 五节：`## 参数`、`## 结构产物`、`## 实测`、`## 规划上限（未达标项）`、`## 边界`。
其中 `## 实测` 只说明耗时在 `timings.json`，不复制读数。

命令摘要打印：输出根、参数、结构计数、耗时三行、未达标上限四项、两份产物摘要、边界三条。
摘要里的耗时是给本次运行的人看的，不进入任何文件。

## 8 输出根布局与所有权

输出根恰好四个文件：`structure.json`、`timings.json`、`report.md`、`manifest.json`。
写盘按 `create_new` + `sync_all` + 读回逐字节比对；任一步失败都删除整个输出根。
输出根已存在即拒绝，不会复用或覆盖。

## 9 CLI 与错误码

| 动词 | 说明 |
| --- | --- |
| `scale measure --pages --headings --paragraphs --output` | 生成并实测，写出四个文件 |
| `scale --help` | 用法 |

| 错误码 | exit | 触发 |
| --- | --- | --- |
| `SCALE_ARGUMENT` | 2 | 参数越界或不可解析、输出根已存在、缺少必需参数 |
| `SCALE_IO` | 3 | 父目录不可访问、创建/写入/同步/回读失败 |
| `SCALE_INTEGRITY` | 3 | 序列化失败、回读不一致、输出根文件集合不符 |
| `CLI_INVALID_ARGUMENT` | 2 | 未知子命令或缺少取值（解析层统一码） |

## 10 独立审计器

`scripts/verify_scale_harness.py` 不 import 产品、不跑 CLI 判定，独立复刻生成器与分段模型：

- 包模式：参数声明、先验、用例表的字段集合与内容，逐项复算 `counts` 与 `pages`。
- 含输出根：布局（恰四个文件、无符号链接）、结构产物 strict、耗时自洽、清单摘要与计数、报告六条必须有与"不得含耗时"。
- 复算与实测逐项比对：`counts`、`pages`、`spec`、`nfr10_status`、四项上限。

先验里的 `limits.detail` 与报告里的一节必须逐字相同——未达标项是结论的一部分，不是附注。

## 11 本轮明确不做

1. 不做千笔记、万原子的**规划**（规划器上限未放宽，只是如实报告）。
2. 不做真实 PDF 或真实教材抽取；合成页面只测文本管道。
3. 不测并发、不测多进程、不测长时间运行的稳定性（那是 soak 的职责）。
4. 不做 P95 延迟统计：单次运行的毫秒数是观测值，不是分布。
5. 不判断科学正确性、不生成任何知识条目。
6. 不比较不同模型或不同编译选项的性能。
7. 不把合成语料的字节数当成真实教材规模的代表。
