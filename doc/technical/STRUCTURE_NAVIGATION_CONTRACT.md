# 同类结构一致性与导航复习契约（B10-T03）

本契约定义 Noetome 第一版「同类结构一致性与导航复习组织」：作者包声明什么、
冻结根里存什么、章节骨架与正文标题怎么比对、错位与缺失为什么必须分别报出、
同一概念为什么只能有一处完整解释、生成链接为什么只能指向已声明目标，
以及输出根的字节确定性从哪来。

对应需求：FR-16（同类结构一致性）、FR-17（唯一规范解释位置）、
FR-19（导航与复习组织）、FR-25（Obsidian 兼容编译）、
AC-17（唯一解释）、AC-19（特殊链接）。

## 1. 边界

- 本层只做**结构一致性与链接核对**：把每份笔记的标题判成就位、位置偏离、多余、缺失或空节，
  把正文里的 wikilink 判成可解析、目标缺失、标题缺失或有歧义，并据概念表生成导航与引用链接。
  它**不改写笔记正文**、**不补齐缺失章节**、**不重排小节**、**不生成知识内容**。
- 本层**不联网、不调用模型**。输出固定写 `model_calls: 0`、`network_requests: 0`。
- 本层**不写知识库、不写托管 Vault**，也不接管已有目录。`adopt` 只创建全新的结构根。
- **偏离只报告不修复**：FR-16 要求"通用模板是结构规范而非强制填空"，所以本层输出的是
  位置清单（第几节、哪一节多余），不是一次自动重排。
- **不虚构重点**：复习提示只来自作者包声明，不写考试频次或出题概率（FR-19 明文禁止）。
- 骨架键（`key`）必须是 ASCII 标识符；骨架标题（`title`）才是中文读者看到的文字。
  这一条是为了让骨架在 JSON 里可稳定引用，不是内容约定。

## 2. 作者包（输入侧）

`family.json` 字段：

| 字段 | 说明 |
| --- | --- |
| `policy` | 固定 `structure-family-v1` |
| `schema_version` | 固定 `1` |
| `producer` | 作者包固定 `fixture_author` |
| `case_id` | 标识符（ASCII 字母数字加 `-_.`） |
| `description` | 不超过 600 字符，说明本包只验证工程契约 |
| `family` | 主题族名（中文可），出现在导航标题与报告里 |
| `concepts` | 相对路径，指向概念表 `.json` |
| `skeleton[]` | `key`（ASCII 标识符）、`title`（中文）、`requirement`（`required`/`optional`） |
| `notes[]` | `note_id`、`path`（必须 `.md`，允许中文路径段）、`title`、`explains[]`、`references[]`、`reviews[]` |
| `limits` | `max_notes`（1..=6）、`max_sections`（1..=12）、`max_concepts`（1..=32）、`max_links`（1..=64） |

概念表（`concepts.json`，`policy` 固定 `structure-concepts-v1`）每条只有
`concept_id`（标识符）与 `term`（中文正名）。概念表是**唯一**的概念白名单：
`explains` 与 `references` 里出现没登记的概念一律整包拒绝。

`explains` 表示"这份笔记是该概念的规范解释位置"；`references` 表示"这份笔记引用该概念，
完整解释在别处"。同一份笔记的 `explains` 与 `references` 不允许交集——一处不能既当
规范位置又当引用（否则读者不知道去哪读）。

## 3. 冻结根布局

```
<结构根>/
  control/
    manifest.json      所有权、身份、作者包与冻结输入的摘要
    inputs.json        每份笔记的路径、标题、摘要、字节数、标题数
    family.json        作者包原文（逐字节冻结）
    concepts.json      概念表原文（逐字节冻结）
    text/
      <note_id>.md     每份笔记的规范化正文（逐字节冻结）
```

顶层只允许 `control/` 一项；`control/` 恰好这 5 项，不多不少。任何多余条目、
符号链接、目录替换都判 `STRUCT_INTEGRITY`。

**尾换行是有区别的**：`manifest.json`、`inputs.json` 由 `strict` 逐字节比对 canonical JSON，
所以**不带**尾换行；`family.json`、`concepts.json`、`text/*.md` 是作者包原文，保持原样。
输出根里的派生记录则相反——五个文件都带一个尾换行（见第 8 节）。

## 4. 章节识别与骨架比对

**标题识别**与 `text::heading` 完全一致：缩进最多 3 个空格，`#` 数量 1 到 6，`#` 之后必须是
空白或行尾。`#没有空格` 不是标题。这一条必须和 Span 层一致，否则结构层会认领
`inputs.json` 从未标记成标题的行。

**每节的正文行数**从标题行的下一行算到下一个标题前一行，只数非空行。`body_lines == 0`
即空节。

**骨架比对只用 H2**：一个笔记的 H2 序列就是它的骨架位置。若整份笔记没有任何 H2，
退化为"所有标题平级参与比对"——否则单层笔记永远被判成缺全部。

四类偏离各自独立：

| 状态 | 判据 |
| --- | --- |
| 就位 `matched` | 该节在 H2 序列里，不空，且没有出现在更靠后的骨架节之前过 |
| 位置偏离 `misordered` | 该节在 H2 序列里，但出现位置早于一个更靠后的骨架节（乱序） |
| 缺失 `missing` | 骨架声明了，笔记里没有这个 H2 |
| 空节 `empty` | 该节标题在，但正文一行内容都没有 |
| 多余 `extra` | 笔记有 H2，但骨架没声明它 |

**空节优先于位置偏离**：两者是不同缺陷——"放错位置"和"写完标题就没了"要分开报。
**乱序在正文出现顺序上判断**：比较骨架序号会在骨架子集被跳过时误报，所以只追踪
"已见的最大正文位置"。

一份笔记判 `consistent` 当且仅当：所有骨架节都就位，或缺失的是 `optional` 节，并且没有多余节。

## 5. 链接解析

正文里的 `[[...]]` 按出现顺序扫，同一行可以有多条。内部按 `目标#标题|别名` 拆：

- **别名竖线**：如果这条链接在表格行里（`trim_start` 以 `|` 开头），裸 `|` 会截断单元格，
  整包拒绝 `STRUCT_LINK_UNESCAPED_ALIAS`；必须写成 `\|`。
- **目标解析**：先按 `path` 精确匹配；失败则按去掉 `.md` 的路径、路径尾段或 `note.title`
  匹配。0 条 → `target_missing`，多条 → `ambiguous`。
- **标题校验**：目标解析成功后，若带 `#标题`，该标题必须在目标笔记的**全部标题**里存在，
  否则 `heading_missing`。

链接解析失败**不是**整包非法：它是这份作者包的链接缺陷，记进 `links.json` 的
`source[].status`/`detail`，报告里逐条列出。只有表格内裸竖线是整包拒绝。

## 6. 概念的唯一解释位置

对概念表里每个概念：

- `explaining`：声明了 `explains` 的笔记列表。**长度大于 1 即整包拒绝**
  `STRUCT_DUPLICATE_EXPLANATION`——同一概念在一条输出版本里只能有一个规范位置（FR-17）。
- `canonical`：`explaining` 的第一项，没有则是 `null`。
- `referenced_by`：声明了 `references` 的笔记列表。

`canonical == null` 且 `referenced_by` 非空的概念是**外部引用**：产品不为它生成链接，
因为本地根本没有可指的目标。报告里写「（无本地完整解释）」，绝不生成假链接。

## 7. 导航与复习生成

导航由确定性规则生成，不读模型、不猜：

- **同族导航**：每份笔记指向本族其余每一份（`n × (n-1)` 条），`text` 用目标标题，路径用目标 `path`。
- **概念链接**：对每份笔记的每个 `references` 概念，若它有 `canonical`，就生成一条指向
  那份笔记的链接。
- **`target_heading` 恒为 `null`**。规范位置是"哪一份笔记"，不是某个标题；猜标题一旦猜错就是
  假链接，FR-17 明确禁止。链接只指文件。
- 生成完再逐条重验目标与标题：目标笔记必须在冻结正文里存在。有断链时 `build` 直接
  报 `STRUCT_INTEGRITY` 并拒绝写出报告——「断链必须为 0」是硬条件，不是建议。

复习提示逐字来自 `notes[].reviews`，导航里按声明顺序列出，不加解释、不加频次。

## 8. 输出根与字节确定性

```
<输出根>/
  structure.json    章节树、逐节状态、多余节、逐笔记计数、结构计数
  links.json        正文链接逐条、生成链接逐条、链接计数
  report.json       结构计数 + 链接计数 + 概念表 + 零调用声明
  navigation.md     可读导航：每份笔记的同族导航、章节骨架、复习提示
  report.md         可读报告：结构一致性表、结构偏离明细、概念唯一位置、链接缺陷、边界
  manifest.json     五个文件的摘要 + 结构计数
```

`manifest.json` **不含时间戳**：同一冻结根的两次 `build` 必须五个文件逐字节相同。
这条是硬要求——带时间戳的清单会让"确定性"变成一句空话。

`navigation.md` 与 `report.md` 是派生视图，读者从这里看结论；`structure.json`、
`links.json`、`report.json` 是机器可读的同一份结论。三者必须一致，审计器逐项比对。

## 9. 所有权与身份校验

- `adopt` 要求：作者包可读且合法、概念表合法、每份笔记都能被 `text::analyze` 解析出至少一个标题、
  **判定能在内存里跑通**。以上任一步失败都不留半个根目录。
- 根目录必须**尚不存在**；父目录必须存在且不是符号链接。
- 冻结根建立后，`manifest.json` 记录根、父目录、`control/`、清单自身、`inputs.json`
  五处文件身份（Unix `device`+`inode` / Windows `volume`+`index`），以及作者包、概念表、
  `inputs.json` 三个摘要和每份笔记的规范化摘要。任何一处变动都判 `STRUCT_INTEGRITY`。
- `status`/`list` 只读：不写、不建目录、不改摘要。陌生目录报
  `STRUCT_UNKNOWN_ROOT`（缺 `control/`）或「不存在」，都不是 IO 错误。

## 10. CLI 动词与错误码

| 动词 | 作用 |
| --- | --- |
| `noetome structure adopt <作者包> <结构根>` | 冻结作者包，建立结构根 |
| `noetome structure build <结构根> <输出根>` | 派生五文件报告 + 清单（输出根必须尚不存在） |
| `noetome structure list <结构根>` | 机器可读摘要（JSON） |
| `noetome structure status <结构根>` | 人类可读状态（逐笔记偏离 + 链接计数） |

| 错误码 | 退出码 | 含义 |
| --- | --- | --- |
| `STRUCT_ARGUMENT` | 2 | 参数或作者包声明不合法，可修正后重试 |
| `STRUCT_INTEGRITY` | 3 | 冻结根被改动、身份不符、或生成链接出现断链 |
| `STRUCT_UNKNOWN_ROOT` | 3 | 目标不是已建立的结构根；未修改任何文件 |
| `STRUCT_DUPLICATE_EXPLANATION` | 3 | 同一概念被多处完整解释 |
| `STRUCT_UNKNOWN_CONCEPT` | 3 | 用了概念表里没有的概念 |
| `STRUCT_LINK_UNESCAPED_ALIAS` | 3 | 表格单元里写了裸 `\|` 别名 |

## 11. 本轮明确不做

1. 不自动改写正文、不自动重排小节、不补齐缺失章节——只报告位置（FR-16）。
2. 不做语义等价判断：章节是否"意思一样"不看，只比标题文字。
3. 不解析嵌入（`![[...]]`）、块引用（`#^block`）与别名重定向；本层只处理 `[[页面#标题|别名]]`。
4. 不做跨族链接：链接只在本族声明的笔记内解析，库外一律 `target_missing`。
5. 不判断内容质量与科学正确性，也不检查 Callouts/Mermaid/MathJax 的渲染结果（FR-25 的渲染面另测）。
6. 不实现锁定（用户锁定的目录/文件名/章节/顺序），也不做增量更新与移动列表（FR-16 后半段）。
7. 不推测用户水平，不生成考试重点。
