# 锁定位置与规划变更的局部影响

对应需求：FR-16（可锁定的结构）、FR-29（变更检测与依赖传播）、AC-23（锁定后新增资料遵守锁定）、AC-25（无关笔记指纹不变）。

本阶段只做**结构层面的变更规划**：给定一份声明了的笔记结构、若干变更提案与若干锁定，算出哪些变更可以应用、哪些必须转成候选、哪些重构不安全，并把未受影响的笔记原样列出。它不生成知识、不改写正文、不写项目与 Vault，模型调用与网络请求恒为 0。

## 1 边界

- 只读声明与冻结的指纹快照，不读取真实笔记库。
- 不判断内容质量与科学正确性；只判断"结构是否被锁定""影响范围是否与声明一致"。
- 冲突不静默丢弃：锁定冲突转成候选并逐条列出锁 id 与理由。
- 不安全的移动、拆分、合并**先拒绝**，并明确说明"已保留旧位置，未生成任何变更"。
- 有缺口时仍然写出完整报告，只把退出码置为 3：审计的产出是结论本身。

## 2 变更声明

| 字段 | 含义 |
| --- | --- |
| `policy` | 固定 `locked-change-v1` |
| `schema_version` | 固定 `1` |
| `producer` | 作者标识 |
| `case_id` | 本次声明的编号 |
| `description` | 一句话说明 |
| `notes` | 笔记结构：编号、路径、标题、主题、位置、章节序列、概念、内容指纹 |
| `changes` | 变更提案：类型、主题、触动概念、受影响笔记、可选的新路径与新章节顺序 |
| `locks` | 锁定：目录、文件、章节、顺序、规范位置 |
| `refactors` | 重构：移动、拆分、合并，含目标与引用变化 |
| `limits` | 四类上限 |

**`proposed_path` 与 `proposed_sections` 是提案的核心**：没有它们，"锁定"永远不会触发，任何变更都会因为"路径没变"而被判为可应用。

## 3 冻结根布局

- 顶层只允许 `control/`。
- `control/` 恰好三件：`inputs.json`、`manifest.json`、`project.json`。
- `project.json` 是声明**原文**（保留来源缩进），`inputs.json` 与 `manifest.json` 是规范编码、**无尾换行**。
- 清单记录的六处身份（根、父目录、control、清单、输入摘要）在每次打开时逐一比对：目录被整体搬走或替换都会报 `CHANGE_INTEGRITY`。
- `adopt` 先在内存里跑完整规划，规则不通过就**不建根**；建根失败则删根，不留半成品。

## 4 五类锁定

| 锁 | 命中条件 |
| --- | --- |
| `file` | 该笔记的路径被改名或移动 |
| `directory` | 原路径在锁定目录内，而新路径不在 |
| `section` | 被锁章节在章节序列里的下标发生变化 |
| `order` | 笔记的位置与锁记录的位置不同 |
| `canonical` | 该概念的完整解释所在笔记的路径发生变化 |

命中任何一条即**转候选**：笔记保持原结构，候选记录当前路径、提案路径与冲突明细。

## 5 影响范围

对每条变更同时做两个方向的检查：

- **漏报**：某份笔记引用了被触动的概念，但没有出现在这次变更的受影响清单里 → `missed_dependency`。
- **多报**：某份笔记被声明为受影响，但它既不共享任何概念，也不属于该变更的主题 → `unexpected_touch`。

两个方向都按概念与主题判定，不按"看起来相关"判定：相关性分数只用于排序，不代替主题授权。

## 6 重构与引用变化

- 拆分必须把原子**完整划分**到目标：原子落到目标之外、同一原子被分到两个目标、某个目标一个原子都没有，都拒绝。
- 重构必须列出引用变化；一条都没有的重构拒绝。
- 目标撞上 `file`、`directory`、`canonical` 锁 → `CHANGE_UNSAFE_REFACTOR`，且不生成任何变更。

## 7 未受影响的笔记

不在任何变更、也不在任何重构里的笔记进入 `unchanged`，携带声明时的内容指纹。**指纹来自声明，不由本工具重新计算**：本阶段没有真实正文可比，报告只保证"这些笔记没有被本规划触动"。

## 8 计数与结论

`counts` 共 11 项：笔记、变更、锁定、已应用、候选、重构、引用变化、未受影响、缺口、模型调用、网络请求。

`verdict` 为 `pass` 当且仅当缺口为 0；否则为 `findings`，并逐条给出 `kind`（`lock_conflict`、`missed_dependency`、`unexpected_touch`）与主体。

## 9 输出与字节确定性

输出根恰好四个文件：`changes.json`、`report.json`、`report.md`、`manifest.json`。三个 JSON 各带一个尾换行；输出清单**不含 `created_at`**，因此同一冻结输入的两次构建逐字节相同。

## 10 动词与错误码

| 动词 | 作用 |
| --- | --- |
| `adopt` | 校验声明、预演规划、冻结输入 |
| `build` | 重算并写出变更计划与报告 |
| `list` | 只读重算并输出结构化结论 |
| `status` | 只读重算并输出中文摘要 |

| 码 | 退出码 | 含义 |
| --- | --- | --- |
| `CHANGE_ARGUMENT` | 2 | 参数或声明不合法 |
| `CHANGE_INTEGRITY` | 3 | 冻结输入被改动、身份不符 |
| `CHANGE_UNKNOWN_ROOT` | 3 | 陌生目录，保持只读 |
| `CHANGE_UNSAFE_REFACTOR` | 3 | 重构会破坏锁定结构，已保留旧位置 |
| `CHANGE_FINDINGS` | 3 | 规划完成但存在缺口，报告已写出 |

## 11 本轮明确不做

1. 不读取或比对真实笔记正文，指纹只来自声明。
2. 不做真实的文件移动、拆分、合并，只输出计划。
3. 不解析 Markdown 链接，只按声明比较引用变化。
4. 不判断变更的科学必要性。
5. 不做增量缓存或跨运行的去重。
6. 不接 GUI，不写 Vault。
7. 不测量千页规模的耗时。
