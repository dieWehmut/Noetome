# 生产整书来源契约

B16-T02将真实PDF资料入口收敛至`noetome_cli::corpus`。CLI `corpus`与桌面资料页调用同一Application API；旧fixture及有界来源契约保留其验收范围。新能力的实际结果见本批验证记录，本文接口不是完成证明。

项目原有`project.json/project.sqlite`不混入分页解析事务。`.noetome-corpus/corpus.sqlite`是项目身份绑定的版本化生产来源库，使用SQLite WAL/FULL和逐页事务；原始版本在独立UUID目录中，来源文件只读。来源ID标识不可变输入版本，内容SHA256用于重复文件复用；同名不同内容另建版本，显示名和选取路径不作为证据身份。

原件以1MiB缓冲复制、计算SHA256、同步并确认。完整原件无固定16/64MiB上限，总物理页无128页上限；磁盘空间、操作系统和解析器能力仍会产生明确失败。获取失败不会覆盖已有版本或使项目初始化标记永久阻塞。重复内容复用已登记身份及结果，不再次创建确认页。

获取原件期间同样持有来源进程锁。获取进程退出后，列表将没有持锁进程的`acquiring`记录只读投影为`interrupted`，说明原件尚未确认并要求重新导入；保留旧记录和部分原件，不把残留锁文件当成活跃任务。当前获取阶段没有取消按钮，也不续传部分原件；重新导入重新流式获取，处理阶段的暂停与恢复另行保留。

预检返回真实字节数、完整物理页数、密码/格式错误、前三页文字抽样和书签。抽样不证明全书文字可读。`limits`显示实际批大小、批超时、单页结构上限与OCR可用性。文字解析每批默认8页、180秒；单页结构最多16MiB，超限明确失败而不截断文本。worker可保存失败页；若补充来源/版本/区域身份后才超限，宿主保存来源错误，保留待处理页或旧版本，不保证新增失败页记录。来源列表返回当前项目的全部来源摘要，不载入页面正文；页面查询分页，每次1至50页，默认5页。

页面状态为`pending/text_ready/needs_ocr/needs_review/ocr_ready/failed/blank`。文字、图形、旋转和复杂版面未知分别保留问题；确认处理不等于知识核验。整书状态和各类页计数分别保存，不将有未知的书显示为全部就绪。每页包含1起始物理页号、CropBox旋转后左上角pt坐标、MediaBox/CropBox/UserUnit/变换、文字、区域及问题和解析身份；不伪造印刷页码。

`needs_ocr_pages`计数状态为`needs_ocr`的待识别页；`review_pages`同时包含`needs_review`和`needs_ocr`，界面“待复核”采用该口径。文字可用、经过OCR和待复核可以同时成立，但两个页状态互斥。`process`只处理待确认文字页及待OCR页；`retry`显式重试当前失败页，保留失败版本，OCR失败时恢复识别前的原始页作为新尝试输入。页版本及区域身份包含完整解析器指纹；历史确认页不自动改写或补造版本字段。

进程互斥使用操作系统文件锁，进程退出自动释放；留下文件不代表锁仍持有。暂停持久写入SQLite，宿主在哈希期间与工作进程运行期间检查请求；已确认页不重复，未确认范围可继续。每批提交前复查持有原件的文件身份/大小/修改时间，拒绝解析期间改动；保存页读取时核对字节摘要。

Python只使用明确选定的锁定解释器或安装目录的受控环境，不从资料目录/PATH发现程序。可信显式venv解释器可为链接，核对规范化目标而保留venv调用路径；资料和项目路径仍禁止链接跳转。宿主嵌入固定worker源码并写入独占临时目录，命令不经过shell。

pdfplumber文本适配器按物理页生成对象并及时释放，避免`PDF.close()`重建整书页缓存。pdfminer对象流保留有界轻量元数据缓存，不缓存解码后的内容/图像流；页面树及交叉引用的必要元数据仍随PDF结构增长。

OCR使用独立原生Windows现成worker与明确配置。模型、配置、程序及原始结构产物的版本和摘要必须可查，GPU是否实际运行与质量是否经过独立核对分别记录。OCR未知符号/图表/关系保留问题，不能仅以输出Markdown或置信度字段宣布科学正确。

新OCR记录的`artifact_root`保存为项目相对路径，只能指向当前来源的受控`ocr`子目录。页及区域逐项声明资产的相对路径、字节数和SHA256；原始结构`raw_output`也被纳入声明。读取页面重新核对声明资产，缺失、改动、链接或越界一律拒绝；不遍历资产目录里的未选取文件。旧绝对目录记录仅在原项目的受控来源目录内兼容，移动后未核对的路径明确拒绝，不悄悄转成新位置。

`corpus export-source <项目> <source-id> <新目录>`导出来源包，复用公开的`copy_source`流式复制并核对原件，按每批最多50页保存当前页记录及状态，只复制当前页声明资产。目的地必须不存在且在项目之外，处理中的来源不能导出；导出后重读文件摘要并确认来源仍一致。中途失败保留`source-package.incomplete.json`及已写入的新目录，不宣布导出完成，也不覆盖重试时已存在的目录。

目的地与项目、选取原件与来源库的包含关系同时核对现有祖先目录的文件系统身份。Windows 的大小写或命名空间别名不能使项目内目的地成为外部目录，也不能从来源库内部重复获取原件；不同身份的外部目录仍可使用。所有路径继续先检查组件并拒绝链接/重解析跳转。

旧OCR页如果存在`raw_output`但该原始结构未列入具有已固定SHA256的资产声明，导出明确报`CORPUS_ASSET_UNPINNED`并保留未完成标记，不生成完成清单，也不现场补造旧历史摘要。旧页文字和已声明图片仍可按原兼容规则读取；该限制只阻止把缺少原始结构证据的页声明为完整来源包。

完成的`source-package.json`说明原件指纹、当前逐页状态、实际导出清单及待OCR/待确认/失败范围，`knowledge_status`始终为`pending`。来源包不是知识笔记、编译IR或科学核验结果；其导出成功只代表当前来源证据包复制和指纹核对完成。
