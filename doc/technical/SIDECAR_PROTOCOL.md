# Parser sidecar v1

Core `sidecar_process::run(ParserCommand, selected_input, new_workspace, Limits, Arc<AtomicBool>)` launches exactly one trusted native command with explicit argv. No shell, executable, extra input or destination is selected by document/response content. Success returns `ValidatedResponse`; failure returns stable `SidecarError` plus bounded stderr bytes. Fake acceptance is only compiled in library unit tests. Public library rejects fake; CLI has no parser/fake switch and does not register results in projects.

Every JSON object denies unknown fields. Fields in the Rust DTOs `sidecar_model.rs` are mandatory, including nullable unit `text`. UTF8 stdin contains one JSON request followed by EOF. UTF8 stdout contains exactly one response JSON, allowing trailing JSON whitespace only. Stderr is opaque diagnostic bytes and never parsed as protocol. Any nonzero exit fails even with valid stdout. Version 1 only; no permissive forward compatibility.

Request fields: `protocol_version=1`, fresh lowercase UUIDv4 `request_id`, `input={path,access:read_only_single_file,fingerprint:{sha256,byte_length}}`, `workspace={path,capability_id,access:exclusive_new_directory}`, and `limits`. Core reads and hashes the complete selected file, holds a read guard and file identity until completion, creates the new directory exclusively and holds its directory identity. Paths are absolute UTF8 capabilities; existing workspaces fail. SHA256 is lowercase 64 hexadecimal digits over raw bytes.

Response fields: `protocol_version=1`, matching `request_id`, `input_fingerprint`, `workspace_capability_id`, `producer=parser|fake`, `parser={name,version,capability_version:1,capabilities:[source_units_v1]}`, `unit_count`, `units`, `resources`, `issues`. Parser name/version are nonempty and bounded. The complete ordered units must have unique IDs and ordinal 0..unit_count-1; count matches the vector. Zero units is allowed only for synthetic protocol tests and carries no PDF completeness claim. A producer=parser response with zero units is rejected. No physical-page/bbox semantics are invented here.

Unit fields: `unit_id`, `ordinal`, `kind=text|formatting|unknown`, `status=parsed|failed|needs_review`, nullable `text={resource_id,start_byte,end_byte}`, `resource_ids`. Text ranges are UTF8 half-open byte ranges into the named resource, on actual character boundaries. Text units require text; resources must be referenced. Resource fields: unique `resource_id`, portable `relative_path`, `kind=utf8_text|binary`, `fingerprint`. Issue fields: `code`, `severity=warning|blocking`, nonempty `message`, `unit_ids`, `resource_ids`; references must resolve and have no duplicates. Failed/review units require a corresponding issue. IDs use 1..128 ASCII letters/digits/_/- with first letter/digit. Resource relative paths use `/`, reject absolute, traversal, reserved Windows names, trailing dot/space, case collisions and file/directory prefix collisions. Core checks regular files, no reparse/link or multiple hard links, identity, SHA/length, UTF8 and exact files/directories. Unknown files or empty undeclared directories fail before descending into them. At most 32 directory components per resource and at most resources * 32 declared directories; traversal is iterative. The complete directory manifest is guarded before resource reads and rechecked afterward. Resource guards persist in the returned value.

Injectable defaults (policy, not measured capacity): request 64 KiB, response 4 MiB, diagnostic 64 KiB, input 64 MiB, single resource 16 MiB, total resources 64 MiB, 256 resources, 10,000 units, 1,000 issues, runtime 30,000 ms. Positive values only; allocations grow by bounded 8 KiB chunks, never preallocate a caller's limit. Exceeding limits fails explicitly; truncated data is never delivered as success. Runtime begins before input preparation. Cancellation is checked before launch, during IO and before validation success.

Windows x64 uses suspended creation and Job Object assignment before resume. Independent nested observer Job queries all active PIDs until empty after termination, including parent-early-exit descendants with noninherited pipes; root is waited and writer/readers joined. A trusted child is managed as a process tree, not an OS file/network sandbox. Unix behavior requires separate validation before a cross-platform claim.

Stable error codes: `SIDECAR_CONFIG` invalid policy; `SIDECAR_START` spawn/Job setup failure; `SIDECAR_IO` pipe/filesystem failure; `SIDECAR_EXIT` unsuccessful exit; `SIDECAR_PROTOCOL` malformed/unknown/missing JSON fields or enums; `SIDECAR_VERSION` unsupported protocol/capability; `SIDECAR_IDENTITY` request/workspace/input mismatch; `SIDECAR_PRODUCER` fake in public entry; `SIDECAR_UNITS` incomplete/duplicate units or invalid references/ranges/issues; `SIDECAR_INPUT` unsafe/changed input; `SIDECAR_WORKSPACE` existing/unsafe/changed root; `SIDECAR_RESOURCE` unsafe/mismatched/nonexact resources; `SIDECAR_LIMIT` any byte/count limit; `SIDECAR_TIMEOUT`; `SIDECAR_CANCELLED`; `SIDECAR_CLEANUP` failed termination/wait/join. Failed workspaces are retained for inspection; no arbitrary recursive cleanup.

UTF8 text resources are decoded once into owned validated strings; unit ranges reuse character-boundary checks without rescanning entire artifacts. Core checks deadline/cancellation within unit, reference and issue loops. Timing regression evidence uses 10,000 synthetic units sharing one 16 MiB resource; it measures these bounded samples only.
