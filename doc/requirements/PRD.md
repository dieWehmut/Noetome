# Noetome 产品需求文档

版本 1.2　日期 2026年11月1日　状态 开发基线与完整工程蓝图已采纳

Noetome 面向需要深入学习一个学科的个人用户，将多份电子资料整合为结构统一、风格可选、知识相互关联的 Obsidian 知识库，并支持长期增量维护。系统先建立可追溯的知识模型，再规划笔记和表达形式；最终文件可独立阅读和编辑。产品的首要交付是可靠的知识整理闭环，包括资料覆盖、多源融合、主动图表表达、质量核验和人工编辑保护。

本文供产品负责人、设计、开发及测试共同评审和拆分任务使用。正文规定产品行为、业务边界、数据约束和验收方法；具体算法、数据库结构、技术选型及64项执行任务已在[完整标准入口](../README.md)固定，产品功能尚待实现。

## 1 文档约定与需求依据

### 1.1 依据与确认等级

需求依据为用户提供的[设计AI知识库软件分享对话](https://chatgpt.com/share/6ae5f83b-e938-83ee-8810-28c30b0431bf)。引用位置按用户发言顺序标识：U1 为最初产品设想，U2 为认同章节粗对齐、原子知识与统一知识模型，U3 为双模式和默认深入，U4 为知识模型解释与命名讨论，U5 为需求追问，U6 为17项回答及对第二、三轮建议的明确接受，U7 为主动生成图表的补充，U8 为项目名候选。

- **已确认**：用户直接表达或明确接受的要求。后续发言对早期设想的修订优先，例如内容筛选、保留历史观点和人工编辑保护。
- **建议基线已采纳**：为使要求可实现、可测试而补充的默认值、交互、数据结构、分期或量化指标。用户于2026年10月31日明确接受全部待决策事项的建议，按这些建议推进，无需重复请求确认。
- **后续验证**：原第18章中的版本、硬件、规模及扩展方向，已决定按对应里程碑实测或另立需求；这不是等待用户重新批准默认方案。新增重大范围变化仍需记录。

每组功能用 FR 编号，质量要求用 NFR 编号，验收用例用 AC 编号。P0 表示个人可用版的必要能力，P1 表示随后增强，P2 表示远期扩展。优先级和里程碑均为建议；不能用分期删去已确认的产品目标。

Noetome 作为工作名称与当前仓库保持一致；已采纳暂不推定开源许可证和公开发布承诺的建议。已采纳决策及其执行解释见[决策基线](DECISIONS.md)。

## 2 产品目标与范围

### 2.1 目标用户与核心价值

首要用户是需要将多本教材、讲义和研究资料整合成个人学科知识库的学习者。初期以用户实际使用的复杂知识材料验证产品，生物学案例用于验收，数据模型仍须容纳数学公式、推导、实验步骤和其他学科的条件关系。

用户希望减少跨书查阅、重复整理、核对冲突、维护链接和更新笔记的劳动，同时保留对知识范围、个人风格和人工内容的控制。一次生成可以耗时很长，但运行状态必须可理解，结果必须能核查，失败后必须能继续。

产品成功应体现为：能在确定范围内覆盖必要知识；多来源的互补内容得到融合；知识和证据不因换风格、改目录而丢失；输出适合人阅读和复习；新资料加入后能够准确更新相关内容。

### 2.2 版本范围建议

| 范围 | 个人可用版 P0 | 后续增强 P1 | 远期 P2 |
| --- | --- | --- | --- |
| 平台 | Windows x64 桌面端，核心可独立运行 | 安装升级和诊断完善 | 其他操作系统 |
| 输入 | 文本型 PDF、扫描 PDF，Markdown 和 TXT | DOCX、PPTX、EPUB 等格式适配 | 更多媒体和连接器 |
| 知识处理 | 覆盖账本、多源对齐、条件化事实、双模式 | 领域扩展包、复杂身份纠正工具 | 大范围跨学科协同 |
| 输出 | 独立 Vault、有效双链、公式、图表、证据索引 | 更多视觉模板和导出后端 | 习题、教学 PPT、讲义 |
| 维护 | 暂停恢复、版本、增量更新、人工审批 | 高级结构迁移及既有库逆向建模 | 多人协作 |
| 模型 | 可替换 API 适配器 | 外部 Agent 适配 | 本地模型成熟支持 |
| 阅读 | 结果预览、搜索、差异和来源定位 | 阅读体验增强、可选 Obsidian 插件 | 接近完整 Obsidian 的阅读编辑能力 |

输入格式采用 PDF 优先的分期，早期用少量 Markdown 和 TXT 固定样例验证数据闭环，随后按开发计划引入真实 PDF；样例能力不代表已支持 PDF。不能把未支持的资料静默转为空白或“成功”。P0 的扫描和复杂图表支持允许存在“无法可靠解析”状态，但必须有原图保留和明确待处理清单。

### 2.3 明确边界

第一版不承担多人权限、付费订阅、公共知识市场、云端同步服务或完整 Obsidian 替代品的职责。旧库作为风格参考与旧库逆向建模是两项不同能力：前者已确认，后者未承诺首版实现。

“深入”不是无边界研究。“完整”是对本轮已定义资料范围和知识要求的可核对结果，不是宣称已穷尽整门学科。对每个来源单元建立处理记录，可以证明流程覆盖情况；真实知识遗漏仍需独立抽样和人工基准检验。

## 3 核心概念与产品原则

### 3.1 核心对象

| 对象 | 产品含义 | 关键区别 |
| --- | --- | --- |
| 项目 Project | 一组资料、目标、策略、知识状态及输出的管理单位 | 不等同于 Vault 文件夹 |
| 来源 Source | 一本书、一份讲义或外部核验材料的某个版本 | 同名文件不一定是同一版本 |
| 来源单元 SourceSpan | 可定位的段落、公式、表格、图片或页面区域 | 扫描失败也必须被记录 |
| 概念 Concept | 具有稳定身份的知识对象及别名 | 名称、路径和身份分离 |
| 知识原子 Atom | 可独立追踪、验证和编排的知识单元 | 可以是公式、过程或推导，不必是一句话 |
| 事实主张 Claim | 对对象或关系的陈述，包含条件和核验状态 | 相似句子在不同条件下可同时成立 |
| 证据 Evidence | 支持、反驳或限制某个主张的来源内容 | 不等于模型自述“可信” |
| 主题 Topic | 学科领域或教学单元 | 可多重归属，不强制等同文件树 |
| 笔记计划 NotePlan | 知识分配、章节、引用和输出位置 | 在写 Markdown 前形成 |
| 表达计划 RepresentationPlan | 每一节选用正文、表格、图示等的决定 | 原文没有图也可以产生图示 |
| 规范位置 CanonicalPlacement | 某个概念完整解释的唯一位置 | 可为文件、标题或稳定块 |
| 发布版本 Release | 一组相互一致的文件、资源、映射及报告 | 不能只保存孤立的 Markdown 快照 |

### 3.2 不可被预设覆盖的原则

1. 人工编辑和人工锁定优先于自动生成；关闭普通审批不撤销这一保护。
2. 正确性和重要信息完整性优先于简短、美观及速度。不同风格共享已确认知识集合。
3. 知识身份独立于名称和文件路径。目录调整不能导致知识重新编号或引用失效。
4. 规范完整解释位置唯一，允许必要的上下文事实和同源嵌入，不产生多份独立完整解释。
5. 每张来源图片都进入检查清单；排除、失败和待核验均有记录。
6. 必要资料覆盖与可选研究分别核算，研究工作不能掩盖原资料遗漏。
7. 新主题候选不会自动变成已经批准的范围；本轮边界随配置版本保存。
8. 写作和验证能反馈到知识模型，禁止只在输出文件中修补事实而留下内部矛盾。
9. 笔记正文保持干净，但知识争议、适用条件和不确定性不能因隐藏来源而消失。
10. 所有性能、预算和资源限制影响排队、分块或停止，不允许据此静默截断必要内容。

## 4 用户旅程与任务状态

### 4.1 首次生成

1. 创建项目，输入学科、学习目的，选择输出位置；可填写目标知识水平和已有知识。
2. 添加资料，查看格式、版本、页数或内容单元、可读性和重复文件提示。
3. 选择生成模式、深入程度、笔记风格、模型、联网范围、审批策略和预算；可选风格参考。
4. 查看启动摘要，明确本轮范围、预计处理规模、数据外发目的地和无法解析的资料；估算不充当费用承诺。
5. 开始运行，依次看到解析、建模、规划、编译、校验及发布进展；无依赖冲突的任务可继续。
6. 查看已通过局部校验的阶段结果，查看待审核变更和来源证据。
7. 生成结束报告，分别确认主任务结果、阻塞问题和可选研究候选。
8. 打开 Vault 阅读、编辑和复习；后续加入资料或调整风格形成新版本。

### 4.2 增量更新

选择既有项目并加入新资料后，系统先识别来源版本变化和外部人工编辑，生成影响范围。新事实、修订事实和新冲突写入知识模型候选版本，再计算受影响笔记、图表、链接和证据映射。安全的变更可发布；可能影响人工内容的变更进入审批。未批准部分维持原文件，依赖其新位置或新事实的变更也不能提前发布。

### 4.3 风格切换与继续研究

风格切换复用知识模型，重新计算必要的布局和表达计划。若用户同时改变知识水平、范围或深度，应作为知识策略变更，显示需要重新筛选或研究的范围，不能伪装成纯排版变更。

用户在结题报告中接受某个研究候选后，该候选进入下一轮已批准范围。继续研究沿用原来源和版本历史；预算、外部来源策略和审批模式在启动前可调整。

### 4.4 执行状态与完成判定

任务运行状态建议为：草稿、就绪、运行中、暂停中、已暂停、等待输入、预算停止、失败、已取消、执行结束。发布状态独立为：无结果、阶段可用、待审批、已发布、发布回滚。暂停、失败和执行结束均不自动表示质量通过。

| 完成维度 | 达成条件 | 不得记为完成的情形 |
| --- | --- | --- |
| 资料覆盖 | 本轮每个来源单元被处理或有合法排除结论；已纳入范围的必要知识无待处理缺口 | 无法解析、尚未审定排除、未处理图片、失败页 |
| 知识编译 | 目标知识已分配有效位置，正文和资源生成完成，引用可解析 | 缺失笔记、待生成图表、未落地的知识原子 |
| 质量验证 | 对指定版本完成规定检查，阻断级问题为零，允许保留的问题逐项可见 | 校验未运行、公式错误未处理、人工冲突未解决 |
| 可选研究扩展 | 本轮明确接受的可选研究目标已完成 | 已批准目标待研究或未达成、预算提前停止 |

主任务完成要求资料覆盖、知识编译、质量验证均满足本轮基线，且所声明发布范围已落地。未来研究候选可仍存在；未完成的已批准必需研究不能归入“未来候选”来伪造完成。若有待人工审批项，显示“可用结果已发布，另有变更待审批”，不得笼统显示全库更新成功。

研究模式采用固定的本轮目标集；只承诺该目标集的完成情况。没有研究目标时扩展维度为“不适用”，不以零任务生成虚假的100%。

## 5 项目配置与默认策略

以下默认值已作为开发基线采纳。每次运行保存配置快照，修改影响正在运行的任务时需生成新配置版本。尚需实测的具体提供商、版本及价格不以猜测填充。

| 配置 | 可选内容 | 默认或约束 |
| --- | --- | --- |
| 生成模式 | 资料驱动、知识体系驱动 | 建议默认资料驱动；两种均必需 |
| 深入程度 | 必要补全、标准、深入、自定义目标 | 深入，已确认；仍受主题范围约束 |
| 知识水平 | 自动推测、用户声明 | 推测结果可查看和修改 |
| 学习目标 | 理解、考试复习、背诵、研究或自定义 | 建议理解与复习 |
| 已有知识 | 用户声明的先修知识和不必展开项 | 不根据学历标签直接推断全部掌握 |
| 笔记风格 | 极简、详细、自定义 | 建议详细；可参考旧库风格 |
| 事实冲突策略 | 保留演变、优先指定来源、逐项审核 | 默认保留历史和最新观点，已确认 |
| 普通审批模式 | 尽量自动、重要问题审核、严格审核 | 建议重要问题审核 |
| 人工编辑保护 | 必须生效 | 不提供关闭保护以自动覆盖的选项 |
| 外部检索策略 | 关闭、仅核验与必要补全、批准范围内研究 | 首次运行明确选择并保存 |
| 新主题准入 | 结题报告候选，经用户接受后继续 | 不打断主流程，已确认 |
| 执行预设 | 质量、均衡、效率 | 建议质量；显示成本与校验差异 |
| 预算 | Token、费用、运行时长、检索量 | 至少明确一项可执行上限或主动选择不设限 |
| 结构锁定 | 目录、笔记、章节、顺序、命名 | 未锁区域自主规划，锁定区域保持 |
| 输出位置 | 新建目录、既有项目 Vault | 非空未知目录需先扫描和展示影响 |

深度和风格独立：极简可以包含深入的理论，但表达紧凑；详细不等于允许新增未经批准主题。运行模式和外部检索开关独立：资料驱动可允许核验，研究模式若关闭外部检索则只能使用已提供材料，并说明目标可达范围。

关闭外部检索不等于完全离线：若选择远程模型 API，资料处理仍需要向该提供商发送必要内容。模型数据外发和外部搜索分别配置、分别展示。完全离线还要求本地模型、解析与验证能力齐备，不作为 API 优先版的默认承诺。

质量预设建议对高风险事实、复杂图片和公式执行额外审查；均衡预设按风险分配校验；效率预设优先缓存和减少重复推理。三者均保留覆盖账本、链接检查、证据映射、人工保护及真实完成状态，不能通过禁用这些底线获得“效率”。

## 6 资料导入与知识筛选

### FR-01 项目和资料管理

优先级 P0。用户可新建、打开、重命名和归档项目，添加多份资料并查看各自处理状态。来源使用独立身份和内容指纹，文件名只作为显示信息。同一文件重复添加应提示复用，内容改变则建立新来源版本；不得覆盖旧证据。

启动前检查输出目录写权限、剩余空间、资料可读取性、模型能力和预算。删除项目记录、移除资料、删除原始文件、删除 Vault 是不同动作，界面明确影响；默认移除资料不删除用户原文件。移除已经引用的资料后，应标记依赖需要复核，不能自动删除人工笔记。

验收：重复导入相同文件不新增重复知识和重复计费任务；同名不同内容保留为可区分版本；单文件失败不使其他有效文件不可处理。

### FR-02 结构解析和来源定位

优先级 P0。解析输出需包含标题树、正文、脚注、表格、公式、图片、图注以及来源位置。页码区分文件物理页与书籍印刷页；无固定页码的格式使用章节路径、段落或元素定位，不伪造页号。

解析器记录阅读顺序、跨页延续、文字置信度和图表关联。多栏页面不能按错误顺序拼接；表格合并单元格、单位、脚注和续表须保留关联。解析后的文本不是唯一证据，原始区域应可回看。

验收：抽查正文、跨页表格、脚注和公式均能回到相应位置；扫描失败页保留页面记录且显示失败原因。

### FR-03 扫描和异常资料

优先级 P0。对无文本层、文本质量低或内容顺序异常的页面触发 OCR 或视觉解析。每张识别出的图片都进入视觉清单；若无法可靠检测页面内图片边界，必须进行页面级视觉检查并标记识别不确定性，不能据“图片数为零”跳过扫描。

加密、损坏、空白、超大、缺页或不支持格式均给出具体状态和处理建议。用户提供必要输入后仅重试相关范围。资源限制通过分批处理解决；不能把截断输入报告为整份完成。

验收：含图片但没有可提取嵌入图对象的扫描 PDF 仍有检查记录；低置信度公式不能直接成为已验证知识。

### FR-04 来源覆盖账本

优先级 P0。每个来源单元记录未处理、已抽取、已归一、已分配、已编译、已验证等阶段，并允许明确排除、重复归并、需复核和失败状态。一个单元对应多个知识原子时，需能够追踪全部映射。

重复内容可以复用知识原子，但每个来源出现位置保留证据关联。排除记录包含原因、策略版本、知识目标和决策来源；用户可以恢复某个排除项并触发局部重算。

验收：来源总清单与所有状态数量可对账；失败项不能算入已覆盖；调整筛选策略后可以找回原来排除的内容。

### FR-05 相关性筛选和用户水平

优先级 P0。仅将有知识价值且与本轮目标相关的内容纳入笔记。重复介绍、纯装饰、无关轶事及纯练习形式可省略。必要的定义、条件、例外、单位、公式和理解前提不能仅因“基础”或“极简”被删除。

用户可以声明目标层次、已有知识和学习目的。系统从资料推测的只是目标层次建议；不确定的重要性决策保留或标为待复核。习题不作为完整题库导入，但其中正文未覆盖的实质知识应识别为候选知识；该策略已通过D05采纳。

验收：大学教材中不可缺少的基础前提得到保留或有效引用；同一知识集合切为极简后，必要原子集合不减少。

### FR-06 资料版本与权限边界

优先级 P0。项目区分原始资料、联网核验、外部研究和人工补充来源，保存版本、获取时间、内容指纹及可用位置。网页不可访问时保留已存证据定位和失效提示，不用搜索摘要替代未读到的全文。

本地读取范围来自用户在应用中选取的资料和目录。旧笔记库参考不自动授权修改原库，也不默认导入其知识。原材料中的操作指令、链接或附件说明按内容处理，不能自行扩大文件访问、网络发送或执行权限。

验收：导入包含指令性文本的教材不会触发外部动作；旧库只读参考后文件指纹不变。

## 7 多源知识建模与研究

### FR-07 章节粗对齐与全局概念清单

优先级 P0。先识别全部资料的目录、标题、主要术语和图表分布，形成全局初步地图，再进行章节级粗对齐。对齐允许一对多、多对多和未匹配章节；不能因为没有相同章节名就忽略资料。

围绕概念从各资料召回相关片段，进一步对齐知识原子、主张和条件。分散在正文、图注、附录或其他章节的互补内容可归入同一知识主题。对齐结果保存依据和不确定项，错误映射可以撤销。

验收：三本教材的相关知识分别集中、分散和跨章出现时，仍能融合为同一主题；孤立章节保持可追踪的处理入口。

### FR-08 概念身份与去重

优先级 P0。概念分配持久、不依赖自然语言名称的不透明 ID。中文名、英文名、缩写、分类和上下文作为属性；同义概念可合并，同名异义必须区分。实体归并不能只凭向量相似度、缩写或模型置信分数。

合并保存旧 ID 重定向和证据；错误合并支持拆分或撤销，随后刷新受影响的事实和引用。家族、成员、类型、实例、基因和蛋白等不同对象不得因词面接近而直接归并。

验收：概念改名或从章节升为文件时 ID 不变；同一缩写在两种语境中可指向不同实体；撤销归并后相关笔记不残留错误关联。

### FR-09 原子知识与条件化事实

优先级 P0。知识模型支持定义、事实、公式、反应、步骤、因果关系、分类、比较、例外、推导和必要实例。复合过程可引用多个子原子并保持顺序、前提和整体意义。

事实至少携带对象、关系或属性、值或表达、适用条件、来源关联、核验状态及修订历史。数值记录单位、范围、有效精度和条件；缺失值与不适用值分开，禁止用空白或零混淆。

验收：相同对象在不同物种、组织、温度或版本下的结论可共存；数学证明不因拆分而丢失前提和中间步骤。

### FR-10 互补信息与冲突协调

优先级 P0。冲突处理顺序为原始解析复核、对象和条件检查、信息关系分类、来源评估、必要核验和决策记录。分类至少包含重复、互补、条件差异、历史演变、真实冲突及证据不足。

默认保留历史和最新观点时，正文应说明各自的适用范围、时间背景及当前证据状态；来源索引保留完整依据。已发现的 OCR 错误不能与正确内容作为两种观点并列。新的、票数多的或排名靠前的网页不能自动视为更权威。

用户可在生成前选择来源优先级和冲突策略。指定来源优先不意味着忽略反证；无法裁决时保留准确的不确定性表述或暂不发布相应结论，按问题等级处理。

验收：两条条件不同的陈述不会被强行二选一；真正冲突可同时看到各自证据和处理结果；没有证据不能显示“已核实”。

### FR-11 资料驱动模式

优先级 P0。以用户选定资料为覆盖边界，允许在批准的联网策略内纠错、消解冲突和补足理解必需的前提。额外内容明确归为核验或必要补全，不混入“来自上传教材”的统计。

对教材未提及且不是理解前提的新主题，只形成研究候选。即使深入程度设为深入，也不能因此自动开辟新的学科分支。用户关闭外部检索时，可以保留待核验项并继续无依赖工作。

验收：同样资料在资料驱动模式下不自动生成一套外延学科；因联网失败保留的缺口在报告中可见。

### FR-12 知识体系驱动模式

优先级 P0。在上传资料的基础上，按已批准主题范围进行缺口补全、机制深入、实验依据或应用研究。范围、深度目标、预算和停止理由独立记录，两种模式共用知识模型和覆盖规则。

建议将本轮研究工作分为：当前主题内已授权目标、已授权的必需前提、新发现的可选主题。前两类可在许可内执行；第三类进入候选队列，结题时由用户决定。相关性分数只用于排序，不代替主题授权。

验收：研究目标完成后本轮可结束；无法满足目标时标记未达成；新增外延主题不会自行扩大本轮必须完成集合。

### FR-13 研究队列与终止机制

优先级 P0。候选记录主题、发现原因、与当前目标的关系、可能收益、来源线索、预估代价、依赖和状态。用户可接受、拒绝、延后、合并或修改范围；拒绝结果应记住，除非出现新理由。

终止原因至少有目标满足、无可靠新证据、边际收益不足、预算不足、用户暂停、网络受限和需要人工判断。预算不足表示本轮停止，不表示知识研究完整。单问题修订循环设置可配置上限，超限升级问题等级，避免无限自我重写。

验收：重复发现同一候选会归并；用户拒绝的主题不会每轮无理由重提；停止时检查点和未完成目标保留。

### FR-14 写作反馈与知识修订

优先级 P0。编写、表格化或绘图时发现知识缺口，必须创建带来源和影响范围的问题，返回模型修订流程。修订经过核验后生成新 IR 版本，再重编译依赖内容。

未经来源支持的“为了让段落顺畅而补充”的事实应标为待核验，不直接发布为结论。对同一问题的反复修订记录版本、原因和结果；没有新证据时不循环推翻既有决定。

验收：能量收支表发现某步骤缺失参数时，修复同时更新反应原子、相关表格、正文和追溯关系，而非只改一份笔记。

## 8 笔记结构与知识关联

### FR-15 教材式自适应规划

优先级 P0。根据概念关系、主题内聚性、教学顺序和阅读目的规划知识点、笔记和文件夹。知识图谱允许多重归属，文件树选择一个主要位置，其他联系用链接表达。

过程完整性、论证完整性和人类查找习惯优先于平均分配字数。主题总览、概念、过程、机制、推导、比较、参考类笔记可采用不同结构。文件数量和篇幅不设机械硬上限，模型上下文限制通过分段编译解决。

验收：连续反应不会无理由拆成大量单句文件；同主题下不同阅读目标可分成反应、调控、能量等笔记；每个必要原子都有规划位置。

### FR-16 同类结构一致性

优先级 P0。同一类型、同一层级的主题尽量采用相近的命名、章节顺序和导航深度。通用模板是结构规范而非强制填空；不适用的章节可以省略，特殊结构须保存理由。

用户可锁定目录、文件名、章节、顺序和规范位置。首次生成可以全面规划；后续更新建议以局部修改为默认，大规模重构输出可审查的移动、拆分、合并及引用变化列表。

验收：三种代谢途径遵循相似组织原则；不存在为“模板齐全”生成的空章节；锁定位置在增量运行后保持。

### FR-17 唯一规范解释位置

优先级 P0。每个需要完整解释的概念，在同一输出版本中恰有一个规范位置，可以是独立文件、标题或块。仅作外部引用或已排除的概念可以尚无本地完整解释，但不得生成假链接。

其他位置以引用为主，可保留理解当前上下文必需的简短事实。需要复现完整内容时使用同源嵌入并校验其有效性；不得生成两份各自维护的完整介绍。规范内容更新时，引用事实和派生表格也应检查一致性。

验收：同一概念出现在多个主题时只有一个完整解释来源；正文不会退化为不可读的纯链接集合；引用摘要不保留过期事实。

### FR-18 链接解析与位置迁移

优先级 P0。内容计划使用概念或知识 ID 引用；编译器根据最终发布映射生成实际链接，不让模型猜文件名。区分概念 ID、章节 ID、文件路径和 Obsidian 块 ID。

支持文件链接、标题链接、块链接、别名和嵌入。使用 Vault 相对路径并以 `/` 分隔；文件或标题歧义时使用明确路径或稳定块。标题重名、标点、空格、中文名及 Windows 文件名限制均需处理。

小节升级为独立文件、笔记重命名或移动后，批量更新全部受影响引用和证据映射。修改人工文本中的链接也可能影响人工内容，必须遵守审批规则。无法安全同时更新时，保留旧发布位置，不先移走目标。

验收：迁移前后每个内部引用均解析到同一知识对象；重复文件名不造成误指；表格内链接别名竖线正确转义。

### FR-19 导航与复习组织

优先级 P0。目录和主题总览帮助用户按教材结构浏览；笔记可包含定义、核心机制、易混对照、条件与例外、记忆提示和必要图解。重点依据学习目标产生，不能虚构考试频次或出题概率。

标题、标签及 Properties 提供稳定可读的基础字段，支持用户现有 Obsidian 工作流。正文不得依赖特定第三方插件才能读懂；插件增强可以另行启用，关闭后保留核心内容。

验收：仅使用标准 Obsidian 即可导航、阅读、渲染主要内容；不安装 Noetome 插件也能使用输出。

## 9 个性化写作与主动视觉表达

### FR-20 风格配置与参考学习

优先级 P0。StyleProfile 描述措辞、标题层级、术语语言、解释密度、列表和表格偏好、图示偏好、强调方式及可选结构规范。支持自然语言说明转换为可编辑配置，并显示冲突项。

旧库参考须由用户主动选取，建议可选代表性笔记或目录。系统提取表达习惯形成风格方案，不将样例事实视为新资料，也不复制整段样例内容。用户可预览同一小段知识的不同风格再应用。

验收：风格变化可以复用已核验知识；极简和详细的必要原子集合一致；自定义要求若与完整性或人工锁定冲突，会提示而非暗中违反。

### FR-21 章节表达规划

优先级 P0。每个章节在编译前决定主要表示形式、必要辅助形式和理由。决策基于知识类型、学习用途、信息密度、可读性和渲染能力，不取决于原文是否有图。

| 知识特征 | 优先候选 | 必须保留 |
| --- | --- | --- |
| 单一概念定义 | 正文、属性列表 | 定义范围和限定条件 |
| 多对象可比属性 | 对照表 | 各属性单位、缺失含义和例外 |
| 顺序过程 | 有序列表、流程图 | 步骤顺序、分支、输入输出 |
| 因果与调控 | 流程图、分层解释 | 因果方向、正负作用和成立条件 |
| 分类体系 | 树状列表、分类表 | 类别边界和多重归属 |
| 公式与证明 | LaTeX、分步推导 | 符号定义、前提、中间步骤 |
| 易混淆知识 | 对照表、Callout | 区别依据及适用场景 |
| 时间演变 | 时间线、版本表 | 时间范围与证据状态 |
| 精确观察和照片 | 原图、说明 | 比例、标注及真实观测细节 |

同一知识可以有总览表和机制解释，但须有主次；不能为增加图表数量重复全部正文。复杂表格可以拆分为关联表格或配套段落，不得为缩窄版面删除信息。

验收：仅提供文字的多对象比较会产生有意义的表格；仅提供文字的多步骤机制可产生流程图；无需图示时仍允许正文。

### FR-22 来源图片重现和重绘

优先级 P0。对每张来源图片判断其知识价值，形成保留、提取知识、重绘、关联已有图或排除的决定。处理优先级为原生高级 Markdown、矢量图、原图，但任何转换都以前置的信息完整性检查为准。

原图承载真实观测时保留原图；复杂空间关系或化学结构不能为了使用 Mermaid 而简化错。重绘记录与原图的对应关系，检查标注、箭头方向、正负号、化学计量、单位、坐标、图例、比例和空间关系。缺乏原始数据时不生成看似精确的新实验曲线。

转换失败可回退到原图并附必要文字解释。原图也无法辨认时标记未解决，而非宣布“已保留所以质量通过”。

验收：重绘丢失关键箭头或单位时不能发布该图；原图可用则回退，原图不可用则进入问题队列。

### FR-23 主动图示的语义约束

优先级 P0。新生成图表的节点、箭头、表格单元格和标签均映射到知识原子或经过验证的派生关系。用表达优化改变形式时，不得新增未经支持的因果关系或把相关性画成因果性。

区分来源重现图和主动表达图，在内部元数据保存 provenance。派生计算保存输入、公式和结果；可以在正文以必要说明解释图意，但不默认加入冗长来源清单。

验收：流程图每条实质关系能回到相应知识；表格“未给出”不会被补为推测数值；图形简化不会删除重要例外。

### FR-24 数学和化学表达

优先级 P0。输入有 TeX 源码时保留原始源码及经过检查的渲染表达；来自扫描或 PDF 排版时只能重建等价 LaTeX，必须保存原区域，不能承诺恢复作者原始字符序列。

保留上下标、向量、矩阵、正负号、积分范围、量纲、反应方向、条件、计量及推导顺序。数学语法能渲染不等于语义正确，需执行来源对照；宏或扩展不兼容时采用可渲染等价写法或图像回退并说明。

验收：源码输入可逐字核对；扫描公式必须通过语义核对；未确认的符号有显式问题项，不能默认替换为最常见表达。

### FR-25 Obsidian 兼容编译

优先级 P0。输出包括标准标题、列表、表格、Wikilinks、嵌入、Callouts、MathJax、Mermaid、图片和适量 Properties。编译器处理转义、代码围栏、YAML 类型、资源路径和链接目标。

MathJax 使用 `$...$` 与 `$$...$$`；Mermaid 使用带语言标识的代码块。Mermaid 内部链接不替代正文中的普通知识关联。对目标 Obsidian 所带 Mermaid 版本不支持的图类型，应回退为已验证类型、SVG 或文字列表。

块 ID 使用兼容字符并在当前文件内唯一。链接到整个表格或 Callout 可用外部块标识；不承诺定位其中任意单元格。嵌入循环应检测并限制。SVG 和图片采用本地相对路径，禁止渲染时执行不可信脚本或默认加载外部追踪资源。

验收：在记录了版本的 Obsidian 干净环境中打开测试 Vault，公式、图表、标题和块引用均可用；语法检查和真实渲染检查均完成。

## 10 来源追溯与结果交付

### FR-26 无正文来源负担的追溯

优先级 P0。默认不在笔记正文插入文献编号、逐句脚注或长出处列表；来源由项目索引维护。应用内可从笔记、章节或可映射内容块查看对应知识、支持证据、反证和原始位置。

建议追溯链为发布版本、笔记 ID、章节或内容块 ID、知识原子、事实主张、证据、来源版本及区域。外部编辑导致映射过期时显示“需重建映射”，不得高亮到错误页面并声称精确匹配。

验收：正文保持干净，用户仍可在基本预览中找到相应原始资料；同一事实的多个来源均可查看；人工新增文字不会自动获得虚假 AI 证据。

### FR-27 Vault 输出与可移植索引

优先级 P0。输出 Vault 包含 Markdown、必要资源和可选导出的独立索引。运行数据库、缓存、密钥和临时文件与输出区分离。建议来源索引支持带版本的 JSON 导出，避免笔记离开本机后完全丢失追溯关系。

导出包含文件清单、内容指纹、规范位置、来源描述及定位信息；是否打包原始资料由用户单独选择。迁移后缺少原文件时仍能展示来源描述，并允许重新定位后验证指纹。

验收：把 Vault 复制到另一目录后相对链接与资源有效；索引导出不含密钥或本机无关路径；丢失索引不影响基本阅读，但应用明确追溯能力受限。

### FR-28 结题与阶段报告

优先级 P0。报告包含配置和来源版本、四类完成状态、发布范围、知识与来源覆盖、排除项、失败项、争议、人工审批、研究候选、资源及调用消耗。每个统计可进入明细。

未纳入本轮范围、合法排除、待审核、解析失败和预算未完成分别列出。报告不得仅给一个百分比，也不得把“模型调用结束”当作成功。建议提供可保存的 Markdown 报告和机器可读摘要。

验收：在存在5个未解决争议、50个研究候选时，报告明确区分它们是否影响本轮完成；任一未覆盖来源可以定位到原始项。

## 11 增量维护与人工控制

### FR-29 变更检测与依赖传播

优先级 P0。检测新来源、来源更新、知识修订、风格变化、目录变更和外部笔记编辑，分别计算影响范围。依赖至少覆盖来源、证据、主张、原子、概念、计划、表达、文件和资源。

纯链接变化使用确定性修正；风格变化原则上不重做资料解析；事实变化使相关摘要、表格、公式及图示失效并重新校验。缓存键包含输入、策略、模型和编译器等必要版本，不能仅根据文件名复用旧结果。

验收：新增一本只影响一个主题的资料，不重写无关笔记；调整模型或筛选规则后相关缓存正确失效，原证据可复用。

### FR-30 人工编辑与锁定保护

优先级 P0。保存上次发布基准，比较当前磁盘内容和新生成候选。凡 AI 变更可能影响人工内容的含义、结构、链接或位置，均要求针对性审批。无法判断编辑来源时按人工内容保守处理。

保护范围包括直接改写、文件移动、删除、合并、章节提升、图像替换、关系修正和回滚。文件级无文本冲突不代表语义上没有影响。对完全独立且未被锁定的生成区域可继续处理；待批准对象及其依赖变更暂缓发布。

验收：用户改动过的断言即使与 AI 判断不一致，也不会被静默覆盖；回滚不能抹掉版本发布后的人工编辑；跨文件搬运同样触发保护。

### FR-31 三级问题与审批策略

优先级 P0。问题等级与是否打断全局执行分开管理，关闭普通审批不代表所有问题都可发布。

| 等级 | 典型情况 | 自动模式 | 重要问题审核 | 严格审核 |
| --- | --- | --- | --- | --- |
| L1 可自动处理 | 明确同义归并、可验证格式错误 | 自动处理并记录 | 自动处理并记录 | 纳入复核摘要 |
| L2 带标记继续 | 可表达的观点争议、非关键缺口 | 保留状态并继续 | 生成候选供审阅 | 相应内容发布前审批 |
| L3 阻断受影响变更 | 人工编辑风险、关键公式不明、结构不可解析 | 隔离该变更，继续独立任务 | 隔离并请求审批 | 隔离并请求审批 |

L3 不等于必须停止全部任务。只有模型凭据失效、存储无法写入、项目状态损坏或没有可独立执行任务时，才进入项目级等待或失败状态。用户暂不处理 L3 时，可交付不依赖它的明确部分结果，但不能宣称全部通过。

验收：出现一个人工冲突时其他主题仍能完成；普通自动模式下该人工冲突也不能被覆盖；报告明确待审批范围。

### FR-32 差异审批与失效控制

优先级 P0。审批界面显示当前内容、新候选、变化理由、受影响知识及证据，必要时提供基准版本。用户可以接受、拒绝、保留当前、局部采纳或编辑候选后再提交。

审批绑定当前文件指纹、候选版本、配置和影响清单。审批之后、写入之前再次检查磁盘；内容变化则原审批失效并重新比较。拒绝决定留痕，重试不会再次自动应用；批量审批可按同类低风险变更合并，但不隐藏人工内容差异。

验收：用户批准后又在 Obsidian 编辑相同文件，系统不会使用旧审批覆盖新内容；每个实际应用变更能找到其批准版本。

### FR-33 安全发布与版本回滚

优先级 P0。先在暂存区生成候选文件、资源及索引，通过校验后发布。发布记录列出新增、修改、移动和删除项，并保留可恢复快照。文件写入避免半成品；多文件发布需有日志或等效机制保证中断可恢复。

操作系统通常不提供整个 Vault 的一次性原子替换保证，因此产品必须处理部分写入、文件占用、同步冲突和重启后的补偿。发布成功标记只在内容、链接和索引一致后写入。回滚遵守人工保护，不能默认恢复整库以覆盖后续人工编辑。

验收：中途断电后恢复到可验证的一致版本或明确待恢复状态；不出现新笔记引用不存在目标却显示成功的结果。

### FR-34 外部变更与非托管内容

优先级 P0。把用户创建的文件、非托管附件和 Obsidian 配置与生成器管理内容区分。同步工具或外部编辑器写入时，依据内容而非时间戳检测变化。人工删除生成文件应记录为显式外部变更，不能立刻自动复活。

没有旧发布基准的已有 Vault 默认只读扫描或风格参考；接管其内容需明确的导入和确认流程。结构锁定信息与管理范围保存在项目状态中，不通过隐蔽覆盖 `.obsidian` 设置实现。

验收：陌生笔记、插件配置及无关附件在更新前后不变；人工删除或重命名文件后系统提出候选处理而非静默重建。

## 12 长任务执行与模型接入

### FR-35 持久化任务与断点恢复

优先级 P0。任务分为可持久化的有限工作单元，记录输入版本、依赖、状态、输出、重试、资源消耗和检查点。成功的单元可复用；失败或版本失效的单元重新计算，不从头反复读取全库。

支持暂停、继续、重试、取消和崩溃恢复。暂停停止发出新请求，在可安全边界落盘；已发往服务商的请求可能继续计费，应显示在途状态。取消保留已确认版本，未发布候选可保留供恢复或清理。

验收：运行中强制退出后，已完成解析和核验不无理由重复；恢复不会重复创建概念、重复发布或重复累计同一个已确认响应。

### FR-36 重试和故障隔离

优先级 P0。网络超时、限流、服务不可用、输出结构不合法、上下文超限和解析器崩溃使用不同恢复策略。重试有次数上限、退避及单独预算；不在失败循环中无限消耗。

模型结构输出需校验，失败时仅修复必要范围。无法确定远端请求是否完成时标记未知，不谎称未计费；具备幂等能力的提供商可复用请求标识。单个坏页面、图或主题不会阻断不依赖它的工作。

验收：连续限流时请求频率受控；错误 JSON 不直接写入知识库；重试用尽后问题可定位且任务不永远显示运行中。

### FR-37 模型提供商与能力路由

优先级 P0 为 API。提供商配置包含服务地址、凭据引用、模型标识、上下文限制、输出能力、视觉支持、速率限制及费用配置。不同任务可分配不同模型，但必须保存实际调用模型和策略版本。

能力不足时明确提示替代路线：视觉解析不能悄悄退化为只看 OCR 文本；需要结构化输出时不能假设所有兼容接口行为相同。服务商切换或模型版本变化后影响结果应可比较。

Agent 适配列为 P1，本地模型成熟支持列为 P2，均不得绕过同一知识 Schema、预算、来源和人工保护。第一版不绑定单一厂商；具体首发提供商列表待定。

验收：模型连接失败不丢失项目；文本模型不被派发不能完成的看图任务；调用记录能解释某条结果来自哪个模型和输入版本。

### FR-38 预算与在途请求

优先级 P0。至少记录输入、输出和可获得的其他 Token 用量，费用估算、实际返回用量、检索次数、重试和耗时分别记录。价格有币种、单位及生效时间；未配置价格时显示费用未知，不能显示为零。

并发调度在发起请求前预留预算，实际结算后释放差额。达到上限停止新任务，允许在途请求按已说明策略结束。Token 可设置请求输出上限；服务商隐藏费用、未知计费和在途请求意味着不能承诺费用绝对零超额，界面应区分应用上限、已承诺用量和服务商账单。

验收：多个并发请求不会各自拿完整剩余预算；费用未知时仍能用 Token 或次数限制；到限后状态为预算停止并保留未完成工作。

### FR-39 进度和后台运行

优先级 P0。任务中心展示当前阶段、主题、已完成与待处理数量、失败和审批、模型消耗及最近有效进展。研究会增加候选数量，不能将推测进度展示为精确承诺。

长任务与窗口生命周期解耦。关闭窗口行为建议提供“继续后台运行”和“安全暂停后退出”，记住用户选择；应用不可不告知地改变电源休眠策略。睡眠、网络切换或重启后恢复可解释状态。

验收：窗口关闭后行为与所选策略一致；状态长时间无进展时能看到在等待网络、预算还是输入；预计剩余时间可显示未知。

### FR-40 可审计日志与问题定位

优先级 P0。用户能从问题定位到任务、来源范围、知识对象和受影响文件。日志保存事件时间、版本、错误分类和处理动作，默认不含完整密钥、认证头及无关原文。

诊断导出提供范围和内容预览，用户决定是否包含敏感材料。记录足以重现问题的配置和指纹，不以保存所有无限长模型上下文为默认。存储保留和清理策略可配置，清理前说明是否影响恢复及追溯。

验收：一次失败可在应用内定位并局部重试；导出诊断不包含明文凭据；清理缓存不破坏已发布版本的必需索引。

## 13 逻辑数据模型与一致性要求

以下为建议逻辑契约，不限定数据库或序列化技术。任何实现都必须能够表达相同语义和约束。

### 13.1 主要实体及最小字段

| 实体 | 最小信息 | 不变量 |
| --- | --- | --- |
| Project | ID、名称、学科、配置版本、目标 Vault、管理范围 | 项目与输出路径解绑，迁移可识别 |
| SourceVersion | 来源ID、版本ID、类型、内容指纹、描述、可用位置 | 内容改变产生版本，不覆盖旧证据 |
| SourceSpan | 来源版本、类型、文本或区域、位置、质量状态 | 每单元可计数并追溯 |
| Evidence | 来源单元、片段、定位、证据关系、获取时间 | 支持与反驳分开，允许一对多 |
| Concept | ID、规范名、别名、类型、主题、身份状态 | 名称不是主键；归并有重定向 |
| KnowledgeAtom | ID、类型、结构化内容、关联概念、主张引用、条件、版本 | 不因风格或位置变化复制事实 |
| Claim | ID、主体、谓词、客体或值、条件、核验状态 | 不同条件的事实可以共存 |
| ClaimEvidence | 主张、证据、支持或反驳或限定 | 多对多并保留关系意义 |
| Relation | 起点、终点、关系类型、条件、依据 | 不只保存父子关系 |
| Topic | ID、名称、多重归属、主要导航父项 | 知识图与输出目录分别管理 |
| NotePlan | 笔记ID、类型、章节、原子分配、输出路径、结构版本 | 所需原子覆盖可校验 |
| SectionPlan | 章节ID、顺序、标题、原子集合、锁定状态 | 标题变更不改变章节身份 |
| RepresentationPlan | 章节ID、形式、候选、理由、覆盖原子、资源 | 图表可反查知识依据 |
| Placement | 知识ID、笔记ID、目标类型、锚点、是否规范位置 | 同概念同版本完整解释位置唯一 |
| CoverageRecord | 来源单元、阶段、映射、排除原因、策略版本 | 排除与失败、重复不混为一类 |
| ResearchItem | 范围、理由、批准状态、优先级、预算、结果 | 候选不等同批准工作 |
| ValidationIssue | 对象、等级、规则、证据、状态、处置 | 关闭问题有可复核理由 |
| ChangeSet | 基准指纹、当前指纹、候选、依赖、审批状态 | 审批绑定版本，内容变化即失效 |
| Job | 输入版本、依赖、状态、尝试、输出、消耗 | 重试可辨识，不重复发布 |
| Release | 版本、文件清单、指纹、计划与索引版本、报告 | 成功状态对应一致产物 |

### 13.2 版本和依赖规则

所有关键对象具备创建时间、更新原因和修订版本。删除知识使用可追踪的废止或替代关系，不能造成悬空证据。概念合并和拆分记录双向历史；只有语义真正相同才合并事实。

输出版本引用确定的知识版本、计划版本、配置和编译器版本。显示“已验证”必须说明验证的是哪个版本；来源、内容或模型修订后，需要失效相关验证结果。旧版本保持可查，不用新证据覆盖旧结论的历史来源。

增量依赖关系为：来源变化影响证据和主张，主张影响知识原子及其关系，知识变化影响计划和表达，位置变化影响引用，最终共同影响发布及追溯索引。执行图应能检测循环依赖，研究反馈循环通过新版本和有限迭代管理。


### 13.4 存储与导出约束

建议将运行数据库和工作队列保存在项目工作区，将可阅读文件与发布索引作为输出。输出可以放在用户同步目录，运行数据库不得依赖云盘实时同步才能保持一致。资源采用去重指纹和稳定引用，不能仅凭相同文件名覆盖。

凭据存放在系统安全存储或等效受保护机制，通过引用绑定提供商；不进入数据库导出、Vault、报告或 Git。导出数据带 schema_version，升级前可备份，升级失败可恢复；旧版本不能无提示写入不兼容结构。

界面以创建任务、理解进度、审阅风险和使用产物为中心。知识 IR、缓存键等实现概念不应成为用户启动任务的必填术语。

### 14.1 页面清单

| 页面 | 主要内容 | 必要操作 | 空状态或异常 |

### 14.2 必须明确的交互

启动按钮附近说明本轮将处理哪些资料、是否联网、使用哪个模型和何种预算。不把每项内部参数都放在主表单；高级设置可折叠，启动摘要需仍可读。

进度页将“执行状态”“已发布结果”“待审核变更”分别呈现。新增候选导致工作总量变化时说明变化来源。处理中可查看已经完成的局部版本，但未验证内容标为候选，不能与已发布笔记混淆。

审批页默认以用户关心的内容差异为主，证据和原始结构可按需展开。接受按钮标明具体变更范围；审批过期后禁用旧按钮并要求重新查看。

对无障碍与键盘操作，要求焦点可见、主要操作可通过键盘执行、状态不只依赖颜色、长文本可缩放。大表格、长公式和复杂图可单独放大，不以裁切隐藏内容。

## 15 非功能需求与质量指标

以下数值是用于首轮验证的建议门槛，尚未进行产品实测。首次基准运行后可以评审调整，但不得在失败后不留记录地降低门槛。

### 15.1 内容质量与可靠性

| 编号 | 要求 | 建议验收门槛或方法 |
| --- | --- | --- |
| NFR-01 来源处理透明 | 每个来源单元有状态和处理依据 | 输入清单对账100%，失败和排除可定位 |
| NFR-02 知识召回 | 已纳入目标的必要知识充分覆盖 | 独立人工金标准原子召回率至少98%，关键原子100% |
| NFR-03 事实准确 | 事实、条件、单位与来源一致 | 分层抽样准确率至少98%，已发现严重事实错误零未处置 |
| NFR-04 引用可追溯 | 所有生成的实质陈述有来源或可验证推导 | 已发布实质原子映射完整率100%，定位抽查零误指 |
| NFR-05 链接可用 | 内部链接唯一解析，嵌入无循环缺陷 | 本轮发布范围内有效率100%，断链零 |
| NFR-06 视觉和公式 | 关键图表与公式无已知语义损失 | 金标准关键图和公式逐项通过；未通过者回退或阻断 |
| NFR-07 人工保护 | 无批准不影响人工内容 | 故障及并发编辑测试中未批准覆盖零次 |
| NFR-08 可恢复 | 已提交结果不因中断损坏 | 检查点恢复、重试、发布恢复和回滚测试全部通过 |

“关键原子”由人工基准预先指定，包含核心公式、反应、条件、限制和例外，不由待测系统自行降低重要性。“实质陈述”指提供知识结论的内容；目录、过渡句和纯排版标签不计入。

召回率门槛用于评估产品在独立基准上的能力，不豁免某次运行的已知必要知识缺口。只要本轮存在已知必需原子遗漏，就仍不能宣布资料覆盖完成。

### 15.2 指标计算口径

- 来源处置率 = 已完成处理或经合法排除的来源单元数 / 本轮来源单元总数。失败和待处理不计入分子。
- 必要原子编译覆盖率 = 已在当前候选或发布版本正确表达的必要原子数 / 本轮确认必要原子数。候选与发布的数值分别显示。
- 金标准召回率 = 被正确覆盖的人工参考原子数 / 人工参考原子总数。错误合并、丢条件或只提及名称不算正确覆盖。
- 事实准确率 = 抽样中事实及适用条件均正确的陈述数 / 抽样实质陈述总数。无法确认计入未通过，不直接剔除。
- 证据映射完整率 = 有有效来源或完整推导链的生成实质原子数 / 生成实质原子总数。模型“自信”不算证据。
- 链接有效率 = 唯一定位到预期目标的内部链接数 / 全部内部链接数。仅存在同名文件不算通过。
- 人工修改保护率 = 按批准或保留策略正确处理的人工影响变更数 / 所有人工影响变更数；同时单独统计未批准覆盖次数。

分母为零时显示“不适用”。用户排除规则发生变化必须更新分母版本并保留旧指标。不能通过把困难内容全部排除来提高召回率，因此排除项必须独立抽审。

### 15.3 性能和容量基线

| 编号 | 场景 | 建议目标 |
| --- | --- | --- |
| NFR-09 长时间执行 | API 请求、解析与编译混合长任务 | 连续24小时基准运行，无不可恢复损坏和无界资源增长 |
| NFR-10 中等项目 | 3份资料合计1000页、10000知识原子、1000篇输出笔记 | 可完成端到端处理，不要求一次载入全部上下文 |
| NFR-11 大库管理 | 3000篇笔记，其中200篇人工修改 | 可扫描影响、分页展示差异，不因全量渲染冻结界面 |
| NFR-12 交互响应 | 项目页、暂停命令、搜索和打开问题 | 本地常规操作P95在2秒内反馈；长操作立即给状态 |
| NFR-13 恢复控制 | 暂停或退出 | 2秒内停止调度新请求；在途请求和安全落盘可继续显示 |

建议基准机记录 Windows x64 版本、8核处理器、16GB内存、SSD以及网络和提供商信息。这是统一测试环境建议，不是最低硬件要求。扫描 OCR、本地模型及外部 API 耗时分别计量；不承诺固定“每本书几分钟”或固定生成成本。

### 15.4 安全与兼容

NFR-14：应用仅在批准目录读写；路径规范化阻止越界写入，处理 Windows 保留名、尾随点、非法字符和路径长度问题。生成内容不能控制输出根目录或执行任意脚本。

NFR-15：凭据不进入日志和导出；远程模型与联网研究分别展示数据用途。外部材料按不可信输入处理，不能通过资料内容改变工具权限或删除文件。应用预览隔离脚本和外部资源。

NFR-16：发布时记录测试的最低支持 Obsidian 版本和当前稳定版本，验证 Markdown、Mermaid、MathJax、SVG、Properties、标题与块链接。不能仅凭文档声明支持就视为实机通过。其他 Markdown 阅读器可以阅读基础文本，Obsidian 扩展不承诺完全等价。

NFR-17：提供可导出日志、配置、版本和问题报告；迁移数据前备份，损坏时可诊断。对项目规模增长采用分页、批处理和受控并发，避免不可控 Token 和内存放大。

### 16.4 发布通过条件

P0边界和指标基线已采纳，正式验收前还需锁定实际基准资料与版本。通过全部适用P0用例、达到内容指标且不存在未处置的严重错误后，才可称该版本达到个人可用标准。

验收记录应同时包含自动结果、人工标注差异、实际 Obsidian 渲染检查、故障注入结果和调用成本。模型自评只能补充问题发现，不能替代独立基准。普通表达建议或低风险问题可以留待下一版，但须明确影响和理由。

## 19 贯穿示例

本例展示组织行为，不作为生物化学事实校核材料。正式基准中的科学内容必须来自经核对的资料。

### 19.1 输入与预期组织

用户导入三份资料，均涉及糖酵解，一份侧重反应顺序，一份侧重调控，一份包含图表。选择资料驱动、深入、详细风格，目标用于理解和背诵。系统先建立概念、反应步骤、调控条件及证据，再生成如下可调整结构：

```text
生物化学/
  糖代谢/
    糖酵解/
      糖酵解概述.md
      糖酵解的反应过程.md
      糖酵解的调控机制.md
      糖酵解的能量收支.md
      关键酶/
        葡糖激酶.md
资源/
  pathway-diagram.svg
```

“己糖激酶”此时可以把完整解释放在调控机制笔记的标题下，不要求一开始独立成篇。反应过程中的引用必须定位到真实标题：

```markdown
参见[[生物化学/糖代谢/糖酵解/糖酵解的调控机制#己糖激酶|己糖激酶]]。
```

若出现在 Markdown 表格内，显示名分隔符按表格语法转义：

```markdown
| 对象 | 详细说明 |
| --- | --- |
| 己糖激酶 | [[糖酵解的调控机制#己糖激酶\|规范解释]] |
```

结构规划可以按知识量和复用价值调整，但实际编译应使用经解析的明确路径，不能机械复制示例中的简写。

### 19.2 主动表达与来源

虽然某份资料用连续文字描述反应顺序，表达规划器仍可以生成步骤总览表；有适当因果或调控关系时可加流程图。每一行、节点和关系都引用同一知识模型，复杂例外放入表格备注或关联小节。

同一知识在表格和解释段中出现是表达复用；规范概念完整解释仍只维护一份。原资料的复杂图不能可靠重绘时保留原图。读者不看到逐行出处，但在 Noetome 的来源侧栏可以查到每项依据。

### 19.3 继续维护

用户人工修改调控机制中的一段解释，随后加入第四份教材。新资料补充该段相关条件时，系统产生差异和证据说明，等待用户决定。新资料在其他主题中的无冲突知识继续发布。

若知识增加使“己糖激酶”需要独立成篇，系统提出结构变更，更新所有引用及来源映射；只要涉及人工内容或锁定结构，就等待对应审批。审批期间不先移走旧目标。

最终报告可以显示已发布的可用结果、待审批变更和继续研究候选，清楚区分本轮达成与未达成部分。
