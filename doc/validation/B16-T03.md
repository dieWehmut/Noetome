## 保留的失败与中断

- 最初 Linux 暂停／取消行为失败。独立进程和文件身份观察定位到 Unix 额外打开并关闭 SQLite inode 会释放本进程 POSIX 锁，导致另一个连接删除仍在使用的 WAL／SHM。修复后以实际写锁竞争、控制事务关闭后的文件身份与第一连接看到暂停指令验证；没有放宽传输或恢复规则。
- 早期 Linux 全量曾因版本断言、运行器导入路径以及错误地把 Linux ELF 配成 Windows Native CLI 而失败。原始 RED 与配置修复记录保留；后续正确配置的完整运行另行保存，不覆盖失败日志。
- 历史 CODE792 Windows 各产品步骤虽退出 0，最后 standalone CLI 与 workspace CLI 的字节不同，最终产物守卫实际失败、driver 退出 1，不能记整体通过。两支真实 Windows CLI 后续完成双向 receipt-before-pins 恢复，2 个方向、126 项检查通过；每个方向 8 个确认片段、8 次 fake HTTP，独立人工账本累计 1300、pending 0，没有记作真实费用。
- `080656` 重跑因随包指南修订受控中断。已经运行的 Cargo 检查正常退出 0 后才停止暂停的 driver，退出 125；workspace build 与 Store16 通过，未启动的预算及全量检查没有计为通过。

最后运行统一使用 workspace 构建的 CLI 副本，并保留严格的同字节守卫。历史失败和中断的详细指纹继续保留，测试成功不抹去这些观察。

- 真实配置：`max_chunk_bytes=6000`、`max_output_tokens=8192`、`request_timeout_ms=60000`、`live` / `deepseek-flash` / `NOETOME_TANGMAO_API_KEY`。
- UI 报错原文：`DESKTOP_COMPILE_WORKER_REFUSED：整理worker未正常返回，请查看持久任务的错误与预算状态。`
- 运行停在 `queued/prepare`：`prepared_pages=0`、`units_total=0`、`attempts=0`；账本未消耗（33,185 tokens / 10 attempts / remaining 9,966,815），但账本被置只读并生成 `tangmao-deepseek.usage.json.production-authority.json` 与 `.production.sqlite`。

### 根因

`crates/noetome-desktop/src/workbench.rs:340` 把 `project.as_os_str()` 原样传给 `helpers/invoke_compile_credential.ps1`；而 `project_open` 经 `canonicalize` 返回 verbatim 路径（`\\?\D:\…`）。`helpers/text_api_support.ps1:223` 的 `Selected-Path` 要求 `^[A-Za-z]:[\\/]`，verbatim 路径直接抛错，helper 打印 `compile-credential-invoke: scope-invalid` 并 `exit 2`，桌面端在 `workbench.rs:359` 回落为通用拒绝文案。
