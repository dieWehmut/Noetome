## 关键取舍

1. **桌面层只做投影，不做业务判定**。`project_entry::create` 直接调用
   `noetome_cli::project::initialize`，`open` 直接调用 `project::inspect`；
   `ProjectSummary` 的六个字段逐一来自 `ProjectInfo` 与规范化后的根路径，前端只渲染返回值。
   TypeScript 侧不重算项目 ID、Schema 版本、创建时间或状态。
2. **错误码原样透传**。`ProjectError` 的 `Display` 已是 `代码：说明`，桌面命令 `map_err(|e| e.to_string())`
   直接把它交给前端；前端只判断是否以已知 `PROJECT_*`/`DESKTOP_*` 代码开头，否则包成
   `DESKTOP_PROJECT_ERROR：…`，未知失败不会被写成成功。
3. **路径规范化复用既有实现**。`check_components` 负责拒绝空路径、非 UTF-8、`..`、
   Windows 非法名与符号链接；桌面层不另写路径校验、不新增写权限，也不改 `capabilities/main.json`
   （文件操作全部经 Tauri 命令进入 Rust，不引入 dialog 插件）。
4. **不自动修复**。已存在目标返回 `PROJECT_PATH_EXISTS`，未完成初始化残留返回 `PROJECT_INCOMPLETE`，
   损坏配置/数据库返回 `PROJECT_INVALID_CONFIG`/`PROJECT_INVALID_DATABASE`；三者都不清理现场、
   不覆盖、不重建。
5. **`capabilities` 与真实能力同步**。`RuntimeInfo.capabilities` 由两项扩为四项，运行检查页会如实
   显示桌面已接入 `project.create`/`project.open`；`cli_preview` 仍只接受 `help`/`version`。

## CLI 基线（桌面要透传的既有返回）

- `noetome project init <新目录>` → exit 0，摘要含「项目 ID：<uuid>」「Schema 版本：1」
  「创建时间：…Z」「状态：initialized」。
- 重复 init 同一目录 → exit 3
  `PROJECT_PATH_EXISTS：目标已存在，不会覆盖现有内容：…；请选择尚不存在的新目录。`
- `noetome project inspect <有效项目>` → exit 0。
- inspect 不存在路径 → exit 3 `PROJECT_IO_ERROR：无法访问项目路径 …：No such file or directory (os error 2)`。
- inspect 外来目录 → exit 3 `PROJECT_IO_ERROR：无法访问项目路径 …/project.json：No such file or directory (os error 2)`。

桌面命令返回的文本与这些完全同源（同一个 `ProjectError::to_string()`）。

`crates/noetome-desktop/src/project_entry.rs` 的 6 项测试，全部在
`target/desktop-project-tests` 下自建唯一目录，用相对路径→字节的 `snapshot()` 与根外哨兵文件
`sentinel()` 断言「没写任何字节」：

| 测试 | 覆盖 |
| --- | --- |
| `create_reports_fields_that_match_the_disk` | 含中文与空格的目录「我的项目 with spaces」；字段与 `project.json` 一致；重开字段完全相等；根外哨兵字节不变 |
| `create_refuses_an_existing_directory_and_preserves_it` | `PROJECT_PATH_EXISTS`；快照前后完全一致 |
