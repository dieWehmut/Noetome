## 流式获取与来源包

CLI `corpus export-source` 使用同一公开流式原件复制能力，按最多 50 页一批保存当前证据，只复制页/区域声明且已固定摘要的资产，重新读取全部产物后生成完成清单。来源包保留 `pending/needs_ocr/failed`，`knowledge_status` 始终为 `pending`；不会据此宣布知识编译或笔记导出完成。失败留下 `source-package.incomplete.json`，已有目的地拒绝且原文件不变。

Windows 程序 SHA256 `087b0f48e9b7ed9477f0a5c7d052853c76c14e4a45ce12c10905711313e9f243` 的实际大文件专项：757,012,744 字节扫描本获取到 1 MiB 时只终止 CLI，重开只读投影 `interrupted`；重新流式导入创建新确认来源、完整登记 710 页，并导出 710 个 `pending` 页记录。原件与副本摘要一致，重复导出到已有目录被拒绝且全部文件摘要不变。获取阶段当前不提供取消按钮或部分字节续传；旧未确认记录和部分原件保留。见[大文件专项摘要](assets/B16-T02/large-source-summary.json)。

同一程序在扫描本物理第 36 页的新派生来源完成真实 MinerU：worker 请求/启动加载阶段暂停 0.547 秒，恢复识别 31.61 秒；保留原文字层页和新 OCR 两个版本，来源 SHA、页号和几何一致。新页资产目录为项目相对路径，`page.png` 与原始结构 JSON 两项均固定 SHA/字节数；真实移走图片或改变字节后读取被拒绝，恢复后可读。来源包的四个文件全部回读摘要通过，未声明文件没有导出。见[OCR 来源生命周期摘要](assets/B16-T02/ocr-source-lifecycle-summary.json)。这是加载阶段暂停，未观察 GPU kernel 内执行时的取消，不证明科学正确率。

旧 OCR 页的原始结构没有预先固定摘要时，导出报 `CORPUS_ASSET_UNPINNED`，保留未完成标记，不现场补造历史摘要；旧页文字和已声明图片仍可读取。新页资产的缺失、篡改、链接和越界均拒绝。

## 本轮审查修复

- 原件读取或摘要检查出错统一保存 `failed` 与错误码，避免界面永久显示运行中。
- 取消写入持久暂停请求，扫描页尚待 OCR 时也能恢复；操作系统锁随进程退出释放。
- 完整登记的扫描本保留“继续扫描识别”入口；失败页通过显式 `corpus retry` 重试，旧失败与 OCR 前页版本保留。
- OCR 必须精确绑定原件 SHA、物理页号与坐标变换；非零进程退出不能被已有 JSON 掩盖，未终止状态不能导致无限重复同页。
- 同批单页 JSON 损坏保留其他已完成页；页身份包含来源、物理页号、解析器、模型/配置指纹与状态。
- 预检再次失败清除旧的可导入结果；跨项目异步返回不覆盖当前来源，未解析页显示未知尺寸。
- 基础测试显式禁用本机 OCR 配置，避免回归测试触发模型；真实 GPU 与原生 OCR 生命周期独立取证。
- 真实 Windows 强杀发现默认进程 Job 不随宿主退出终止 worker；PDF/OCR 共用独立 kill-on-close Job，worker 在挂起状态下先绑定，再开始运行。早期 OCR 初始化强杀在资源压力下超过观察期限的记录保留；最终程序 PDF 与真实 MinerU 初始化强杀分别实测约 0.016/0.703 秒退出，原生句柄、确认页摘要、SQLite 与恢复状态均核对。OCR 恢复后仍保留待识别页；该专项没有把未确认页重新识别为成功。
- 本轮独立审查在新建合成项目复现 Windows 大小写别名绕过导出边界：相同路径原拼写拒绝，改变大小写却把来源包创建到项目内。导出与资料库内部原件检查改为核对现有祖先目录的文件系统身份，保留无链接路径检查；回归覆盖大小写/命名空间别名、内部导入无新增版本残留、POSIX 链接拒绝与真实外部兄弟目录导出。复现失败原件、修复与最终源码检查分别保存。
