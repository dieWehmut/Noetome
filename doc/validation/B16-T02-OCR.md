# B16-T02 真实 OCR 对照

两套现成方案分别尝试同一批 32 张冻结原页；MinerU 4.2.1 已捕获 32 页、0 页识别失败，PaddleOCR 3.7.0 / Paddle 3.2.1 CUDA / VL-1.6 显式识别块批大小 1 已捕获 32 页、1 页识别失败。生产侧选择 MinerU，保留图表、公式和图中关系的复核要求。正文完整召回及科学正确率均未测量。

样本来自用户选定目录中的 12 个原件版本，22 页中文、10 页英文；全组原 PNG 的输入摘要、原件摘要、物理页号、输出摘要和逐项数值在 [可审阅汇总](assets/B16-T02/ocr-comparison-summary.json)。仓库不收录教材正文、原页图或 OCR 全文；原始结构和图片保存于本机忽略目录的证据归档；[本机归档指纹](assets/B16-T02/ocr-private-archive.json) 只提供大小、SHA256 和相对路径。

四页先验检查观察标题、单位、基因名、跨页续句和图中标注，不是科学知识 Gold 集。MinerU 漏了两项图中标签以及完整稀释比例序列；PaddleOCR 改写了一个谱系标签并漏了同一比例序列。图中数值、方向、表格对应和化学结构不能仅凭 OCR 文字视为核验通过。其余 28 页由执行者看过原页并进行版面和后验锚点核对；汇总如实记录后验锚点缺失，既不把后验检查说成先验 Gold，也不据此宣称全文召回率。

GPU 路径由实际运行时记录：MinerU 文字识别与版面 ONNX 会话使用 DirectML，文字检测 ONNX 会话仍为 CPU；运行时选中的适配器为 RTX 4070 SUPER。PaddleOCR 实际选择 `gpu:0` 的同一 CUDA 设备。下列读数属于整块 GPU，包含同时存在的其他应用，不是 OCR 单进程显存峰值。

- MinerU：83 次有效读数，整机显存采样最大值 6143 MiB，利用率采样最大值 97%。
- PaddleOCR：1941 次有效读数，整机显存采样最大值 11981 MiB，利用率采样最大值 100%。

MinerU 使用明确的两项上游 revision；18 个当前模型文件共 2,098,697,303 字节，逐个流式 SHA256 与冻结清单全部匹配。PaddleOCR 的包、管线版本和当前 28 个模型缓存文件共 2,062,718,289 字节已记录摘要，但首次下载前未独立冻结上游模型 revision；它作为比较方案，不据此宣称与所选方案相同的 revision 锁定。

首次 PaddleOCR 默认 `VLRecognition.batch_size=-1` 已确认前 10 页，第 11 页在 1036.68 秒后仍未返回，整机显存接近 12 GiB。首次比较脚本遗漏页 watchdog，执行者确认进程归属后外部停止了自己的解释器和 venv launcher；失败不是预设 600 秒期限及时触发，旧日志与结果保留。随后按安装的官方配置接口把识别块批大小设为 1，保留默认解码上限，重新运行一致配置的完整 32 页；第 11 页实际返回的时间在下表。

比较工具逐页保存确认产物；`--resume` 在模型加载前核对输入清单、原 PNG 和此前结果摘要，再继续未确认页。Paddle 块批 1 的第 19 页实际在 601.02 秒由 Python 计时线程保存超时失败并退出 124，随后重新加载模型继续。第 4 页之后为原生单页验证暂停；第 24 个确认页之后为最终原生验收与编译内存窗口暂停，第 25 页的未确认识别在 220.84 秒主动取消，未算作成功或失败。暂停时观察到自己的模型进程 private commit 14,512 MiB、整机 GPU 使用 11,973 MiB；这是资源压力观测，不单凭同时发生的 LLVM 编译失败证明唯一原因。旧日志、暂停回执及已确认页摘要保留。Paddle 累计时间按成功模型构建与已确认页调用（包括失败页）求和，不含等待、监督/解释器启动、输入摘要核对和主动取消的未确认页耗时；实际模型构建次数与每次时间列在汇总中。MinerU 保留早期捕获器直接保存的总耗时 195.134276 秒；显式模型构建 2.246363 秒与逐页调用 190.908521 秒之外有 1.979392 秒差额，属于总记录中没有逐项拆分的其他开销，不重算原记录或把差额归给特定操作。两套总耗时口径因此分别标注。

外部 `run_comparison.ps1` 按独立进程期限监督后续识别，默认 600 秒，核对解释器与 launcher 归属后强制结束超限尝试并持久保存失败；Python 线程另作补充。专门用不加载 OCR 的合成 native Sleep 持有 Python GIL，证明计时线程不执行时外部监督仍能保存失败、保留身份及停止自己的进程，7 项检查通过。该合成测试不证明真实 PaddleOCR 发生过 GIL 计时失灵。首版 PowerShell 汇总失败页的 Hashtable 类型错误已独立保留，改成 PSCustomObject 后在新的测试目录复验通过。实际 Windows 验证还包括：不存在的测试原件返回退出 1，失败结果仍保留请求的原件 SHA、物理页和 geometry，且没有伪造文字，共 6 项断言通过；比较结果或原 PNG 被改后分别在模型启动前退出 1 拒绝续跑，共两项前置拒绝通过。篡改检查首测脚本路径算错，未进入被测工具；修正路径后复验通过，原失败保留。续跑时还保存了一次 PowerShell 默认路径参数的启动失败（尚未加载模型，随后修正），以及两次 Paddle 模型构建阶段退出（尚未进入页识别，不计页失败）：首次无 Python traceback；第二次构建 372.70 秒后在加载权重时返回 OS 1455 页面文件空间不足。成功构建及已确认页的累计时间不含这两次失败的构建，它们单列保存；首次退出码未记录，第二次 PowerShell 返回 null，后续监督在启动时缓存进程 handle 以保留退出信息；原生合成任务的成功 0 与失败 7 两种退出码回读分别通过，未加载 OCR/GPU。Python 语法检查通过。

2026-11-14 续跑前独立核对已确认的 30 页及全部 32 张输入图摘要；最后两页分别在 292.33 秒和 83.27 秒返回，先前 30 页结果 SHA256 保持不变。外部监督保存退出码 1，这是第 19 页历史识别失败仍被保留后的整体结果；没有将它改成全组识别成功。完整输入、原件绑定、页号、输出摘要及尺寸均通过回读，成功页区域边界无越界。MinerU 后验稀疏锚点共 11 项缺失，Paddle 共 5 项缺失；它们是原页选定词的线索检查，不能换算成全文召回率。

Paddle GPU 原日志第 1782 条记录包含 NUL 字节，原文件保留、该整条记录被排除并保存行号/字节数/SHA256；汇总明确列出原记录数、有效记录数及损坏记录，不声明资源采样连续无缺口。当前同批模型缓存 28 个文件再次流式核对，2,062,718,289 字节全部与之前的本地清单 SHA256 匹配。运行日志同时提示已安装 cuDNN 9.5 与 Paddle 编译时 cuDNN 9.9 不一致；这是保留的运行时警告，不据此推断识别质量或先前超时的唯一原因。
