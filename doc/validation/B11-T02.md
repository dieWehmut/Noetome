## 3. 关键实现取舍

1. **区域判定按路径组件，不按字符串前缀**。`under(path, area)` 要求 `path == area` 或
   `path` 以 `area + "/"` 开头。`vault2/x` 不算在 `vault` 里——否则任何名字相近的兄弟目录
   都会被误判成输出区内部。
2. **区域混用报 `INDEX_AREA_LEAK`（exit 3）而不是 `INDEX_ARGUMENT`（exit 2）**。
   它是"声明的结构和要求不符"，不是"参数写错了"。错误码分级决定调用方该重试还是该改数据。
3. **来源按字节摘要识别，不按文件名**。重定位先建 `sha256 → 路径` 映射；命中即 `relocated`。
   只有不为命中时才看文件名：有同名但摘要不同 → `digest_mismatch`（"同名不能证明是同一份来源"），
   无同名 → `missing`。**两种失败必须分开计数**：前者是"搬来了但内容变了"，后者是"没搬到这里"。
4. **`missing` 与 `digest_mismatch` 都不指向具体页面**。映射过期时只提示"需要重建映射"，
   绝不给一个可能指错的链接——FR-26 明确禁止指向错误页。
5. **运行库与临时区的字节留在原地**。`adopt` 只记它们的摘要与路径（`runtime_entries`/
   `temp_entries`），不复制进 `control/files/`。复制就等于把会话数据库、缓存和上传残片
   一起打包进可移植输出。
6. **`control/manifest.json` 与 `control/inputs.json` 不带尾换行，输出的四个 JSON 各带一个**。
   `strict` 会重新规范化后逐字节比对，多写一个 `\n` 会让此后每次 `open` 都报"非规范编码"。
   这是仓库里第二次踩同一个坑（B10-T02 的 `author.json`），因此写进了契约第 3 节。
7. **输出清单不含 `created_at`**。索引根的 `control/manifest.json` 带建立时间（冻结事实），
   输出的 `manifest.json` 不带（描述"这次算出了什么"），否则同一冻结输入的两次构建字节不同。

## 6. 实现过程中发现并修掉的缺陷

| # | 缺陷 | 现象 | 修法 |
| --- | --- | --- | --- |
| 1 | `Candidate` 借用生命周期 | `&'a str` 无法从 `Inputs` 借出候选列表 | 改为拥有型 `String` |
| 2 | `Read::by_ref()` 与 `take()` 冲突 | 摘要计算处借用冲突无法编译 | 改为 `(&mut file).take(...)` |
| 3 | 布局常量自带 `control/` 前缀 | 建出 `control/control/`，`open` 报"发现多余的 control" | 常量只写裸名，由调用方 `control.join(...)` |
| 4 | `adopt_into` 里误用 `target` | 写盘路径指向未定义作用域 | 改用 `control` |
| 5 | `OUTPUT_ENTRIES` 未使用 | 输出根多写文件不会被发现 | 在 `write_output` 增加文件集合核对 |
| 6 | 区域分离误用 `argument` | 区域混用报 exit 2（"参数写错"） | 改为 `area_leak`（exit 3，结构不变量） |

另外三处属**自定义接口而非产品**的缺陷，已修正并写进测试：

- `adopt_refuses_a_missing_parent_and_leaves_nothing_behind` 原断言 `PROJECT_IO_ERROR`，
  实测父目录不可访问时统一按 `INDEX_INTEGRITY` 报（与 `structure_store`/`migrate_store`
  的 `require_dir` 逐字相同）→ 改为断言文案 `无法访问索引根的父目录`，
  并注明"关键是失败后不留半个根，而不是错误码措辞"。
- 审计器 `check_expected` 把先验的三键来源记录与重放的四键记录整表比较 → 改为投影 `detail` 后比
  （先验只承载判据，不复制产品措辞）。
- 审计器 `mismatched` 用 `status != relocated` 选，把 `missing` 也收进来 →
  改为只收 `digest_mismatch`（`missing` 已由计数表达，混进来会掩盖两者区别）。
- 审计器 markdown 检查名原为 `markdown-{heading[:6]}`，切片粗到无法定位 →
  改为 `markdown-section:{heading}`，并同步测试断言。

## 8. 仍未闭合

1. **Windows 原生门禁未运行**：无 `x86_64-pc-windows-msvc` target、无 NSIS。
2. **workspace 既有 98 项 lib 失败未修**：需要 `NOETOME_PDF_PYTHON` 指向锁定解释器。
3. **Python 41 failures / 12 errors 未修**：同上，缺 `pdfplumber` 与锁定 Python 3.12。
4. **`locator` 不校验**：本层只保存"第 112-118 页"这样的文本，不验证页码是否真的对应那一节。
5. **不做增量重定位**：每次 `relocate` 都是对整目录的一次完整只读扫描，目录大时是线性成本。
6. **不做跨目录合并**：一次只扫一个目录，多副本需要分次调用后人工合并。
7. **不判断内容质量**：`scientific_status` 固定 `not_run`，本层只核对位置与摘要。
8. **不接 GUI**：索引目前只有 CLI 与报告，桌面端尚无入口。
