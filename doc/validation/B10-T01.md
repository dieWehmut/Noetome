关键实现取舍：

- **章节区间必须是"到下一标题前一行"**：`Section.end_line` 若只覆盖标题行，
  `heading_concept_missing_from_body` 就永远无法证伪——标题里提到的概念必然落在"本节正文"之外。
  端到端证据是 `doc-appendix` 的 `## 3 丙酮酸脱氢酶复合体` 被判未对齐。
- **`number_depth_mismatch` 相对父节判断**：不同书编号约定不同，用绝对层级（`level - 1`）会把
  常规的 `## 1` / `### 1.1` 判成不匹配。规则写成 `depth != parent_depth + 1`。
- **`concept_only_in_caption_or_appendix` 要求全部出现都在图注或附录**：只判"正文计数为 0"会把
  只出现在**标题**里的概念也收进来，而那只该报 `heading_concept_missing_from_body`。
- **标题判据与 Span 层逐字一致**：`#` 后必须跟空白或行尾。更松的规则会让章节树认领
  `inputs.json` 从未标成 heading 的行，两层的"标题"就不是同一个概念了。
- **输出清单不含时间戳**：承诺"同一冻结输入的两次构建字节相同"就不能把墙钟时间写进任何一个
  输出文件。这正是本轮实测发现并修掉的真实缺陷（见下节）。
- **陌生目录报 `OUTLINE_UNKNOWN_ROOT` 而不是 IO 错误**："这不是对齐根"是正常结果，不是故障；
  与 `research`、`retrieve`、`revision` 三类根的行为一致。

## 实现过程中发现并修掉的三个真实缺陷

1. **`outline status <陌生目录>` 报 `PROJECT_IO_ERROR`**。原 `open()` 直接把 `control/` 交给
   `require_dir`，缺少目录就看不出"这不是根"。修法：先判断 `control/` 是否存在，不存在报
   `OUTLINE_UNKNOWN_ROOT`。实测 exit=3、`unknown-root.txt` 留档。
2. **两次构建的 `manifest.json` 不一致**（`created_at` 纳秒级不同），而 HELP 承诺"同一输入必须字节相同"。
   修法：从 `OutputManifest` 删掉 `created_at` 字段，并把帮助文本改成
   "同一冻结输入的两次构建必须字节相同（输出清单不含时间戳）"。修后五个文件全部 SAME。
3. **标题判据比 Span 层松**：`heading_level` 原只看 `#` 个数，于是 `#没有空格` 被算作标题，
   而 `crates/noetome-cli/src/text.rs` 的 `heading()` 要求 `#` 后是空白。这会让章节树认领
   `inputs.json` 从未标记为 heading 的行。修法：按 `text::heading` 的规则补上"后随空白或行尾"，
   并在函数上写明为什么不许放宽。此缺陷由 `cargo test --workspace` 暴露（`outline_model` 单测 1 项失败）。

## 仍未闭合

1. **Windows 原生门禁未运行**：本机只有 `x86_64-unknown-linux-gnu` target，无 Windows 交叉工具链；
   `cargo test` 只在 Linux 上跑过。
2. **workspace 既有失败未修**：99 项失败全部来自 PDF sidecar / 抽取链路的宿主边界，
   需要 `NOETOME_PDF_PYTHON` 锁定解释器；不在本任务范围，也未声称修好。
3. **Python 既有失败未修**：41 failures / 12 errors 同上。
4. **不做语义对齐**：不做同义章节合并、实体识别、语义相似度；词表外的术语不会进全局清单，
   这是刻意选择而非缺陷。
5. **不判断内容质量**：对齐成功只说明"章节结构没有明显缺陷"，不说明概念定义准确、来源权威。
6. **不支持 PDF/DOCX 直接输入**：只吃已规范化的 Markdown；抽取属于上游任务。
7. **不做增量对齐**：每次 build 都从冻结输入全量重算，没有"只重算受影响文档"的路径。
