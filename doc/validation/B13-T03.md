# B13-T03 长时运行与暂停语义的可复现 soak

Linux 上实现并端到端跑通 soak harness：14 项 Rust 集成测试、40 项 Python 审计器测试、
独立只读审计器 118 / 118 / 116 / 114 / 45 项零失败全部在本机实际运行。
**Windows 原生门禁未运行**（本机 rustup 未安装 `x86_64-pc-windows-msvc`，也没有 NSIS）。

**NFR-09 未达标（`not_met`）**：本轮实测最长一次是 300 轮、0.5 秒级，与「连续 24 小时」
相差极远；`structure.json.coverage` 按参数如实写 `not_met`，没有把短时结果当长时结论。
**NFR-13 为 `partially_measured`**：闸门关闭后不再调度新请求这件事由可观测计数证明
（`scheduled_after_pause = 0`），但「应用暂停命令」的界面与在途请求展示不在本轮范围内。

## 3 关键取舍

1. **闸门只在一处判断**：每轮开始取一次 `elapsed`，`paused = pause_after_ms
   .is_some_and(|after| elapsed >= after)`，一旦为真永不复原。分散在多处判断就会出现
   「某些轮被拦住、某些轮漏过」的窗口，而那种 bug 在日志里看不出来。
2. **暂停的可验证性是计数，不是日志**：关门后若还有轮次被调度，`scheduled_after_pause`
   自增；审计器与集成测试都要求它恒为 0。写「已暂停」证明不了任何事。
3. **覆盖率由参数推导**：`planned_floor_millis = rounds × interval_ms` 写进
   NFR-09 的 `detail`，`not_met` 是计算结果而不是硬编码字面量；改 `met` 会被测试与
   审计器同时判失败。
4. **读数与确定性产物分离**：`timings.json` 装逐轮读数（`state`/`elapsed`/`work`/
   `total`/`rss`/`error_code`）与 summary/pause；`structure.json`、`manifest.json`、
   `report.md` 只由参数决定，同参数两次运行必须字节相同。
5. **清单里不能放读数**：这条是被实测打回来的取舍（见 §5）。
6. **无轮次时读数必须为 `null`**：暂停 0 毫秒的样例一轮都没跑，四个内存读数全为
   `null`、增长为「未知」。补 0 会让「不可得」看起来像「测得 0」。

## 6 实现过程中修掉的缺陷

1. **清单带读数**（真实缺陷）：`manifest.json` 原本含 `summary` 与 `pause`，两者都有
   毫秒与 RSS 读数，于是同参数两次运行 `manifest.json` 不同（首跑 `determinism.txt`
   实测 `DIFF manifest.json`）。修法：从 `Manifest` 删掉这两个字段，并在结构上留注释
   说明为什么不能放。
2. **`soak_store.rs` 被写串**：一次批量 patch 把 `bench_model.rs` 的全文写进了
   `soak_store.rs`（774 行，首行是 bench 的文档注释），`cargo build` 报
   `E0425: cannot find function run in module soak_store`。整篇重写恢复。教训：patch
   脚本必须先断言目标文件特征行再写，否则会把两个模块写串。
3. **审计器先验整表比措辞**：`expected-enforcement` / `expected-coverage` 拿先验与
   产品逐字比 `note` 与 `detail`，永远不等。改为投影比对（先验只承载判据）。
4. **暂停样例误报内存缺失**：一轮未调度时四个读数必然全 `null`，审计器原要求齐全。
   改为 `scheduled == 0` 时要求全部 `null`，其余要求齐全。
5. **取数漏空格**：产品写「2000 毫秒」（数字与单位之间有空格），审计器按「数字紧跟
   单位」取数，永远取不到。改为先跳过空白。
6. **`report-no-timings` 按值误报**：暂停样例每轮 `work_millis` 都是 0，与允许值 0
   撞车。该检查删除——按值判断只会误报，真正的保证是「同参数两次运行 report.md 字节
   相同」，由 Rust 集成测试负责。
7. **测试判据过粗**：集成测试最初要求报告里「任何含毫秒的行都不得出现 2000/86400000」，
   实测挂在 `- 判定口径：每一轮开始时记下距起点的毫秒数…`（这句没有数字）。改为提取
   每个「毫秒」前的数字并断言取值 ∈ `{0, 2000, 86400000}`。

## 8 仍未闭合

1. **NFR-09 未达标**：没有跑连续 24 小时，最长一次 300 轮。
2. **NFR-13 只有部分测量**：没有暂停命令的界面，也没有在途请求状态展示。
3. **没有崩溃恢复**：`SOAK_WORK` 只保证失败时留下轮次与复现命令，进程被杀后的恢复
   不在本轮。
4. **没有并发与多进程 soak**。
5. **合成负载**：工作单元是文本分析，不代表真实解析、模型调用与编译的混合负载。
6. **Windows 原生门禁未运行**：本机缺少 `x86_64-pc-windows-msvc` 目标与 NSIS。
7. **既有 98 项库失败未修**：全部集中在本机缺少锁定 PDF Python 解释器造成的宿主边界。
8. **耗时读数不可跨机器比较**：报告与摘要只写「本次运行」的数字，合同也明确禁止横向比较。
