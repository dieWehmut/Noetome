## 交付边界

`sidecar_process::run`只接受可信程序与原生argv、明确单文件、尚不存在的工作区、限额和取消令牌。Core完整读取原始字节、计算SHA/长度并持有只读句柄与文件身份；请求传递绝对UTF8路径及访问约束，未向子进程传递整个用户目录的搜索能力。独占新根具有本轮UUID能力和目录守卫。单请求发送后stdin关闭，stdout只能是一份UTF8 JSON及末尾JSON空白，stderr保持诊断字节。

响应要求同一protocol_version、request_id、原始指纹和workspace能力，明确producer、parser/能力版本、完整有序单元、相对资源清单及结构化问题。所有DTO拒绝未知字段，nullable `Unit.text`也必须存在；未知枚举、缺字段、错身份、重复/漏号、错引用或不完整问题均分类失败。非零退出即使配合法JSON也失败。

Core再次检查资源安全相对路径、实际字节/SHA/长度/身份、普通文件与链接数、UTF8边界及完整文件/目录清单。每资源最多32层目录，遍历迭代执行，未声明目录在下钻前被拒绝。输入及成功返回的资源/目录句柄保持守卫，返回值释放后才允许替换。失败工作区保留诊断现场，没有自动接管或递归清理入口。

默认政策为请求64 KiB、响应4 MiB、诊断64 KiB、输入64 MiB、单资源16 MiB、资源合计64 MiB、资源256、单元10,000、问题1,000、运行30,000 ms。限额可注入且必须正数；按有界块增长，超限不截断后报成功。这些值是协议政策，未据此宣称容量、吞吐或PRD性能达标。

普通库拒绝`producer=fake`，CLI没有fake或parse-pdf入口，项目登记拒绝fake且配置/数据库字节不变。测试helper仅Python标准库，不导入PDF/OCR/模型库，不触发网络或下载。对抗测试中伪造`producer=parser`只用于拒绝不完整响应及校验压力，不证明真实解析器正确。

## 独立审查与必要修复

对`0620140..cae9895`的独立代码审查和公共库实跑发现三项必要缺口。审查探针只使用自造输入/新测试根，不修改已提交源文件、索引或用户旧改动。

1. **重复UTF8扫描延迟了时限和取消。** 10,000单元共用16 MiB资源，初版逐单元重扫约160 GiB且循环不检查Control。独立公共run单独1秒时限实测6887 ms才TIMEOUT；另一有并发CPU竞争的2秒取消探针10224 ms才CANCELLED。修复回归`14-red-validation-latency.txt`分别复现6863 ms时限、5938 ms校验起点取消。每资源只做一次UTF8验证并复用字符串，单元/引用/问题循环持续检查Control后，`16-green-validation-latency.txt`相同1秒政策约888 ms正常完成，校验起点取消约2 ms返回。`15`中的测试错误地坚持优化后仍必然超时；改为合法语义“时限内完成，或及时TIMEOUT”，原始断言错误不删除。
2. **主Job终止失败挡住独立兜底。** 初版`start_kill`失败后先做无界原生`wait`，关闭kill-on-close Job的兜底因而无法执行。该缺口由错误分支静态确认，没有声称制造真实Win32终止API故障。仅测试构建的私有故障入口跳过主终止并返回错误，真实root/child/grandchild仍存活；`17-red-termination-fallback.txt`中PID为38232/44080/33484，旧宿主30013 ms才返回。修复先释放独立kill-on-close Observer全部句柄，另保留不负责kill的外层census Job，再有限轮询原生退出和活动PID；只在确认原生退出后调用缓存wait，确认读写已结束后join。`18-green-termination-fallback.txt`先确认45520/46768/47668存活，再7 ms收束并通过三PID已退出断言，返回SIDECAR_CLEANUP而未掩盖主终止错误。清理另有最多10秒截止；若根、树或IO线程未确认停止，明确cleanup incomplete，不能称为回收成功。
3. **IO线程错误未及时通知控制循环。** 公共run向真实helper发送65988字节请求，helper关闭stdin后继续活5秒；旧宿主等待4秒才TIMEOUT，同helper直接`write_all`对照立即OS109 BrokenPipe。新回归发送66,284字节有效JSON（含合法前导空白，低于128 KiB请求政策），先确认真实三个PID存活，再触发root关闭stdin而不自然退出。`20-red-broken-pipe.txt`复现3816 ms才TIMEOUT；读写线程通过固定三槽错误通道及时通知控制循环后，`22-green-broken-pipe.txt`确认16360/41652/45548存活，再13 ms返回SIDECAR_IO、OS109并核对三PID退出。`21`是测试先观察握手文件exists、内容尚未写完造成EOF的setup竞态；helper改为临时文件加原子rename发布握手后通过，保留原失败记录。现有“不读stdin直到超时”的测试不能替代这个BrokenPipe行为。

独立复审基于`32c1861db82527d2e8587fdc4f26dea9929d44f6`，确认三项均关闭，未发现修复引入的新Critical/Important。审查者重新用rustc链接当前普通rlib（SHA256 `64961b40c855c21185b1c6a5daf111d14f9b22bc6b707fb2c376409379fe6151`）生成新可执行探针，不复用旧链接文件：相同1秒大资源公共run实测873 ms合法完成；原65988字节请求、320层合法输入长路径的closedstdin公共run实测220 ms返回SIDECAR_IO。220 ms包含输入与长路径准备，与握手后13 ms为不同计时范围。

复审者另直接运行最新库测试exe的`sidecar_process::tests::review_ --nocapture --test-threads=1`：6通过、0失败、237 filtered，2.40 s；过滤器含4项新修复回归和2项既有状态测试。实际10,000单元/16 MiB用例878 ms合法完成、取消2 ms；BrokenPipe的43580/44228/46756先存活后13 ms报IO并全部退出；主终止故障树43348/44092/21060先存活后8 ms收束且全部退出。未把复审读到的79/3旧日志表述为复审重跑了全部组。

## 验收矩阵

| 范围 | 要求的实际断言 |
| --- | --- |
| 单请求/身份 | 有效、诊断隔离、末尾空白；启动失败、退出7、崩溃、空/非法UTF8/JSON、截断/额外stdout、版本/身份/指纹不符均拒绝 |
| 完整单元/问题 | 数量、顺序、唯一ID、必填nullable、未知枚举、UTF8范围、资源类型/引用、failed/needs_review与对应问题严格对账 |
| 有界并发 | stdout/stderr超过管道容量仍无死锁；请求、响应、诊断、输入、资源、数量和时间越界及取消明确失败 |
| Windows进程树 | root/child/grandchild先握手确认存活；超时、取消、输出超限、父进程早退及主终止失败兜底后均确认真实退出 |
| 管道失败 | 真实关闭stdin后的BrokenPipe及时IO，实际仍存活树被终止；不由最终TIMEOUT覆盖 |
| 资源/路径 | 绝对/`..`/Windows保留名/尾随点与空格/大小写及文件目录前缀冲突、真实junction/硬链接、未知内容、深目录及既有根均失败；外部哨兵与输入不变 |
| 普通入口 | 普通库、CLI和项目登记排除fake；数据库/配置不变，测试权限入口不进入产品构建 |

Windows树用例让子/孙进程使用独立且不继承父管道的句柄，先等待真实PID握手再触发停止。EOF或父进程退出不能代替完整树验证。Job受控进程管理不限制文件或网络访问，不能称为操作系统沙盒。
