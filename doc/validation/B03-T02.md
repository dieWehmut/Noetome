# B03-T02 单份真实文本PDF解析验收

本项交付独立`source parse-pdf`，只解析明确选取的单份PDF到尚不存在的测试根，不登记来源项目。原始PDF、严格字形库存、逐页正文、真实页/区域定位和Host报告均可从新根复查。项目Schema2和编译Schema1仍分开；B03-T03没有开始。

生产解析只使用pdfplumber 0.11.9及pdfminer.six 20251230；固定CPython3.12.14、Pillow12.3.0、pypdfium2 5.14.0、cryptography50.0.2、charset-normalizer3.5.2、cffi2.1.1、pycparser3.11。8包当前安装版本、9个协议字段与27份原始许可证长度/SHA已逐项核对，完整锁见[runtime-lock](../../sidecars/pdf_parser/runtime-lock.json)。版本锁没有验证原始wheel档案来源，许可证原文按字节保留。

## 接口及实际保护

```text
noetome source parse-pdf <PDF> <尚不存在的测试根> --python <绝对Python路径> [--timeout-ms <0..30000>]
```

调用不安装依赖。按[环境说明](../../sidecars/pdf_parser/README.md)准备受信运行时；唯一adapter以`-I -B`和SystemRoot-only环境启动。Core复用真实Windows Job进程树、三个并发有界管道、只读选定输入和独占快照。PDF v2严格DTO、真实资源字节/身份/单链接、全部已确认页、字形覆盖、正文顺序、UTF8半开范围及CropBox局部pt bbox由Core重算；详细算法见[PDF协议](../technical/PDF_PARSE_PROTOCOL.md)。

所有页parsed且校验通过才ready/退出0；合法partial为needs_review/退出3，保留每页真实状态和已确认范围。文档未确认完整页库存时failed，不伪造page_count或页。输入/配置/协议错误退出2，真实读取/解析/限额/超时/取消/写入受阻退出3，内部输出错误退出1。真实非零native退出码单列保留，不把stderr解析成可信响应。

Host先独占写`.parse.pending.json`并保持文件句柄，完成可取消的资源、快照和目录最终复核，再通过保持打开的文件句柄不覆盖地原子改名为`parse.json`。这一步为交付点。交付前取消不发布正式报告，交付后取消不倒转成功；未知或已有报告始终保留。

## 已复现的失败与修复

初始旧CLI不识别命令形成真实退出2红；模型stub的12个行为红随后修复。Core另实测1e-7微小裁剪必须需复核、公开transport上限不得放宽；adapter修复加密分类、pdfplumber关闭时重新枚举失败页，以及Python/Rust U+001C–U+001F空白差异。

Host初次矩阵4通过/5失败：数字JSON 1.0与1比较、超时测试在根写握手、超时允许保存失败报告，以及误判只读原始硬链接属于测试设置错误，逐项修正，未改作者预期。随后15次真实CLI中前14项作者全文/页/字形/区域全部通过，仅F01聚合failed与冻结needs_review不符；单一Host partial状态修复后再验收。

独立边界审查还实际复现并修复：合法但不同Python3.12.7子进程退出2被误映射为CLI3；在成功报告已写后取消，API错误却残留ready正式报告。前者保留native_exit_code并准确映射1/2，后者改为待提交文件和原子交付点。新解释器/runtime退出码复验、交付前及交付后两种实际取消复验已通过。最初工作区本地target是旧构建，审查误用后已改为显式`D:/Noetome/target`，这次只记设置失败，不算修复失败。

平台原子改名首试relative FileName+RootDirectory在本机返回Win32 87，后来使用绝对目标、RootDirectory=NULL，并持有源/目标祖先目录守卫、核对同父native身份、保持源文件DELETE句柄、ReplaceIfExists=false。真实正常改名、已有目标保护、非法目标、缺DELETE及候选硬链接拒绝分别测试。未知子进程伪造parse.json以及真实可写文件映射输入也独立实测拒绝，原字节保持。
