# B03-T02 真实文本 PDF、物理页与区域定位验收

2026-11-02，Windows 11 x64。已实现普通 CLI 的 `source parse-pdf` 与 `source inspect-pdf`：明确选取一份 PDF，只在尚不存在的测试根保存原始字节、物理页、逐页正文、区域和持久报告，Rust Core 复核后才返回结果。全部页面可靠时退出0；`failed` 或 `needs_review` 退出3，保留真实问题及已确认范围。

来源项目仍是 Schema2，编译库仍是独立 Schema1。本项没有登记 PDF 来源版本、修改数据库、写 Vault、接 OCR/模型或增加项目 GUI。下一项是另轮启动的 B03-T03；持续开发目标仍未完成。

## 实际实现与环境

唯一文本 PDF adapter 是 [pdfplumber 0.11.9](../../sidecars/pdf_parser/README.md)，其依赖 pdfminer.six 20251230 提供字符清单；pypdfium2/Pillow 是上游运行依赖，不是第二个文本解析后端。按精确版本的官方 API、发行元数据及许可证核查，全部8个运行依赖和 wheel SHA 已锁定于 [requirements-lock.txt](../../sidecars/pdf_parser/requirements-lock.txt) 与 [runtime-lock.json](../../sidecars/pdf_parser/runtime-lock.json)。不在仓库分发依赖二进制；后续运行时打包仍须保留 wheel 的全部 notices。

实测 Rust/Cargo 1.98.1、CPython 3.12.14、Windows-11-10.0.26200-SP0 / AMD64。通过工作区运行时创建新的独立 venv，实际以 `--isolated --require-hashes --only-binary=:all:` 从官方 PyPI 安装锁定 wheel；最终重新读取全部版本并运行 `pip --isolated check`，退出0、无依赖冲突，证据见 [环境事实](assets/B03-T02-runtime.json)、[pip 输出](assets/B03-T02-pip-check.log)。开发机解释器路径仅作为执行审计事实记录；仓库脚本与产品没有写死该路径，也不会自动联网安装。

原生 argv 使用 `-I -B -X utf8 -c` 运行随 Rust 二进制嵌入的可信 adapter。可读源码曾实际触发 Windows `WinError206`；现提交标准库 zlib 压缩 payload，由 [build_pdf_sidecar.py](../../scripts/build_pdf_sidecar.py) 核对解压结果与源码逐字节一致，不写临时 driver。最终 [字节绑定检查](assets/B03-T02-payload-check.log) 退出0：源码31,814字节、payload 8,926字节。

## 真实样例与独立位置预期

[14份输入及定义](../../fixtures/pdf-text-v1/README.md) 全部自造，不含私人资料。generator 只使用作者绘制操作、固定 Helvetica 字体指标和 authoring 库，不导入待测 parser；原始 SHA、真实页数、字符序号、正文、顺序和 geometry 先于对应实现/审查修复冻结。`layout-order.pdf` 特意先绘制 Second 再 First：字符 ordinal 保留 drawing 顺序，正文使用视觉顺序。曾错误混用两者的预期已按原始操作符修正，未改变 PDF 字节。

初始19页审查指出旋转/review页缺少独立字符位置 oracle；随后加入 CropBox 偏移90/180/270与 UserUnit2，形成23页。首次整项审查又复现错开双栏与纯空格页误报 parsed，因此只在 columns/blank 各添加第二页，形成最终25个可渲染页；另12份 raw 逐字节不变。旧 [23页预期](assets/B03-T02-initial-expected.json)、[视觉记录](assets/B03-T02-initial-authoring-review.json)、[支持事实](assets/B03-T02-support-matrix-initial.json) 和变动前 [columns](assets/B03-T02-initial-columns-page.pdf)/[blank](assets/B03-T02-initial-blank-page.pdf) 均保留，不能用新结果抹去旧缺口。

Poppler `pdfinfo`/`pdftoppm` 实际完成25页渲染，每个 PNG 存在且退出0，见 [完整记录](assets/B03-T02-authoring-review.json)、[contact](assets/B03-T02-authoring-contact.png)、[普通单页](assets/B03-T02-authoring-single.png)、[CropBox](assets/B03-T02-authoring-crop.png)、[旋转 CropBox](assets/B03-T02-authoring-rotated-crop.png)、[错开两栏](assets/B03-T02-authoring-staggered-columns.png) 与 [纯空格页](assets/B03-T02-authoring-whitespace-only.png)。独立子代理审阅原始操作符、字符清单、矩阵、字体布局框和图片，结论见 [审查记录](B03-T02-REVIEW.md)。这不是人工科学金标准。

最终 [独立 CLI 验证器](../../scripts/verify_pdf_parse.py) 不调用 adapter/Core 校验函数，不用待测输出生成 expected，实际执行14次 parse、14次 inspect、1次 version，共29次普通 CLI。核对全部14个原始 SHA、24个已确认物理页、1,025个作者字形及其位置、15行完整字面正文/顺序/UTF8片段；每个资源实际 SHA/长度、JSON/Markdown同事实、精确目录清单、原输入/外部哨兵及 inspect 前后文件字节/mtime全部通过，见 [命令输出](assets/B03-T02-independent-cli.log) 和 [逐文件事实](assets/B03-T02-support-matrix.json)。加密文件作者知道有一页且可用 authoring 口令渲染，但本 parser 没有确认页总数，因此 manifest 的24页不含它，未伪造一页成功清单。

| 最终支持范围 | 文件数 | 确认物理页 | 实际结论 |
| --- | --- | --- | --- |
| 单页/三页单栏、偏移CropBox、绘制顺序 | 4 | 6 | 整份 parsed，退出0 |
| 旋转、扫描、空白/纯空格、表格、公式、图片、双栏 | 7 | 16 | 整份 needs_review，退出3；保留页/字符/原始视觉证据 |
| 损坏、加密、部分页损坏 | 3 | 2 | 整份 failed，退出3；前两项总页数未知，后一项保留两页及单页失败 |

跨所有文件实际页面状态为8 parsed / 15 needs_review / 1 failed；文件状态为4 parsed / 7 needs_review / 3 failed。逐文件时间、页数与错误见 [支持矩阵](assets/B03-T02-support-matrix.md)。扫描/空白的0字节文本 artifact 是真实资源：wire 单元 `text=null`，不是 `[0,0)` 假正文。纯空格保留实际三个空格和 LF，仍需复核。表格、图片、公式、分栏和旋转的字符串存在不等于结构或阅读顺序已支持。

## 页、区域、正文和只读重查

[PDF契约](../technical/PDF_PARSE_CONTRACT.md) 与 `pdf_model.rs` 固定完整物理页索引 `[0,page_count)`、显示页为索引+1、未知 printed_page_label=null。geometry 保留原始 MediaBox/CropBox、UserUnit、Rotate及到显示 CropBox 左上原点/Y向下 pt 的矩阵。Core 验证有限页内坐标、逐字符包络、每字符恰分配一次、规范行/阅读顺序、全文字节与区域范围；不能以任意页内 bbox 或 PDF raw offset 代替真实区域。

单页实测 raw SHA 为 `1a8bbfe535892b74e2ec1e0fdb6f99320d98e3492441f5f8ae339a57644fc457`，正文147字节、SHA为 `ba2f6db48aa0f2a485453db4bed9dd4d54e728a3486171f54f17d14f0266f1eb`。第一行是 `Noetome PDF fixture - physical page one`，区域片段 `[0,39)` 排除随后LF；其页为 index0/display1/label null，显示大小600×800pt，布局 bbox 约为 `[72,62.484,291.42,74.484]`。这段字节范围只绑定 `page-text-000000`，与二进制 PDF 或旧 `blocks-v1` 无关。

Rust `pdf_parse.rs` 复用已验收 sidecar 生命周期；`pdf_workspace.rs` 独占创建外层根、报告 create_new/重读，`pdf_validate.rs` 进行 PDF 语义复核。inspect 不启动 parser，从保存的 raw、manifest、全部资源及报告重新计算，原文件移动/删除后仍可核对。目标存在、未知内容、链接/junction、文件占用、原始或目录身份替换、资源/报告冲突拒绝接管。宿主/Core故障的 `failure.json` 保守保留未知原始 SHA/页数和诊断，parser残留不算已验收；不自动删除现场。

## 时间与输出资源实测、未验收项

14次parse的完整CLI墙钟时间为195.838–253.874ms，已验证 raw/text/manifest 总资源920–99,807字节；逐份实际数字保存在支持矩阵JSON。它包含原生进程启动、Python、Core及最终报告写入；报告的 elapsed_ms 只测原始准备+child+初次Core验证，两者不能混用。只有一次本机小样例运行，不宣称吞吐统计、内存或CPU峰值。

测量时普通debug CLI SHA为 `65f1988f2a381897e21431873d14e9ab3f72bc9240e4bf8865c069795d5da579`，9,226,752字节，时间/版本亦在JSON。后续workspace feature统一构建/复审的debug SHA为 `d0cb8b88d01a36b3f5da8b7efb7b3835f88374ac02859bcabfebcc5e6e045fcb`；两次均绑定同一冻结源码/payload，不把前次测量冒充后次二进制的测量。

一般PDF内容完整性仍不能只凭parser字符清单证明；这里的独立authoring位置和完整正文验收只涵盖所列小样例。字体bbox是布局/advance包络，不是墨迹紧框；空格标注没有可见墨迹；多码点ToUnicode字体bbox未经独立验收，因此保留needs_review。相邻行的分栏规则只识别保守候选，不是完整版面算法。[UserUnit图](assets/B03-T02-authoring-user-unit.png) 核对了规范化位置，但独立renderer的物理比例未验收。

未运行：内存/CPU采样、1000页吞吐、24小时稳定性、跨平台兼容、科学人工金标准、OCR、模型/知识召回或科学准确率；本环境无pdftotext，未宣称该工具比对通过。扫描、复杂结构、任意编码字体与一般版面不能因小样例通过而列为可靠支持。
