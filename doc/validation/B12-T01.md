# B12-T01 教材式自适应规划：概念关系、教学顺序与规划位置——验证记录

状态：Linux 上实现并端到端跑通，教学顺序、笔记与文件夹规划、多重归属只留一个主要位置、反应链拆分理由与逐原子规划位置均已在冻结 fixture 与真实 CLI 输出上实际运行。**Windows 原生门禁未运行**（本机 rustup 未安装 `x86_64-pc-windows-msvc`，也没有 NSIS），因此安装包形态下的行为仍未验证。

## 1 范围与先验作者

本任务对应 FR-15（教材式自适应规划，P0）与 FR-07（概念关系与多重归属）：根据概念关系、主题内聚性、教学顺序与阅读目的规划知识点、笔记与文件夹；知识图谱允许多重归属，但文件树只选一个主要位置，其余联系用链接表达；连续反应不得无理由拆成大量单句文件；每个必要原子都要有规划位置。

`fixtures/adaptive-plan-v1/` 全部内容自造，不含真实教材原文，也不含任何笔记正文：

- `project.json`：case `plan-metabolism-v1`，`folder_root` 为 `代谢`；2 个主题、6 个阅读目标、4 个概念、4 条概念关系、1 条反应链、8 个必要原子。
- `expected.json`：**在实现验证之前手写**，逐条给出 10 项计数、2 个文件夹、6 份笔记、8 个原子的规划位置、教学顺序、1 条 `goal_without_atoms` 提醒与四条拒绝先验。
- 四个变体：`project-cycle.json`（前置关系成环）、`project-split.json`（删掉拆分理由）、`project-unplaced.json`（完整解释不在主目标）、`project-argument.json`（跨主题搬原子），各自只违反一条规则。
- `cases.json`、`README.md`（8 成员表与先验推导）、`frozen-sha256.json`。

先验怎么算出来的：前置边是 glycolysis→pfk、glycolysis→gluconeogenesis、pyruvate→gluconeogenesis，入度为 0 的只有糖酵解，随后磷酸果糖激酶与丙酮酸同时就绪、按声明序取前者，最后糖异生，于是教学顺序为 `糖酵解 → 磷酸果糖激酶 → 丙酮酸 → 糖异生`；2 个主题 × 3 个目标 = 6 份笔记、2 个文件夹；8 个原子都声明了目标，其中 3 个落在非主目标，因此产生 3 处跨笔记引用；反应链 `chain-glycolysis` 的 3 个步骤横跨两份笔记并声明了 `chain_too_long`，所以拆分计数为 1。

## 3 关键取舍

1. **同层就绪的概念按声明顺序取**，不按字母序，也不依赖哈希迭代顺序。教学顺序必须能被人工复述，否则"先学什么"就成了实现细节。
2. **每个概念只能属于一个主题**。多重归属在知识图谱里成立，但文件树需要唯一的主要位置；跨主题搬原子直接以 `PLAN_ARGUMENT` 拒绝，其余联系用链接表达。
3. **每个概念至少有一个原子落在其主题的主阅读目标里**，否则 `PLAN_UNPLACED`。位置存在不够，位置必须就是说清楚这个概念的那一份笔记。
4. **连续反应链被拆到多份笔记时必须给出可检查的理由**（`chain_too_long`、`topic_boundary`、`user_lock`），否则 `PLAN_CHAIN_SPLIT`。没有理由就把反应拆成单句文件，正是 FR-15 明确禁止的退化形态。
5. **空目标允许存在但必须可见**：没有原子的目标仍生成笔记，并产生一条 `goal_without_atoms` 提醒，不静默丢掉阅读目标。
6. **`plan.json` 的原子按阅读顺序输出**（笔记顺序、笔记内位置），而不是声明顺序或目标 id 的字母序——否则文件读起来与规划本身不一致。
7. **输出清单不含 `created_at`**，同一冻结输入的两次构建字节相同；`adopt` 先完整预演一次规划再建根，失败不留半个根。

## 6 实现中发现并修掉的缺陷

1. **`adopt` 摘要把一份笔记标题当成教学顺序**：原实现打印 `planner.plan_file.notes.first().title`，实测输出 `教学顺序：糖酵解：反应与调控`。改为 `PlanFile.teaching_order`（`OrderRecord`）并由 `order_text()` 统一渲染，`status` 也新增了教学顺序行。
2. **`plan.json` 的原子按目标 id 字母序输出**，与笔记阅读顺序不一致；改为按 `(note_index, position)` 排序。
3. **`report.md` 的提醒只写 `subject：detail`**，看不出是哪类提醒；改为 `- {kind}（{subject}）：{detail}`，并补 `## 教学顺序` 一节。
4. **审计器 `check_output` 在输出缺 `report.md` 时抛 `FileNotFoundError`**：改为先判存在性、记 `output-present:<文件>` 与 `output-complete` 后短路返回，`plan.json`/`report.json` 的 `strict_load` 也改为捕获 `ValueError`。
5. **上一任务末尾的手改没有再过 rustfmt**：`audit_model.rs`、`audit_store.rs`、`tests/audit.rs` 在本轮 `cargo fmt --all --check` 下报差异，已一并格式化（仅格式，无语义改动），`lib.rs` 的 `mod` 声明也因此按 rustfmt 的模块顺序归位。
