## 1 范围与先验作者

`fixtures/diagnostics-export-v1/`（10 成员，`--freeze` 后 9 个写入 `frozen-sha256.json`）由本任务自造，
不含任何真实用户的日志、来源正文或凭据。

- `project.json`：`case_id = diag-traceability-v1`，三个范围类别——`journal-events`（审计事件，
  2 条，120 + 180 字节）、`run-logs`（运行日志，1 条，400 字节）、`source-body`（来源正文，
  **敏感**，1 条，9000 字节）；`selection` 只勾前两个；`consent.sensitive_approved = false`；
  复现信息 3 项配置 + 3 个输入指纹；`limits` 8/64/240。
- 五个变体各只破一条规则：`project-consent.json`（勾选敏感类别）、`project-absolute.json`
  （预览里粘一句带 `/home/lyinn/...` 的句子）、`project-secret.json`（预览含 `password=hunter2`）、
  `project-unknown.json`（勾选不存在的类别）、`project-empty.json`（`run-logs` 清空）。
- `expected.json` 是**实现验证之前手写**的判据，不是从产品输出回填：13 项 counts
  （categories 3 / selected 2 / excluded 1 / sensitive 1 / sensitive_included 0 / entries 4 /
  selected_entries 3 / exported_bytes 700 / excluded_bytes 9000 / config 3 / fingerprints 3 /
  model 0 / network 0）、三条类别记录、三条条目记录、五条拒绝、确定性与边界。
  700 = 120 + 180 + 400，9000 = 被排除的来源正文——两个数字都是声明的字节直接相加。

## 3 关键取舍

1. **同意检查前置**：命中敏感类别而 `consent.sensitive_approved == false` 时，在算任何计数之前
   返回 `DIAGNOSTICS_CONSENT`。导出包会被分享出去，同意必须在导出之前落定，不是事后提醒。
2. **未导出类别保留真实字节**：`included=false` 时 `selected_entries=0`、`exported_bytes=0`，
   但 `bytes` 仍写真实值并计入 `excluded_bytes`。把未导出写成 0 字节等于谎报包的大小。
3. **绝对路径逐 token 判**：只判「整串以 `/` 开头」会漏掉粘在句子中间的路径（实测该变体
   第一版确实漏检）。扫描器看每个 `/`、`\` 是否起一个 token，另认 `X:/`、`X:\` 盘符形态。
4. **拒绝时不写字节**：绝对路径与凭据都在 `validate()` 内、建根之前触发，五个变体实测 `left=0`。
5. **空类别拒绝**：空类别会让预览看起来比实际更完整，读者以为这一类内容也在包里。
6. **输出清单不含时间戳**：`control/manifest.json` 有 `created_at`（冻结那一刻值得记录），
   输出 `manifest.json` 没有——派生包不该带运行时间，否则两次构建无法字节相同。
7. **身份不含文件长度**：沿用 B14-T01 的 `compile_identity::Identity`；把长度编进身份会让
   写清单本身改变清单刚捕获的值。

## 6 实现过程中修掉的缺陷

1. `adopt_summary` 首行文案从 journal 复制过来时没改，写着「审计事件日志」——真实产品文案错误。
2. `absolute_forms` 只判字符串开头，句中路径漏检——`project-absolute` 变体第一版 adopt 成功。
3. `resolve` 用 `split('/')` + `join("/")` 丢掉绝对路径的前导空段，把 `/home/...` 变成相对路径，
   `adopt` 直接读不到声明（`DIAGNOSTICS_INTEGRITY：无法读取诊断声明 home/lyinn/...`）。
   改为遍历 `path.components()`，与 `journal_store.rs` 同构。
4. `diagnostics_store.rs` 里 12 处「审计根」全部改成「诊断根」（复制源代码时留下的用词）。
5. `adopt` 里 `root_identity` 先取出再传入 `adopt_into`，被借用报 E0382——传 `clone()`。
6. `adopt_into` 内多余的 `fs::create_dir`：根由 `adopt` 建并取身份，重复建会报已存在。
7. 测试侧：`status_and_list_report_the_same_export_without_writing` 里
   `let text = text(&status)` 遮蔽同名 helper 导致 E0618；三处断言文案与实际措辞不一致。
8. 审计器侧：`build_output` 读 `root/control/inputs.json` 让只建输出的用例全部 `FileNotFoundError`
   → 抽出 `inputs_payload()`；四个只审输出的用例必须传 `package` 才能拿到重放值；
   `cases.json` 缺 `expect` 块导致五个变体都报「期望 None」→ 补齐并与 `expected.json.rejections` 交叉核对。
