# B01-T03 桌面构建与安装验证记录

日期：2026年11月1日（Asia/Shanghai）。用户明确要求提前搭建桌面应用，使用选定图标、忽略 sample，并本地安装后测试。当前结论：构建和代码回归通过，自动安装和原生窗口验收受阻，任务尚未完成。

## 已实现产物

- `apps/desktop`：React TypeScript 工作台、运行检查和关于页面，使用本地图标，无外部字体或服务。初始无项目、无运行结果，未实现能力明确显示。
- `crates/noetome-desktop`：Tauri Windows 程序及当前用户 NSIS 安装配置。桌面入口直接复用 `noetome_cli::render`，只提供帮助、版本及运行信息，不执行任意 shell，不启用文件、网络或进程插件。
- `scripts/generate_app_icons.py`：将用户选定的正方形图片派生为 RGBA PNG 和多尺寸 ICO，保留构图。原始 sample 目录被忽略，生产资源及指纹清单提交，普通构建不依赖 sample 或 Python。
- `scripts/install_desktop.ps1`：当前用户静默安装入口，并校验安装后的程序存在及其指纹。安装未满足后置条件时明确报错，不把安装器退出码 0 当作成功。

## 本地安装与原生窗口阻塞

第一次通过 `scripts/install_desktop.ps1` 执行 NSIS `/S /D=<LOCALAPPDATA>/Programs/Noetome`，安装器退出码 0，但安装后程序不存在，脚本正确报告失败。指定仓库临时目录、重定向句柄及工具临时目录的诊断尝试仍失败（退出码 2），没有安装文件、快捷方式或卸载登记可核对。

实际读取的 NSIS 错误窗口为：`Error writing temporary file. Make sure your temp folder is valid.`。普通文件写入、精确 GetTempFileNameW 和带读写及 DELETE_ON_CLOSE 的 CreateFileW 探针在所选仓库测试目录成功；这些探针没有解释安装器进程为何失败，不能据此宣布问题已解决。

Windows 自动化工具的截图或启动/输入尝试还分别返回 `CreateForMonitor 0x80070057`、`GetCursorPos 0x80070005（拒绝访问）`，重新连接后仍不可操作。通过命令工具启动构建后的桌面程序退出 101，捕获到 Tauri `Failed to setup app: 拒绝访问。(os error 5)`。尚未确定该问题在普通用户桌面是否复现。未更改系统 ACL、安全设置或安装 WebView2 来绕开问题。

已请用户保持 Windows 桌面解锁，并在普通桌面手动运行生成的安装器，反馈安装和启动结果。该反馈和实际安装后验收仍待完成。
