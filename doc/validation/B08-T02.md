关键实现取舍：

- **预留即计入、用完不回收**：每次调度按最坏情况预留 `1` 次查询 + `max_query_bytes` + `max_query_millis`，
  **先写盘再扫描**。结算不改已用额度，因此接近上限时后到的调度必然被拒，不可能出现各方都拿到
  全部剩余额度。审计器把"已用 = 预留之和"作为独立检查项（`budget-reservation-shape`）。
- **中断只补结算，不重复计费**：如果账本里存在 `reserved` 的尝试，`step`/`run` 会先补结算那一条
  而不是新开一次预留；补结算成功后账本里不会有第二条针对同一查询的已结算尝试
  （审计检查 `ledger-no-double-settle`）。
- **终止理由必须有账本证据**：`finish` 先跑 `reason_supported`，缺证据即 `RETRIEVAL_REASON_UNSUPPORTED`
  （exit 3）并且不写盘。注释含义直接写在错误消息里（例如"糖异生绕行反应、糖酵解净能量收支 尚无已结算证据"）。
- **终止只写一次**：`termination` 表 `singleton CHECK(singleton = 1)`，重复记录即
  `RETRIEVAL_ARGUMENT`（exit 2），且不修改字节。
- **越界查询在 adopt 阶段就被拒**：`scope_class` 只允许 `authorized_target` 与 `required_prerequisite`；
  `goal_subjects` 里每个主题都必须对应某条已授权查询，否则拒收。根目录根本不会被创建。
- **命中键与机器可读输出**：命中键是 `"{文档}#{词项}@{UTF-8 字节偏移}"`，`run` 的 `records` 是结构化
  数组（`query_id`/`outcome`/`hits`/`new_hits`），人类可读句子单独放在 `notes`。这样审计可以逐条比对
  而不用解析中文。

### 5. 暂停、恢复与中断恢复

`crates/noetome-cli/tests/retrieval.rs` 的
`pause_blocks_scheduling_and_resume_restores_it` 与
`interrupted_reservation_is_settled_once_without_double_spending` 覆盖：

- 暂停后 `step` 返回 `RETRIEVAL_PAUSED`（exit 3），账本字节不变；`resume` 后继续调度。

  且不会出现同一查询被结算两次。
