## 3 关键取舍

1. **提案字段是锁的意义所在**：`proposed_path` / `proposed_sections` 缺省时一律视为"保持原样"，所以任何锁都不会触发；先写锁不写提案，测试就永远绿，等于没测。
2. **冲突转候选而不是报错**：锁定被撞时笔记保持原结构，候选逐条记录锁 id 与理由；只有重构会破坏锁定结构时才硬拒。
3. **影响范围双向判定**：既查漏报（引用被触动概念却没声明），也查多报（声明了却既不共享概念也不同主题）。
4. **重构先校验再记账**：拆分必须完整划分原子，空壳目标、重复分配、原子落到目标之外都拒绝；引用变化为空也拒绝。
5. **指纹来自声明**：本阶段没有真实正文，`unchanged` 只证明"没有被本规划触动"，报告里如实写明。
6. **有缺口仍写完整报告**：报告先落盘，再把退出码置 3；缺口被藏进拒绝里就永远不会被逐条看见。

## 6 实现中修掉的缺陷

1. `fs::canonicalize(root)` 在根尚不存在时必然失败 → adopt / build 改为先 canonicalize 父目录再 `join(file_name)`。
2. `build` 在 findings 非空时仍返回摘要（exit 0）→ 改为返回 `CHANGE_FINDINGS` exit 3。
3. `under(note.path, path)` 传 `String` 给 `&str` 参数 → 改 `&note.path`。
4. `open` 缺少身份校验 → 补 root / parent / control / manifest / inputs 五处，清单从 8 字段扩到 13 字段。
5. 重构没有和锁比对 → 补 `file` / `directory` / `canonical` 三类锁的拒绝分支。
6. 集成测试 `tree()` 把绝对路径当键，两个不同输出根永远不等 → 改为相对路径。
7. 审计器 `refactor["atoms"]` 对 `move` 变体是缺失键 → 改 `get(..., [])`。
8. 手动改代码后 `cargo fmt --all --check` 失败 → 跑 `cargo fmt --all` 修正并复验。
