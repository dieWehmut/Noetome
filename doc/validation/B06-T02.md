[真实 CLI RED 原件](assets/B06-T02/cli-red/)记录产品实现前的普通项目创建、来源导入和两条新命令失败。实际 SQL/资源与选定文本一致；旧 CLI 对 `knowledge process-review`、`knowledge flow` 均返回2和 `CLI_INVALID_ARGUMENT`，没有创建对应输出根。归档脚本第一次错误地要求统一参数错误文字包含动词，导致脚本断言失败；真实命令回执已保留，修正归档断言后没有重写 RED 历史或伪造 IR。

实现见[过程流程契约](../technical/PROCESS_FLOW_CONTRACT.md)。来源解析器完整消费实际 SourceSession 选定文字，随后与独立 gold 精确比较；步骤/关系/证据按 ID 规范化，保留各字段原词面。来源忠实性与图模型支持分开：相关/循环可通过来源核对，但当前有向流程模型会阻断。未解析语句保留真实已识别/未处理分母，无成功过程 IR。

`knowledge flow` 持有并重建保存 review 的完整清单和原字节，再选择流程图或有据文字。两份固定中文笔记保存过程说明、步骤输入输出/条件/例外、关系含义和普通导航链接。图中节点/边为生成的 ASCII 身份，方向、分支判据和正负作用均来自实际关系；每个图元素和必要正文均有字节范围到证据的映射。最终重新读取保存笔记，独立解析有限 Mermaid/Markdown 后检查实际结构与映射。

## 实际渲染能力与保真边界

[能力探针](assets/B06-T02/capability-probe/README.md)使用新测试 Vault、独立配置和实际安装的 Obsidian1.6.7；同安装包 Mermaid10.6.1，成员 SHA-256 为 `662f8b68d21daac0e9bc0d0b7adc78e2c556e69e70881edccb81a5cf384eee64`。顺序、菱形分支和正负边标签可见，默认 HTML 标签配合十进制 ASCII 标点编码保留已测单行字符，两个普通中文链接实际点击成功。`htmlLabels=false`显示实体文字；无效语法没有成功 SVG。

[空白补充实测](assets/B06-T02/capability-probe/whitespace/README.md)发现首尾 ASCII 空格被裁剪，中间连续空格视觉折叠，U+2028/U+2029丢失行/段分隔含义。NBSP单行码点保留不证明所有不换行语义。产品因此保守地将首尾/连续 ASCII 空格和其他空白标签/判据回退为预格式文字；单个内部 ASCII 空格仍可画图。正文内容保持原字符，不能据 DOM 中字符存在宣称视觉保真。

以上探针是技术能力调查，**不替代最终产品 CLI 生成笔记的 Obsidian 验收**。最终产品图、正文导航、文字回退、来源字节联结和配置清理会另行记录。

## 失败与修正记录

1. 初次编译发现旧公共 Fingerprint 类型没有 PartialEq，新增按 SHA 和 byte_length 比较的 trait 实现；不改变 wire 字段或旧契约。
2. 首轮 flow 把尚不存在的新输出根传给需要既有目录身份的 helper，普通 CLI 和运行期测试实际失败。修正为对已检查组件的绝对路径做包含判断，继续由 OutputRoot 保证新根；16作者链及后续运行期测试重跑通过。独立复查也识别了该缺陷，其实际调用发生在修正后，只能作为 GREEN。
3. 第一次 Rust 过滤 `process_` 同时选中了旧 PDF/进程宿主用例；Linux宿主用例失败不算本项通过，也不替代 Windows full gate。之后用明确的 `process_flow` 和 `process_parser` 范围检查新代码。
4. 第一轮完整 Python 与 Cargo 重建并行时，旧独立协调测试检测到运行中的 CLI SHA 改变并拒绝。这是验证调度失误；保留失败日志，后续 Python 使用固定字节的独立 CLI 副本，并在原生固定源码门槛顺序运行。
5. [核对器交叉复查](assets/B06-T02/independent/checker-review.md)实证两处独立校验缺口：失败报告的对象定位/原因仅做弱格式检查，改成无关步骤并同步两报告仍通过；以及旧来源 helper 直接读取 SQL 提供的项目外绝对资源路径，同字节副本可被核对器接受，而 Rust 实际入口拒绝 `SOURCE_INVALID_RECORD`。保留原始假通过后，本项加强了独立诊断推导、固定资源路径、raw→规范文本及真实 blocks-v1 范围核对。修复后的28项针对测试通过，同输入伪造由新核对器拒绝、正例仍通过；额外 raw/cache 同步伪造及 SQL 截掉否定尾句也由新核对器和 Rust 拒绝。普通 CLI 新导入带标题/空白前缀的过程，并选择 ordinal2 的完整正链通过。不改变旧产品的来源保护门槛；最终原生门槛使用修复后的核对器。

[独立产品复查](assets/B06-T02/independent/review.md)覆盖新模块、CLI及共享保护改动，没有发现修正后的新增实质问题；记录所审文件指纹和未验证范围。核对器本身另须交叉审查，不能由编写者自证独立。
