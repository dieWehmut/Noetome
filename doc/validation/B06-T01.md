# B06-T01 有据主动比较表验证

本任务从实际来源核对和成功协调结果生成新测试 Vault 预览。工程作者样例为公开自造输入；`knowledge=pending`、`scientific_quality=not_run`、`published=false`，不能推导科学正确率、任意自然语言规划能力或生产 Vault 发布通过。任务状态以账本为准。

## 实现与独立依据

普通入口为 `noetome knowledge present <project> <coordination-case> <coordination-output> <new-Vault>`。严格重验 v1/v2/v3 的来源、SQL/资源、九件核对依据、协调 IR 和双报告；成功时主动选择比较表或正文。多个对象共享显式属性才生表，未知格显示“选定事实未给出”；完整值、单位、条件、例外、适用状态、有据时间和全部原出现保留。逐段/逐格正文和链接分别保存 UTF-8 半开范围。

实现见[主动表达契约](../technical/ACTIVE_PRESENTATION_CONTRACT.md)。`257bde9` 保存独立核对脚本和标准；`2eacb00` 保存实现、CLI、运行期守卫及回归。原作者与普通 CLI RED 早于实现提交 `345129b`，三组冻结包共 14 个场景（12 个成功表达、2 个合法未决），另有审查后新增的多行显示名回归。

独立 Python 先从作者、真实来源和旧协调核对重建事实，再重建完整计划并读取真实 Markdown。最终 Linux 审计 39 场景、125 次普通 CLI：14 个作者闭环、22 个同步篡改、3 个路径拒绝。同步修改计划、Markdown、映射、双报告及指纹后，删单位/条件/例外/时间、错行、错属性列、表头依据串换、填零、丢出处及假成功仍拒绝。[审查与原件](assets/B06-T01/independent/review.md)记录范围、源码指纹和两轮真实结果；原始报告与输出在相邻归档中。

## 失败与修复历史

- [原始 CLI RED](assets/B06-T01/README.md)：`knowledge present` 尚未接线时返回 2，来源核对和协调原件保留；未用手写 NotePlan 替代主动规划。首次渲染单测使用私有错误字段导致编译失败，修正后 5 项通过。
- 捕获的计划被其他写者更改时，原清理顺序提前返回，留下未改变的成功双报告。修复为优先清理已捕获报告，并逐件尝试其余捕获结果；更改文件和未知人工文件保留。真实 RED/GREEN 见[开发原流](assets/B06-T01/development-runs/capture.json)。
- 第一轮扩展集成测试发现合法跨事实对象/属性角色复用被合并唯一性校验误拒，以及不同对象详情的小节 ID 必须按笔记限定；修复后 9 项集成测试通过，旧版本完整依据保持。
- [独立审查](assets/B06-T01/review.json)发现合法显示名含换行/Tab 时，协调成功但表达报 `PRESENT_RENDER_PLAN`。移除标题对有限明文的重复限制，保留原转义和固定详情链接。[RED](assets/B06-T01/multiline-label-red/capture.json)与[GREEN](assets/B06-T01/multiline-label-green/receipt.json)保存同输入普通 CLI 结果、新增回归及渲染测试。
- 固定快照前，首次格式检查检出新增回归断行；先提交校验脚本后立即尝试快照，因实现尚未提交被准入检查拒绝，未创建不完整 repo。执行格式修正并提交实现后，快照逐件核对 1,532 个 Git blob 字节匹配。
- 修复后的第二位审查者发现 Python v1/v2/v3 协调校验及表达 expected 校验仍误拒合法多行显示名。新增精确的显示字段有限明文检查，仅对 `concepts[index].display_name` 允许换行/Tab；ID、路径、其他字段的限制保持。三版本实际 CLI 及完整独立核对先得 3 项 RED，修复后 6 项测试通过，覆盖控制字符、隐藏内容、链接、HTML 和数值邮箱自动链接拒绝。
- 首轮 Windows workspace 623 项全部通过，但完整 Python 出现 15 个失败：验收脚本把 TEMP 指向源码仓库内，合成凭据测试被产品“凭据不可放仓库”的既有规则正确拒绝。只修正验收环境为源码快照外的自有临时目录，16 项原生凭据测试通过；没有修改凭据保护或使用真实密钥。完整最终回归另跑。
