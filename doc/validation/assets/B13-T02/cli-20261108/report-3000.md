# 大库规模实测（bench-library-v1）

语料是**合成的**：笔记由参数生成，人工改动也是生成的。它证明这个规模上的结构与分页能算出来，不证明真实笔记库的语言质量，也不证明界面不会冻结。

## 参数

- 笔记数 3000、人工改动 200、样本数 10、预热 2
- 分页大小 100 条/页

## 语料与阶段

- 主题 300、概念 5729、文本片段 30800
- 检测到改动 200 处，落在 2 页变更清单里
- 影响范围 1830 篇（与改动笔记共享概念或主题的笔记）

## 测量协议

- 每个阶段重复 10 次，前 2 次作为预热丢弃
- 不含进程启动、参数解析与语料生成：计时只包住阶段本身
- 分位数用 nearest_rank 的 P95：样本排序后取第 ceil(P/100×n) 个
- 阶段定义：scan 逐篇跑文本分析并取摘要；detect 与冻结基线比摘要；plan 汇总共享概念与主题的笔记；page 渲染变更清单第一页

## 门槛与判定规则

- NFR-12 门槛 2000 ms，逐个阶段比较 P95 与门槛；判定结果写在 timings.json，不写进本文件
- 本文件不含本次运行的任何耗时读数：一旦写进来，同一参数两次运行就不再相同；上面那个门槛是常量，不是读数

## 覆盖范围与未达标项

- NFR-11（partially_measured）：合成库确实建到 3000 篇笔记、200 处人工改动，扫描、检测、影响规划与分页都在这个规模上真实跑过；但「不因全量渲染冻结界面」属于 GUI 行为，本 harness 没有界面，只证明数据结构与分页产物能算出来、算得快。
- NFR-12（partially_measured）：本轮只测 scan/detect/plan/page 四个阶段在 2 秒门槛下的 P95；项目页、暂停命令、搜索与打开问题的端到端反馈没有界面可测，暂停语义属于 B13-T03。

## 边界

- 不联网、不调用模型、不写项目与 Vault；只写这一个输出根。
- 合成语料不代表真实笔记库；没有真实 PDF 抽取，也没有真实人工编辑。
- 没有界面，因此「不因全量渲染冻结界面」没有被验证。
