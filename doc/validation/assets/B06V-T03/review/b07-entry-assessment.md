# B06V-T03 收束时的 B07 进入评估草案

本文件属于当前兼容矩阵任务的只读验收分工，不创建、启动或完成B07任务，也不更改任务账本。评估依据是仓库现存实现和原件，不把路线表、运行状态字段或少量fixture等同于已实现可靠维护。正式切批次仍由主执行者在B06V-T03全部检查、独立终审、提交及远端核对后进行。

## 可进入的范围与尚待收束的门槛

建议在B06V-T03完整验收后进入**有界CLI可靠维护工程**：先对明确选取、已有确定性处理的有限工作单元实现检查点和恢复，再把已受限单请求适配接入持久化预算与有界重试，最后对明确托管的测试文件集合实现人工差异审批及可恢复安全发布。所有验收使用新的测试项目/Vault和人工构造外部编辑；人工保护通过前持续遵守D09，不接管生产Vault。

评估写入时，最低1.6.7的32个组合已有[完整原件独立审计](../minimum/audit-result.json)。主执行者报告当前稳定1.15.0的32个组合已完成，最终Pele/MathJax/SVG只批准真实测过的组合；完整Windows Rust、两平台Python、五视觉独立审计、最终源码绑定和终审仍在本任务收束流程中。本草案没有把尚未汇总的最终检查预先算作通过。如果最终发现影响正确性或数据安全的回归，先修复当前任务，再决定进入。

[路线表](../../../../execution/ROADMAP.md)对B07的进入条件是“已有闭环稳定，测试资产足够”，其正式200原子质量基准和个人版长任务门槛仍须另行实际验收。因此科学质量尚未达标不应伪装为已达标；它也不要求把可独立验证的检查点/人工保护工程无限延期。B07阶段的小任务完成只证明其明确工程边界，不能宣布个人可用版或生产发布就绪。

本评估草案形成时尚待收束的检查现已有实际结果：Windows Rust726/0/0、最终Windows Python441项434通过/7权限skip、Linux最终第四快照380项361通过/19平台skip，五视觉317CLI和强WindowsC当前30目标+15来源setup全部通过；原生64组合、原件/源码与文档范围证明均见[B06V-T03验收](../../../../validation/B06V-T03.md)。先前待完成描述保留为当时记录，正式切批次仍须完成日志、提交与远端核对。

## 已具备的工程基础

1. 来源身份、不可变内容版本与原字节指纹已有明确结构。文本/PDF来源保存快照、完整区域和真实失败，读取与复用会核对来源/解析版本和实际内容。已有SQLite状态、所有权标记及Windows读/写保护可供恢复契约复用；[数据契约](../../../../technical/DATA_CONTRACTS.md)同时明确现有残留拒绝，不实现原目录自动续写。
2. `fixture_compile.rs` 与 `compile_store.rs` 已有确定性暂存、逐阶段故障钩子、输出/链接重验、状态记录与 `recovery_required`。真实进程终止测试保留现场，而不是把中断标为published。该能力范围是新的fixture编译目录，不能推成用户运行任务的暂停/继续或生产Vault发布协议。
3. 文本API与扫描API已实行单请求预算预检、工程预留、原响应和严格用量核对；返回模型、失败、未知计量和科学状态分开。CLI帮助明确不自动重试，`max_requests=0`无请求。现有开发侧累计额度记录与人工脚本不是产品级并发预算账本，不能代替FR-35/36/38。
4. 有界知识协调、表格/流程、公式/图像/选定扫描输出保留来源与独立语义expected，始终区分pending、not_run和published=false。新增视觉能力已有最低与当前稳定版的实际显示原件，可以在维护过程中验证表达失效/再编译及附件/链接一致性。
5. 当前普通CLI命令尚无持久化 `run resume/pause/cancel`、多请求预算调度、三方差异审批、已有Vault接管或生产增量发布入口。公开help也明确“完整知识编译与生产Vault增量发布尚未实现”。下一批应建立这些缺口的最小合同，不把现有内部checkpoint函数或fixture的published标志包装成完成。

上述实现来源见[CLI入口](../../../../../crates/noetome-cli/src/lib.rs)、[fixture编译](../../../../../crates/noetome-cli/src/fixture_compile.rs)、[发布存储](../../../../../crates/noetome-cli/src/compile_store.rs)、[单请求文本API](../../../../../crates/noetome-cli/src/extraction_api.rs)和[扫描入口](../../../../../crates/noetome-cli/src/scan_formula.rs)。这次评估只读代码与已有验收，没有运行或新增B07代码。

## 建议最多三张独立验收卡

以下编号和接口名称仅为草案；正式任务卡由主执行者根据最终结果落账，后续卡不得在前置验收前启动。三卡均保留明确source/config/compiler/strategy版本、真实未运行项和独立作者预期，任务状态与发布状态分开，不扩大模型或资料范围。

### 草案 B07-T01：一个固定有限流程的持久检查点与恢复

依据FR-35、FR-40、NFR-08/NFR-13与AC-26。只选择一个已有明确输入、确定性输出的闭环作为最小流程，例如已冻结fixture的校验、暂存编译和独立结果核对；不同时接入全部知识命令或真实批量模型。显式版本化Run/WorkUnit契约，保存输入/依赖/策略/输出指纹、持久状态和检查点，提供只针对该明确流程的启动、状态、暂停、继续与取消控制。

验收必须实际在每个可提交边界强制终止进程，再从原检查点继续；已成功单元不重复计算，结果ID/文件/确认响应不重复。来源、配置或编译器指纹变化只使依赖单元失效，未知/损坏检查点明确拒绝并保留现场。暂停停止新单元调度、可安全落盘，取消保留已确认结果；运行结束仍分别报告质量和发布状态。正常与失败场景都要验证原输入/外部哨兵未变、恢复结果和从头确定性运行的完整输出一致。

产物建议为显式Run契约、一个普通CLI最小入口、冻结有限图、逐边界真实中断/恢复原件和独立校验器。与生产来源项目Schema/fixture compile状态的迁移关系必须明示，不能借修复自动接管旧不明残留。

### 草案 B07-T02：持久预算预留下的有界重试与隔离

依赖T01；依据FR-36/38、D08、AC-29/30。只接一个已授权适配器的既有单请求语义，以固定本地环回测试服务模拟429、5xx、超时、断连、结构错误及有效响应。测试使用人工凭据、实际模型与付费调用为0；服务/策略范围改变须显式记录，既有开发累计10M授权不重置为每个产品Run的新额度。

请求前持久预留预算，重试计入独立次数/Token/耗时上限并有明确退避；仅符合既定策略的故障可以重试。对超时或断连导致的远端完成未知，保持未知/在途状态，不释放全部承诺预算、不报告零计费。已确认同一响应在恢复/重复接收后只能结算一次；无效JSON不能污染知识或冒充已确认用量。至少两个并发单元的近限额测试证明不能各自领取全部剩余额度，到限停止新调度并保留未完成单元；坏单元不阻断不依赖它的工作。

产物建议为预算/attempt契约、严格恢复状态、真实环回HTTP时间/次数记录、并发近限额与重复结算故障原件、独立预算重建审计。当前未知价格继续为null；费用未知时仍可用次数和Token控制。真实网关重试验证如需要，另定明确小预算，不从离线成功推出真实网络可恢复。

### 草案 B07-T03：一个明确托管测试集合的人工差异审批与可恢复发布

依赖T01/T02；依据FR-29至34、NFR-07/08/14、AC-21/22/24/25/27/28。先限定一个显式托管笔记/附件/链接集合，保留上次发布基准、当前磁盘和新候选三方字节及影响清单；已有或来源不明编辑均按人工内容处理。只做CLI/机器可读差异与明确批准记录，不同时建设完整审批GUI、全库逆向接管或通用结构迁移。

普通自动模式下，可能影响人工含义、结构、链接、位置或附件的候选必须隔离，拒绝决定可追溯且重试不能重新自动应用；不依赖它的明确安全变更可继续。批准绑定当前磁盘指纹、候选/配置版本和完整影响清单，写入前再读，人工再次编辑使批准失效。发布先暂存并核对文件/资源/链接/索引，再用可恢复日志逐项落盘；成功标志仅在一致性确认后写入。对每个发布边界注入进程终止、文件占用和外部写入，恢复为可核对的一致版本或明确待恢复；回滚同样识别发布后的人工改动并需针对性批准。

产物建议为托管范围及基准/审批/发布合同、一个小型新测试Vault，包含人工修改、陌生文件/附件、Obsidian配置、删除/重命名和无关主题；前后逐文件核对未批准覆盖为0、无关内容字节不变、待审批依赖未提前移走、断链不显示成功。没有旧基准的Vault继续只读；这张卡通过之前不授权生产Vault写入。若实现范围超出单一可审查闭环，应在正式B07规划时进一步缩小托管集合，保留其余维护能力为阶段目标。
