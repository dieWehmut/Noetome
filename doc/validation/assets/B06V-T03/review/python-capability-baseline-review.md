# B06V-T03 独立 Python 能力门禁与显式目标接口基线

本记录仅覆盖当前任务内 Python 校验器重构及其实际回归，不登记尚未由本轮正式原生语义采集通过的当前稳定运行时。原 13 用例冻结包及 3 项流程补充包、四类旧作者包均只读，作者 expected、语义、原件和 SHA 不修改。

四个独立校验器调用 [visual_capability_registry.py](../../../../../scripts/visual_capability_registry.py)。登记范围暂时只有已有原生验收的 Obsidian 1.6.7 / MathJax 3.2.2、1.6.7 SVG，以及完整 Schema 1 的 Obsidian 1.6.7 / Mermaid 10.6.1 流程 profile。helper 不读取 Rust 实现、产品计划或报告，也不根据输出声明推断目标能力；它精确比较版本组合、流程 profile 身份、label codec 及必要布尔值。领域校验器的 schema 和语义判据保持独立。旧验收依据分别见 [公式](../../../B06-T03.md)、[图像](../../../B06V-T01.md)、[扫描](../../../B06V-T02.md)及[流程](../../../B06-T02.md)。

本次发现 formula/image 的原 `verify_output` 还强制 profile 等于旧作者冻结 profile，单纯新增 registry 条目不足以验证后续版本普通 CLI 产物。按根代理明确的兼容矩阵验收要求，增加可选 `target_profile` 参数及 `check --target-profile` CLI 入口：原位置参数仍必须等于作者基线；显式目标必须来自独立选定原件并与保存副本及报告输入一致。目标决定由冻结源语义与独立 registry 重新计算；默认调用仍使用旧作者 profile/expected 精确判据。未读取待审输出作为目标来源，也未重写作者 expected。scan/flow 原接口已经从显式输入 profile 独立分类，保持该行为。

实际新增检查覆盖未知目标、Obsidian/MathJax 交叉版本、流程引擎与 profile_id 混配、`verified`/支持标志不能批准目标、布尔与整数不能互换、原 SVG target/flag 双诊断保留，以及以下语义门槛：

- 公式原 TeX 负号变化先产生语义不符，不转为图像回退成功。
- 扫描负号与下标未知仍阻断；猜测完整 TeX 或改变识别负号/下标不会补齐未知。
- 图像未知关系、流程未知方向先阻断，兼容回退不能覆盖该结果。
- 显式未知目标的真实普通 CLI 回退产物可被独立核对；原默认 checker 拒绝替换作者 profile。
- 同步更改保存 profile、报告及全部普通 SHA 后的原生公式/SVG 能力伪造仍拒绝；显式已测目标仍拒绝同步丢失负号或箭头的可见内容。
