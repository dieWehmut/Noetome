# B15-T02：自己的 PDF 到待核验 Obsidian 笔记

用户在本轮明确选择「自己的 PDF → 模型整理 → Obsidian 笔记」，并确认安装目标为 Windows 11 x64。本记录保存该流程的实现和实际验证；任务状态以[账本](../../dev-log/tasks.json)为准。NSIS、完整内置依赖和安装版 UI 由 B15-T03 单独验收。

## 实现

桌面当前项目和工作流由 App 持有，切页保留，换项目清空旧资料/结果并拒绝迟到响应。父目录与新名称创建项目；资料页明确选择单份 PDF/MD/TXT，显示真实状态、Span 或物理页区域。手动批量选择最多64个非空可用单位、正文64KiB，完整原文预览并确认后才能调用模型；失败、空文本和不可确认扫描区域不能进入付费流程。

`confirmedUnits` 必须与当前持有的真实来源 binding/units 完全一致。SelectedSource 的只读文件身份保护贯穿子 CLI，临时配置、信号和 API 结果保存在项目外。固定服务/模型复用既有授权；凭据通过 Windows 遮蔽窗口保存 CurrentUser DPAPI，前端不接收 key。累计账本保留完整十条历史和33,185已用，缺失需明确确认恢复；零账本、历史改动、虚假计数和非法状态拒绝，未知用量保留预留。

`preview choices/units/export` 支持 CLI 和桌面恢复。导出零额外 HTTP，重验成功请求、实际正文与原始响应、候选、双报告、owner、文件指纹及当前来源，并重建整份请求正文比对。新根内 `vault/` 为概念/证据/总览和原件附件，`reports/` 保留审计；producer=extraction_preview、pending/unverified、required=false、published=false、scientific_quality=not_run。既有目录、生产 Vault 的 `.obsidian` 祖先、重叠与篡改拒绝。

Markdown、HTML、wiki、Obsidian隐藏注释、数学/删除线/高亮、围栏、列表及缩进都按字面转义；多行标题/别名显示 ↵/⇥，原始字段仍在审计。离线自检使用独立作者 fixture，不代替真实资料或模型验证。

桌面注册21条受限命令，runtime_info显示17项能力；没有新增通用 shell、文件或网络插件权限。Release 缺资源明确失败，不借编译仓库补资源。Windows 外层 Job 在根进程悬挂时分配、再恢复，并用独立 kill-on-close/census 守护取消和退出后的后代。固定可信 PowerShell helper 使用当前子进程级 ExecutionPolicy Bypass，不修改系统策略；[参数与来源摘要](assets/B15-T02/backend-summary.json)明确区分源码模板和实际调用。

## 实际发现与复验

1. 真正的作者来源和生产 CLI 证实 `%%`、未闭合围栏、数学/删除线/高亮及跨行别名能使笔记隐藏或吞掉内容。用同一份不变的保存 API 完成[RED](assets/B15-T02/core-preview-audit/red.result.json)→[GREEN](assets/B15-T02/core-preview-audit/green.result.json)，0额外HTTP；[链接检查](assets/B15-T02/core-preview-audit/green-links.result.json)确认生成目标真实存在。已知/未知值及完整条件、单位、quote、原件的[独立语义检查](assets/B15-T02/core-preview-audit/known-unknown-semantics.json)通过。
2. 独立负例把候选数值改为999，并同步候选摘要及JSON/Markdown，保留原HTTP响应；仍以 PREVIEW_INVALID_API 拒绝且不创建输出根。[原始结果](assets/B15-T02/core-preview-audit/repinned-candidate-negative.result.json)。
3. 原生所选 DeepSeek Chat 链生成候选成功后导出失败，发现实际HTTP正文把请求放在 `request` 包装中。最小修复读取真实位置，仍执行整个正文重建，不放宽保护。新增真实Chat测试完成唯一HTTP后关闭服务、两次恢复导出成功，Windows全部10和Linux新专项通过；原失败与修复后记录均保留。
4. 64段作者文本真实拆为127个Span，原错误测试预期已保留并修正为从真实列表选64个非空Span；不修改既有解析拆分。空白片段的可选状态同时按受保护真实正文修正。
5. 用量检查的清零、改旧历史、假次数和非法结算状态原本不足，改为完整冻结前缀及状态/算术/次数核对；实际原生反例通过。假CLI redaction标记和展示 producer 的两处测试错误期待也保留原日志再修正，没有改生产成功规则以迁就测试。
6. 首次证据提交的暂存区检查发现原始日志空白和CRLF转换，检查失败后仍提交属于收束操作错误。追加专用归档属性并重新暂存原件，保留失败提交，不修改日志正文来绕过检查；逐项核对最终Git对象与复制索引的SHA256。
