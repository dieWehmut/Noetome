## 已实现行为

```text
noetome source import <project-path> <selected-PDF> [--source-id <existing-id>] [--reparse]
noetome source inspect <project-path> <import-id>
```

调用者通过NOETOME_PDF_PYTHON指定锁定解释器。默认同字节或重命名可复用同Source/Version及已验证parsed/needs_review解析，每次仍创建新import_id；显式source_id只在该来源内复用。内容改变形成新版本，回到旧字节复用旧版本；--reparse每次形成新parse_id，failed尝试不会永久阻止重试。MD/TXT配合--reparse在写入前拒绝。

完整原始字节保存为`.noetome-sources/{version_id}/raw.pdf`；PDF Version为acquired，normalized及版本error为空，旧Span清单为空。解析失败保留原始版本和真实失败尝试；未完整获取只保留获取失败import，version/parse为空，不补造SHA、规范化文本、页或区域。正常结果保存现有B03-T02原始parser树和Core双报告；host失败单独保存diagnostic与固定名称的未确认残留。

PDF报告schema_version=2、report_kind=source_pdf_import，分别表达原始获取和解析状态，knowledge_status始终pending，仅统计实际区域及对应待抽取数。PDF仅parsed退出0，needs_review、failed或not_attempted退出3；只读inspect保留状态和退出码，从项目快照重新核对。原文件移动或删除仍可重查。原文本报告v1和文本inspect成功核对后退出0的规则保持。

[精确契约](../technical/PDF_SOURCE_CONTRACT.md)固定十表Schema3、nullable字段、统一导入rowid、页JSON、资源级别与快照布局。默认缓存键绑定原始SHA/长度、协议1、七项requested parser身份、adapter源码SHA、导入选项与缓存版本；重新解析使用fresh选项，旧页和原始证据保持独立。
