# B16-T02 桌面资料库与恢复操作验证

2026-11-13，工作区 `Noetome-mainline`，分支 `codex/b16-t02-pdf-corpus`。本记录分别描述桌面实现、编译、浏览器 UI mock，以及同源 Windows 开发程序的真实 Tauri/Core IPC 操作。真实整书页覆盖、OCR 对照和 Windows 全量回归由本任务其他记录分别验收；本次原生桌面没有运行安装器或整书知识编译。

## 已修复的实际界面问题

- 完整扫描本的全部物理页已登记时，核心状态可为 `needs_review`，但页面仍有 `needs_ocr` 内容。此前界面按 `processed_pages == page_count` 隐藏继续按钮，安装 OCR 后无法从界面开始识别。现在用核心返回的 `needs_ocr_pages` 单独展示待识别页数，并提供“继续扫描识别”；文字页、OCR 页与待复核页分别计数。
- 失败页有独立“重试失败页”入口，调用 `corpus_retry`，与处理未确认页的 `corpus_process` 分开。按钮显示失败范围并说明成功页及历史页版本保留；实际失败页重排和原件保护由核心验收，UI mock 不证明其安全性。
- 已通过预检后再次检查发生错误时，旧 `ready` 结果原先会留下。现在新检查先清除旧结果，错误出现后导入保持禁用。
- 预检分别显示文字批处理上限与 OCR 单页等待上限、实际识别器版本和渲染 DPI，并显示 OCR 配置错误。首页明确整书资料当前提供逐页解析与恢复，整书知识整理仍待接入。
- 本页正文可展开查看页版本、解析器及坐标变换记录；OCR 页版本更新后重置该页阅读状态。没有 `page_revision` 的旧解析记录明确说明版本字段缺失，不伪造版本。返回的资料 ID 与页偏移必须匹配当前选择；项目切换期间旧页面不会作为当前页面展示。
- 获取进程退出后核心返回的 `interrupted` 现在显示为“获取已中断”。原件 SHA256 尚未确认或来源处于该状态时，隐藏继续解析与失败页重试，保留原错误，并提示重新选取原件、检查后重新导入；获取仍在进行时说明等待保存及中断后的处理方式。原件已确认的临时解析失败继续保留解析和重试入口。

实现产物为 `apps/desktop/src/AppCorpus.tsx`、`useCorpus.ts`、`corpusTypes.ts`、`App.tsx`，及 `crates/noetome-desktop/src/main.rs` 的 `corpus_retry` 命令、27 项能力清单和真实命令注册。核心 `needs_ocr_pages/retry` 对应变化另见本项核心记录。

## 实际操作链

1. 重载页面并恢复最近项目 A，读取完整 710 页的待识别扫描本 mock；待识别页数、继续识别与暂停均可见。“继续扫描识别”后“暂停解析”，观察到各一次 `corpus_process/corpus_pause` 请求及持久暂停说明。
2. 将该 mock 设为 2 个失败页，点击“重试失败页（2 页）”，得到一次 `corpus_retry`，参数绑定 `/qa/项目 A` 与 `corpus-a`；响应后失败页按钮消失。
3. 选择 PDF 并预检通过，导入启用，OCR 1800 秒单页上限和 150 DPI 可见。再模拟预检配置错误，错误代码显示且旧通过结果消失，导入禁用。710/722 MiB 等数值均为 UI 状态测试，不能作为真实教材解析结果。
4. 跳到物理第 710 页，确认末组 706–710 页及末页内容可读。展开页面版本记录，真实 mock 版本字段可见；没有 `undefined` 页面尺寸。
5. 保持解析请求未返回，执行 A→B→A：B 没有 A 的旧页面，处理请求保持 1 次，向 B 请求旧资料页的次数为 0；回 A 后可暂停。
6. 延迟预检请求跨 A→B→A：旧 `ready` 响应被丢弃，新项目代次的输入保持空白。模拟列表读取失败时，错误显示并保留上次读到的来源；恢复读取后错误可清除。
7. 中断状态的最终修复单独运行 `interrupted-ui-qa.js`：恢复 `interrupted` 且原件未确认的记录，中文标签、重新选取提示和原错误均可见，继续与重试按钮不存在；再检查未确认原件的 `failed`，以及明确自造的 `interrupted` 但含指纹变体，均没有处理入口，三类阻断记录的处理请求合计 0。原件已确认的临时解析失败仍有继续和重试按钮，实际各点击一次得到 `corpus_process/corpus_retry`，均绑定 `/qa/acquisition-project` 与 `confirmed-failure`。共 16 项断言全部通过，截图为 `interrupted-final.png`；这是渲染界面与模拟 IPC 的验收，不证明实际获取中断已通过。

上述模拟均为零模型调用。跨项目结果原回执为 `recovery-cross-project-result.json`。原线程 2026-11-12 的旧资料恢复、密码阻断和首次窄窗口检查仍保留于 `.artifacts/B16-T02/desktop/README.md` 与当日原始回执，不改写其日期或验收范围。

## 失败记录与未运行范围

恢复后的首次 mock 桥遗漏 Tauri `metadata.currentWindow`，引发 `WindowControls` 错误和空页面。补齐模拟桥元数据并完全重载后复测通过；这是测试桥配置失败，未修改生产窗口组件。跨项目脚本还曾使用同时匹配 region 与 textbox 的 label，以及只匹配半句的精确文本；修正选择器后成功回执保留。最终 console 检查在完整重载后的新页面完成，前述失败未混入通过结果。

新增中断检查首次用文件参数调用 Playwright 时，工具的允许根仍是 `Noetome`，拒绝读取 `Noetome-mainline` 中的脚本；该次未执行页面检查，回执保存为 `interrupted-browser-setup-result.json`。随后使用相同脚本的内联内容在新隔离上下文实际运行通过，没有变更生产代码或放宽断言。

同源 Windows 首测已真实打开项目，但测试脚本将 Core 返回的 `\\?\C:\…` 与输入的 `C:\…` 按字符串直接比较，误报目录不一致。仅修正忽略目录中的验证脚本：两边都要求绝对路径，再通过 `path.win32.toNamespacedPath` 比较；真实路径与 DTO 不改写。首测 fatal、结果、manifest 和成功构建回执保留原文件与摘要。首次复用启动还因未签名 UNC PowerShell 脚本的执行策略被拒绝，实际 UI 检查未运行；该日志保留，随后用仅针对该进程的 `ExecutionPolicy Bypass` 运行已审查验证脚本，在新的项目和证据目录得到上述真实通过结果，没有再构建或修改产品源码。

本 UI 分工没有执行安装后的原生按钮、Windows 文件选择器、真实 OCR 质量或整书模型整理；浏览器 mock 与开发程序 IPC 通过不能替代这些验收。为后续复现准备了 `recovery-ui-qa.js`，新增完整脚本尚未执行，不将其中尚未运行的长 Unicode 文本拼接、错误页面响应等断言计入通过数。真正跑过的操作与读数以本记录及原始回执为准。
