# B12-T02 同一主题的多阅读目标与同类结构一致

## 1. 状态

Linux 上实现并端到端跑通：`template adopt|build|list|status`、独立只读审计器、20 项 Rust 集成测试与 51 项 Python 审计测试全部实际运行通过。**Windows 原生门禁未运行**（本机 rustup 未安装 `x86_64-pc-windows-msvc`，也没有 NSIS），安装包与卸载流程不在本轮结论内。

## 4. 关键取舍

1. **省略合法但必须可见**：模板里不适用的章节可以省略，省略逐条记 `section_omitted`，subject 写成 `goal_id#section`；但"声明了章节却没有原子"直接拒绝——空章节是为了凑模板齐全，不是结构设计。
2. **模板外章节必须给理由**：`special_reason` 缺失即 `TEMPLATE_UNREASONED`，给了记 `special_section` 偏差，这样"特殊结构"与"笔误"可区分。
3. **章节顺序按模板的相对顺序判定**：省略不改变顺序，换序必须换模板或先改模板，否则 `TEMPLATE_SECTION_ORDER`。
4. **同类同层一致性按 `(template_id, level, kind)` 分组比"存活章节序列"**：序列不同且有理由记偏差，无理由进 `inconsistent_structure` 缺口；这样不依赖百分比。
5. **唯一解释位置**：概念 `explanation` 原子必须恰 1 个，其余目标只能 `reference`/`embed` 且指向解释笔记；解释笔记内部自指直接拒绝。
6. **有缺口仍写报告**：`build` 遇到 findings 仍写出完整报告，只把退出码置 3，按首个 finding 映射 `TEMPLATE_INCONSISTENT`/`TEMPLATE_UNEXPLAINED`/`TEMPLATE_DUPLICATE_EXPLANATION`。
7. **输出清单不含 `created_at`**：同一冻结输入的两次构建必须逐字节相同。

## 7. 实现过程中修掉的缺陷

1. **摘要重复计数**：原摘要写"其他偏差 N 处"，实际是 deviations 总数（含省略），与"省略章节 10 处"重复计数 → 三处摘要统一改为"偏差合计 N 处"。
2. **`template_model.rs` 导入路径**：`use crate::ProjectError` 报 E0432 → `use crate::project::ProjectError;`。
3. **测试 fixture 自身有空章节**：`declaration()` 声明三章却只有两章原子，导致 6 项假失败 → 改为只声明有原子的章节，其余测试按需补原子。
4. **集成测试把引用总数当 reference 数**：`goal.references` 同时包含 `embed`，初版断言总数 5 失败 → 改为按 role 分类计数（reference 5、embed 1）。
5. **审计器整表比对措辞**：`output-report` 因 `detail` 措辞不同永远失败 → 改为投影比对（只比结构字段与 `(kind, subject)` 列表）。
6. **审计器省略偏差 subject 口径**：产品写 `goal_id#section`，审计器原只写 `goal_id` → 已对齐。
7. **审计器 root 模式抛 traceback**：被改坏的声明直接 `strict_load` 抛出 → 改为记 `root-declaration` 失败后继续输出结论。
