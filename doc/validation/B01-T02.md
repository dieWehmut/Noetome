# B01-T02 空项目初始化与只读检查

日期：2026年11月1日，Windows x64。范围为 `project init` 与 `project inspect`；没有导入资料、抽取知识、生成 Vault，桌面尚未接入项目业务。

## 实际能力与产物

`crates/noetome-cli/src/project.rs` 在明确的新目录初始化 Schema 1。配置只保存项目 UUID v4、Schema、UTC 创建时间、initialized 状态和固定相对数据库路径；SQLite 只创建真实 project_metadata 基础表。配置和数据库元数据一致，应用标识及 user_version 可核对。

初始化采用独占目录、marker、暂存文件和不可覆盖的硬链接发布。普通失败仅清理身份及字节仍匹配的本次文件；未知、改写、删除或被替换的内容保留。中断现场明确拒绝继续写入，当前恢复方法是新目录重试；没有生产任务续写或通用迁移功能。

inspect 用只读、immutable SQLite URI 检查静止项目。Windows 持有拒绝写入/删除共享的读句柄，拒绝事务侧文件，检查配置、实际表结构、元数据和 quick_check；不会迁移、恢复日志或生成 WAL/shm。此用法不是未来可写运行库的并发快照方案。

参数解析与执行分开，桌面共享 render 仍只响应帮助和版本，不会经预览接口创建项目。README、数据契约、架构和设计同步实际范围。

## 失败与修复记录

1. 首次新增bundled SQLite编译时MSVC C1.dll报D8050“无法将命令行放入调试记录”。当前Low构建树的子进程不能使用Medium系统临时目录；选择项目构建临时目录后C编译和工作区检查通过。
2. 初次存储测试4项失败：检查Windows canonical prefix时把尚未完整的 `\\?\D:` 当作目录访问，返回os error 1。改为到RootDir形成完整卷根后检查，仍逐级验证全部真实祖先。5项存储用例通过。
3. 空目录身份替换测试改为在marker前实际移动空根，避免把Windows拒绝移动含打开文件的目录误算成成功替换；相同字节文件替换另有实际测试。
4. 首次项目黑盒事务测试快照读取SQLite SHM锁定区返回os error 33；改为完整核对锁区外字节，逐字节记录120至127的可读值或锁状态，并核对文件长度、修改时间和属性。真实活动事务仍须被拒绝；事务结束后重查数据库完整字节。11项项目CLI用例最终全部通过，没有跳过事务或SHM文件。
5. 独立Python冒烟第一次搬移被其验证连接占用：Python连接上下文只结束事务，不关闭连接。显式关闭后新目录完整复测通过；这是验证脚本修复，没有放宽CLI要求。
6. PowerShell脚本调用会消耗未加引号的 `--`，导致Cargo未收到程序/测试参数分隔符。README示例改为 `'--'`，通过wrapper实际运行项目初始化和检查验证转发；没有把Cargo帮助误作应用执行。
