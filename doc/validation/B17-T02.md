# B17-T02：本地模型作为可选 provider 的适配与实测判定

任务状态以[账本](../../dev-log/tasks.json)为准。本地模型是可选 provider，云端 `deepseek-flash` 仍是默认和验收基线；本地实测不替代云端验收。

## 实现

提交 `47cc00e`、`862a3a9`（合并 `78473b4`、`16ce328`），后续 `dfb3074` 补本地 strict schema：

- `crates/noetome-cli/src/production_compile/provider.rs::validate_config` 增加 `local_openai`：必须 `credential_mode=none` 且 `credential_env` 为空（`LOCAL_PROVIDER_CREDENTIAL_MODE`）；端点必须是 `http` + `127.0.0.1`/`localhost` + 端口 + `/v1/chat/completions`，无 query/fragment/userinfo（`LOCAL_PROVIDER_ENDPOINT`）；`max_output_tokens` 1..=32768、`request_timeout_ms` 1..=300000（`LOCAL_PROVIDER_LIMIT`）；账本名必须为 `local-openai.usage.json` 且必须已存在（`LOCAL_PROVIDER_LEDGER`、`LOCAL_PROVIDER_LEDGER_MISSING`）。
- `model.rs` 增加可选 `credential_mode`、`reasoning_effort`；本地时凭据置空、跳过云端凭据校验与 `credential_echo`，传输层无 bearer 时不发 `Authorization`。
- 本地 `response_format` 使用 strict `json_schema`（`noetome_candidates_v1`）；LM Studio 只接受 `json_schema` 或 `text`，`json_object` 会返回 HTTP 400。
- 新增 `scripts/measure_local_provider.py`、`store_tests.rs` 的 `local_openai_fake_http_smoke`、`local_tests::local_config_matrix`。

## 可用范围结论

本地 provider 适合小规模草稿或链路验证：24 个真实片段中只有 9 个产出非空有效候选，quote 逐字保真 7/24，中位 23.8 s、最长 84.8 s；按 1298 单元、每单元 24 s 估算整书约 8.6 小时，长尾更久。当前不用于整本生产，不替代云端验收。速度限制主要来自本地 9B 模型的输出质量与长尾，而不是 HTTP 传输。

## 边界

- 本地 CLI 两次真跑的页面是 synthetic `multi.pdf`，内容贫乏导致 `concept_ids=[]`；这证明传输/账本/严格错误码，不证明本地能稳定产出合格知识。
- 云端回归只覆盖安装版 bounded run5，不声明整本完成。
