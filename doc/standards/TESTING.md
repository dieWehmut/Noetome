# Noetome 测试标准

本文件规定从小型 fixture 闭环开始的验证要求。产品验收目标见 [PRD](../requirements/PRD.md)，实现边界见 [工程架构](../technical/ARCHITECTURE.md) 和 [数据契约](../technical/DATA_CONTRACTS.md)。

所有“通过”必须有实际执行证据。未运行、环境不可用、被跳过、已知失败和不适用分别报告，不能统称通过。

## 1 首阶段目标

首阶段证明确定性资料登记、知识映射、计划、输出与报告能构成可信闭环。IR 与计划由已审阅 fixture 提供，测试结果不代表自动抽取、事实裁决、学科覆盖或模型质量已经达标。

默认回归不需要网络、API 密钥、外部模型、桌面应用或用户真实 Vault。外部适配器引入后，仍须保持基础回归能够离线执行。

fixture 是可审计的预期行为样例。它不能证明真实教材客观上100%无遗漏，也不能因为由 AI 生成过就称为独立人工金标准。

## 2 测试分层

| 层级 | 当前应测范围 | 后续补充 |
| --- | --- | --- |
| 单元 | 编码规范化、指纹、定位、路径、转义、引用解析 | 复杂图表、公式、预算计算 |
| 契约 | 合法与非法 JSON、版本、必填字段、引用完整性 | sidecar 与 provider 响应 |
| 集成 | SQLite、账本、IR、NotePlan、渲染映射 | 持久化队列、真实解析器 |
| 端到端 | CLI 到独立临时 Vault 和双报告 | 真实资料和桌面操作 |
| 故障与保护 | 无效输入、路径越界、目标碰撞、未完成阻断 | 并发编辑、审批过期、发布补偿 |
| 内容评估 | fixture 原子与条件是否完整保留 | 独立标注集的真实模型评估 |

不要为纯文案、小范围可逆样式变动编写镜像实现的测试。优先测试跨模块契约、失败路径和不可破坏的不变量。

## 3 Fixture 管理

测试输入与期望文件纳入版本控制，目录按行为命名，不按模型名称组织。每个 case 说明目的、来源许可或自造性质、必需知识、排除理由、期望结果及局限。

fixture 原文优先使用自造、可公开的短材料，避免将用户生产笔记、私有教材或凭据提交仓库。科学样例如需真实知识，应记录审阅者与依据；首闭环可以使用明确标为虚构的比较对象验证结构。

case 包至少包括：MD/TXT 来源、case 清单、IR、NotePlan 和独立 expected 清单。源码字节与各实体 ID 固定；时间和运行目录等非确定字段在检查时单独处理。

更新期望文件前先解释行为为何改变，审查差异，再提交更新。不得在测试失败后自动接受当前产物为新基准。

首次至少准备：

1. 正常来源、两个关联笔记、标题链接及比较表。
2. 同名或重复来源，以及同名但内容改变的版本。
3. 必要条件、单位、例外及明确未给出的属性。
4. 合法排除的空白与格式内容，以及不能排除的失败来源。
5. 缺失原子、缺失证据、歧义目标和不合法计划。
6. 中文、空格、长文件名和 Windows 路径边界。
7. 工作区外哨兵文件、输出目录碰撞和未知内容保护。

## 4 不可放宽的不变量

### 来源与知识覆盖

每个来源版本的规范文本区间完整、有序、无重叠地进入 Span 清单；全部 Span 与账本双向可对账。失败和待复核项不能计入覆盖完成，排除必须有可核对理由。

必须根据独立 expected 清单检查必要原子，而不是只让程序对自己生成的清单计算100%。必要原子、条件、单位或例外未出现在实际输出时，计划 ID 齐全也必须失败。

重复归并保留每个来源位置的证据关系，不能把第二本资料的出现位置删除。未知或无法确认的值不能变成零、默认值或“已验证”。

### 身份与引用

概念、Span、笔记和章节身份不能因显示名称改变而换号。每个需要完整解释的概念只有一个当前规范位置；全部语义引用唯一定位到计划中的实际目标。

跨文件标题链接、表格别名转义、重名路径及中文路径都需验证。仅存在一个同名文件不算解析到预期目标；当前闭环不支持的块链接和嵌入应拒绝或明确标示未支持。

### 人工内容与文件安全

所有测试写入独立临时目录。测试根之外放置哨兵文件，成功与失败运行后都核对指纹；不测试用户生产 Vault。

首阶段不支持接管已有内容，因此遇到非空目标、未知文件或已存在发布目录必须拒绝，不能以 `--force` 或重试覆盖。fixture 目录与输出重叠必须拒绝。

路径校验覆盖 `..`、绝对路径、Windows 保留名、大小写碰撞、尾随点/空格和 junction 越界。平台相关能力不可用时明确报告未运行，不假称已完成全部平台保护测试。

后续有增量更新时，测试还需覆盖人工编辑、重命名、删除、图像替换、回滚与审批后再编辑。未批准覆盖次数必须为零，普通自动模式不能降低要求。

### 发布与状态

必要校验 failed 或 not_run 时禁止发布成功。部分文件存在、命令走到末尾、数据库事务提交成功，都不足以证明整轮成功。

发布完成后重读文件校验指纹，核对 Release 清单、实际文件和报告。失败运行必须返回非零退出码，并保留可定位原因。

研究未启用时显示不适用；预算、网络费用及模型指标没有执行就不得产生假数字。JSON 与 Markdown 报告必须表达相同状态与计数。

## 5 首闭环测试矩阵

| 编号 | 输入或操作 | 必须观察到的结果 |
| --- | --- | --- |
| T01 | 最小有效 case | 生成独立临时 Vault、状态和报告，退出码0 |
| T02 | 两次运行同一 case | 内容文件一致，稳定身份不变，审计字段独立 |
| T03 | 来源指纹与声明不符 | 拒绝旧 IR 映射，不发布成功 |
| T04 | 无效 UTF-8 或错误范围 | 明确失败，不丢字节或填充假原文 |
| T05 | 缺少或重复 CoverageRecord | 来源对账失败 |
| T06 | 必要原子只在计划中出现 | 输出映射或内容检查失败 |
| T07 | 删除条件、单位或例外 | 独立内容预期失败，不能靠计数通过 |
| T08 | 缺失证据或证据片段越界 | 契约或知识验证失败 |
| T09 | 两个规范位置或不存在的目标 | 计划验证失败，无假双链 |
| T10 | 表格内别名与中文路径 | 列不被错误拆分，链接指向正确位置 |
| T11 | `../`、绝对路径或路径碰撞 | 写入前拒绝，哨兵指纹不变 |
| T12 | 输出目标预先有人工内容 | 拒绝覆盖，内容指纹不变 |
| T13 | 渲染阶段注入失败 | 不出现 published 成功记录 |
| T14 | 暂存后模拟中断或登记失败 | 输出与状态可识别为未发布或待恢复 |
| T15 | 不支持契约版本或字段拼错 | 显式拒绝，非零退出码 |
| T16 | 成功与失败双报告 | 状态、计数、路径和问题一致 |

T02 比较规范化后的产物内容，不要求 run_id 或时间相同。T14 初期可通过受控故障注入验证残留状态，不能据此宣称所有断电场景已经安全恢复。

## 6 测试命令与证据

Rust 工程建立后，基本检查采用格式检查、适当的静态检查和 `cargo test`。具体工作区参数由工程实际布局确定，不能把尚不存在的命令标成已执行。

端到端测试通过编译后的 CLI 调用，核对退出码、报告、数据库和文件指纹。不要只单独调用渲染函数就声称 CLI 闭环通过。

每次相关变更记录：提交、测试范围、命令、环境、通过与失败数量、未运行项、输出位置。常规通过结果简要汇总；失败保留稳定错误码及重现所需最小资料。

必需的 Windows 行为至少在 Windows x64 执行。其他平台运行的单元测试不能替代 Windows 路径、文件占用或进程管理测试。

基础回归通过后，只有新变更、失败或明确未解决风险才扩大或重复测试，不为增加检查数量而重跑相同证据。

## 7 外部能力的引入门槛

### Python sidecar 与真实资料

先用协议假进程测试启动、JSON 输出、标准错误隔离、超时、非零退出、截断响应和越界资源路径，再接入一个真实解析器。协议测试不依赖 Python 解析库或模型下载。

B03-T01 的具体验收见[实施方案](../execution/B03-T01_PLAN.md)与[协议契约](../technical/SIDECAR_PROTOCOL.md)。真实 fake helper 固定 producer=fake，仅在测试入口允许；普通 CLI 不暴露 fake 参数。除单个响应与严格字段外，必须测试 stdout/stderr 同时超管道容量、请求/响应/诊断/时间越界、取消和资源精确清单；Windows 子/孙进程先 PID 握手确认存活，再确认终止及活动 Job 清单为空。父进程早退和后代不继承管道的情形不能只依靠 EOF 或库的 wait 宣传判定通过。

时限和取消覆盖进程通信及Core输出校验，不只覆盖等进程退出。大量单元共用大UTF8资源时，不能逐单元重扫整份文本；单元、引用和问题校验中持续检查取消与时限。真实BrokenPipe必须及时报告IO并停止仍存活的进程树；只测不读stdin直到超时不能替代读写错误传播。主Job终止失败用仅测试构建的私有故障注入验证独立兜底和有界退出等待，仍须真实确认root/child/grandchild退出，不能由模拟PID清单证明。

资源路径、Windows 名称/大小写/前缀冲突、文件 SHA/长度/身份、UTF8范围、重解析点与链接数（本项分别用真实junction与硬链接实测）、未知文件和既有工作区均需实际失败断言。单独文件符号链接特权用例没有运行时明确标记，不能因helper存在该模式就称为通过。错误及限额诊断保留已读取的有界字节，超限不得截断后继续交付成功。只清理确认属于测试的根；Job Object 进程管理不构成文件或网络沙盒。

真实 PDF 样例分别覆盖文本、扫描、表格、公式和图片；每类记录支持、失败和需要人工复核的结果。扫描失败不能以保留空白文本宣布来源覆盖完成。

B03-T02固定作者自造的14PDF及25个可渲染页，正文、原始页数/SHA、Helvetica baseline/字宽、逐字形/区域和CropBox/Rotate/UserUnit矩阵预期不从解析输出反推。初始样例先于parser实现，独立审查又增错开栏和纯空格页并固定作者预期再做修复红绿。Poppler页数/渲染与agent回看是独立工程证据；pdftotext未提供时记not_run，UserUnit标注图只证明归一位置，不证明渲染物理尺寸。复杂页仅核对真实字形/位置和保守状态，未声明可靠阅读顺序。完成证据见[B03-T02验证](../validation/B03-T02.md)、[adapter红绿](../validation/B03-T02-ADAPTER.md)与[独立支持矩阵](../validation/assets/B03-T02-support-matrix.md)。

真实`tests/pdf_parse.rs`按全部物理页、字面正文/行序、独立glyph和bbox及实际资源字节核验普通CLI，再执行漏页、错页、页内错框、越界、漏正文、错序和Unicode切断等篡改。修改manifest后更新实际artifact SHA/字节总和及JSON/Markdown对应事实，并要求具体PDF语义错误族；陈旧MD或region名称规则提前失败不能替代正文/位置失败证据。空页的实际0字节artifact保留，但非空wire范围必须start<end，unknown空页wire text=null并需复核，不放宽已验收v1。

Core DTO测试与adapter直接Python进程分开记账；Root PDF边界测试另用实际Windows锁、junction/硬链接、目录替换、create_new报告碰撞、stdout/资源限额和已观察存活PID后的timeout/cancel/退出。故障程序只存在于测试调用，普通CLI不接受fake、命令覆盖或故障环境开关。独立`scripts/verify_pdf_parse.py`不导入parser/Core实现，从固定expected检查14次parse、14次只读inspect与实际SHA、计数、正文/位置，保存wall_ms、资源字节及完整产物指纹。小型wall/输出资源测量不是内存、CPU、千页吞吐、24小时稳定或科学指标。

整项code review以额外真实PDF复现了错开栏误parsed、纯空格误parsed和多码点ToUnicode空格规则漂移。必须保留原红灯，逐项补adapter和Core的伪造parsed拒绝；Rust再用实际动态作者CMap核对A+space后B只保留一个空格、needs_review及readonly inspect。该CMap回归不扩大多码点font bbox支持声明。

真实PDF回归须先按[锁定环境](../../sidecars/pdf_parser/README.md)配置NOETOME_PDF_PYTHON绝对路径；既有fake回归用NOETOME_TEST_PYTHON，均不自动下载。每次改adapter后生成并检查`scripts/build_pdf_sidecar.py --check`的源码/payload字节和SHA绑定，避免可读源码测试与实际嵌入代码分叉。普通Rust构建消费提交的payload，不导入Python解析库。

### B03-T03 PDF来源项目

先固定[Schema3契约](../technical/PDF_SOURCE_CONTRACT.md)，真实RED必须区分产品失败、测试设置错误及更新后不适用的旧断言。普通CLI从旧Schema1/2升级，逐字段核对全部旧SQL四表与实际rowid、原始/规范化字节和报告；PDF保存独立raw/parse身份，默认复用、显式重解析、内容修订、回到旧字节、跨来源同SHA、失败后重试与获取未完成分别验收。

Writer在准备、版本发布、parse发布、数据库发布、配置发布、完整重读和清理阶段做可确认回退；实际未知文件和Windows拒绝删除句柄必须保留现场及备份。真实子进程中断先以同步关闭的完整receipt证明阶段和PID存活，再终止/等待；不得用模拟PID或“已调用kill”替代退出证据。敏感性变体在独立编译目录破坏abort后，原测试应真实失败，变体不改生产代码。

只读验证需要核对原始页JSON数值词法、所有资源SHA/长度/身份及精确缓存清单，已保存host失败与未确认parser残留按各自证据级别处理。并发回归在实际raw文件守卫被观察到后注入：新文件或原先不存在的来源根出现使当前读取拒绝，owner改写/替换被守卫阻止或使当前读取拒绝；覆盖无已获取PDF版本的Schema3。有限文本PDF登记通过仍不替代扫描OCR、科学准确性、生产Vault或跨平台实测。

实际完整回归、独立CLI、审查修复和原始日志统一见[B03-T03验收](../validation/B03-T03.md)。

### B04-T01 离线fake候选网关

先声明受控来源、独立gold和严格候选契约，运行未接线普通CLI取得真实RED，再实现网关。显式producer=fake只证明重放契约，不能充当真实模型、科学准确率或完整知识覆盖验收。独立脚本`scripts/validate_extraction_gateway.py`创建新的来源项目/fake输入/输出，直接核对SQLite、来源字节、mtime和清单，并比较真实请求绑定、作者期待值、双报告验证快照及实际产物指纹。

覆盖非法/重复/额外/缺字段JSON、未知版本/parse、错误SHA、中文UTF8边界、quote不符、无文本或failed PDF、真实needs_review和unknown值、能力不足、空响应、输入/响应/token限额、预算预留/停止、价格未知、超时、运行期间取消、旧输出/越界与来源/fake/输出清单干扰。每个失败返回非零，candidates.json不得残留为验收成功；未知人工文件保持原字节。来源缓存硬链接须在语义内容读取前拒绝，Windows实际持有读取守卫并拒绝配置/SQLite/快照写入。

验证脚本自己的SQLite读取必须显式关闭连接，不能等待GC才释放Windows句柄并干扰下一次来源登记。普通回归离线，金额价格未知不写0；真实模型用量/tokenizer保持null。实际工程结果和失败修复见[B04-T01验证记录](../validation/B04-T01.md)，不宣称Ctrl+C、跨平台、生产Vault、长任务或真实模型质量已验收。

### B04-T02 单请求文本API离线验收
