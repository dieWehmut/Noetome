# Noetome 全项目测试与验收标准

本文件规定从最小CLI到个人可用V1的验证层级、数据、追溯、故障和真实质量门槛。产品定义见 [PRD](../requirements/PRD.md)，发布证据和命令见 [RELEASE](RELEASE.md)。完整计划不意味着测试已经执行；通过、失败、未运行、阻塞与不适用必须分别记录。

## 1 验证原则

一次小任务只运行与变化相关的验证及必要回归，完成后保存真实命令、退出码、测试数量和产物。代码已写、文件存在、提交成功或模型自评不代表验收通过。新的输入能力、数据库状态、预算与发布边界必须有能区分错误实现的样例。

基础工程回归默认离线，不需要私有资料、API凭据、桌面应用或真实模型。完整V1仍必须通过真实provider、授权资料、独立金标准、干净Windows安装与Obsidian实机门禁；离线成功不能替代这些项目。

验证默认由开发Agent执行、分析和记录。单元、CLI、数据库、故障、UI、打包、安装与回归不得转交小白用户手动运行命令；桌面自动化使用[UI自动化方案](../technical/UI_AUTOMATION.md)。用户只在无法替代的验收点参与：缺少时一次配置真实提供商凭据及预算、确认或提供已独立审阅的gold知识，以及最终实际使用体验。已有有效授权与审阅证据不重复索取；可自动获得的环境、日志和截图由Agent自行处理。

不为纯文案或小范围可逆样式编写镜像实现的测试。禁止在失败后删除用例、自动更新gold、降低阈值或缩小语料却保持原完成声明。修复后重跑受影响检查，只有新风险或新改动才扩大范围。

## 2 测试层级与执行环境

| 层级 | 验证对象 | 最低必要覆盖 | 证据 |
| --- | --- | --- | --- |
| 单元 | 纯规则与转换 | UTF-8、指纹、定位、预算算术、转义、条件与ID | 运行器结果及失败用例 |
| 契约 | JSON、SQL、IPC、sidecar与provider | 有效、缺字段、未知字段、重复键、错误版本、越界与超大输出 | 版本化fixture和解析结果 |
| 集成 | SQLite、对象仓库、任务、审批与发布 | 事务、恢复、依赖失效、请求幂等、写前校验 | 状态库与文件对照 |
| CLI端到端 | 真正构建后的二进制 | 参数、退出码、受理与完成、项目生命周期、导入至报告 | 命令、stdout/stderr、文件与DB |
| 桌面端到端 | 安装包和WebView | 项目、任务、来源、审批、取消、恢复、托盘 | 实机事件及必要截图 |
| 内容质量 | 真实资料与模型产物 | 召回、事实、条件、证据、排除、图表与公式 | 逐项gold判定和审阅记录 |
| 性能与容量 | 实际大负载 | 1000页、10000原子、3000笔记、交互和24h | 时间序列与原始测量 |
| 发行验证 | Windows安装产物 | 干净安装、离线依赖、升级、卸载、签名和许可证 | 包指纹、清单与环境报告 |

Rust测试覆盖领域与core；Python测试覆盖解析侧车及工具；前端使用组件、契约及真实WebView测试。Node/Playwright只作为开发和CI依赖，不引入运行时Chromium服务。Linux或模拟文件系统通过不能代替Windows路径、文件占用、命名管道、进程与安装验证。

## 3 测试资料与生产方式

### 工程fixture

测试输入与独立expected纳入版本控制，按行为命名。每个case声明目的、许可或自造性质、producer、已知局限及预期。优先使用自造且可公开的短文本和虚构比较对象，不将私有教材、生产Vault或密钥加入仓库。

最小闭环fixture包括MD/TXT、case清单、IR、NotePlan和expected。IR由审阅过的固定样例提供，producer必须是fixture；表格计划和知识内容已给定时，只证明确定性编译，不证明AI抽取或主动规划。

case必须包含正常两个关联笔记及表格、重复与换版来源、条件/单位/例外、合法排除、缺证据与歧义引用、中文与空格路径、外部哨兵、目标目录碰撞。输入字节和ID固定，run_id、时间及临时目录单独比较。

### 真实资料包与人工gold

正式基准登记于tests/benchmarks/manifest.json。优先采用用户已有且授权用于测试的资料或许可明确的公开资料。私有语料保存在未跟踪测试数据目录，manifest记录内容指纹、许可说明和本机可解析别名；不写可复用密钥或公开下载受限内容。

基准至少3份同学科资料，章节组织不同且有重叠，包括文本PDF、扫描页面、复杂图、表格、源码公式和扫描公式。另有数学推导样例，避免只验证生物学结构。

正式gold最低包含200个独立人工审阅的必要原子，其中至少40个关键原子；至少20组身份、条件或真实冲突案例，以及至少20个关键图表和公式案例。类别可以引用同一原子，但不得把重复记录算成独立数量。关键原子由gold预先指定，覆盖核心公式、反应、限定、单位和例外。

每条gold记录至少有gold_id、source_version_id、定位、原子内容、条件、单位、必要性、是否关键、可接受等价表达、证据关系、排除理由或不适用理由、reviewer_id、reviewed_at、review_status。审阅必须独立于待测输出；AI可提出标注候选，但不把模型作者改名为“人工专家”。已有人类审阅证据可复用，未审阅条目保持pending_review并阻断真实质量门禁。

gold版本在运行前冻结并计算指纹。先生成待测产物，再按冻结gold判定；不能从同轮输出自动生成expected或回填遗漏原子以提高指标。数据修订须保留变更原因、旧版本及受影响测试，重新运行相应评估。

### 真实模型与fake区别

fake、录制响应、本地API stub和真实远程provider必须显式区分。fake可以验证协议、预算、状态和容量；录制响应仅说明回放契约兼容；真实canary只说明该次模型和接口调用成功。任何一种都不能直接证明完整学科正确率。

真实模型报告记录provider、实际model、端点authority、能力profile、提示词及配置版本、来源指纹、时间、用量、未知费用和每次调用结果。密钥不进入报告。质量结论只适用于已测试组合，不能扩展为任意用户自选模型保证。

## 4 不可破坏的数据与状态不变量

### 来源与知识

全部规范文本区间以有序、无重叠的叶单元进入Span清单，叶Span与覆盖账本双向对账。父级章节可以包含子区间，但不得将父子重复计入覆盖分母。失败与未复核不算覆盖；无法读取原始字节时不伪造内容指纹，无法解码时不伪造规范化文本。重复归并保留每个来源位置的证据。

必要原子必须在实际输出及内容映射中正确出现。只在计划中登记ID、只提及名称、丢条件或丢单位都不算正确覆盖。模型自信不算证据，未知数值不填零。

身份不随文件、标题或名称变更；同名异义分开，同义归并有可撤销历史。每个需完整解释的概念只有一个规范位置；移动、拆分或撤销归并后全部受影响引用和证据重新验证。

### 配置 网络与预算

CLI和桌面给定相同输入应得到相同effective_config_hash。外部检索关闭不等于模型API离线；测试分别观察检索、页面抓取、provider请求和解析器网络活动。页面抓取不得进入本机、内网、云元数据地址或携带模型认证头。

并发预留不能超卖剩余预算。总尝试数包含传输和结构修复；outcome_unknown不自动重排，预留unknown继续占用。超时、未知费用、已计费失败、重复回调、二次结算、服务商切换和价格缺失分别测试。

缺少凭据、预算或发送范围时不得发真实请求；不会阻止读取项目、离线fixture和不依赖远程结果的工作。人工保护不能关闭；扩大读写范围或接纳新主题须有明确授权和新快照，普通运行参数或模型输出不能绕过已有范围。

### 人工保护与发布

测试只写独立临时目录；目录外和非托管范围放哨兵，成功、失败与恢复后均检查指纹。覆盖绝对路径、父目录穿越、保留名、大小写碰撞、尾随点/空格、超长路径、junction和资源路径越界。

人工编辑、移动、删除、图像替换、章节提升、回滚及审批后的再编辑全部纳入保护。字节无冲突不意味着语义无影响。审批绑定版本与变更清单；过期审批不能写入，拒绝不能被重试自动推翻。

发布成功必须同时满足实际文件、资源、位置映射、索引、Release清单与数据库一致。候选文件存在、DB提交成功、退出码0或UI通知不能独自证明成功。关键检查failed或not_run时，禁止将受影响范围记为完整发布。

## 5 故障注入矩阵

以下失败点由确定性seed及命名killpoint触发；测试构建可启用，生产构建不暴露任意损坏开关。

| 场景 | 注入位置 | 必须观察的结果 |
| --- | --- | --- |
| 解析失败 | 无效UTF-8、加密PDF、页超时、截断侧车响应 | 来源失败可定位，独立资料继续 |
| 对象写入失败 | 临时写、flush、替换前后 | 不使用半成品，原对象不被截断 |
| DB失败 | 提交前、提交后、迁移中断 | 事务与版本可诊断，未知状态不自动成功 |
| worker崩溃 | Job领用后、请求发出后、结果提交前 | 重启检查点，未知请求不重复收费 |
| API限流与断网 | 429、超时、连接断开、5xx、错误JSON | 有界退避，统一尝试计数，预算正确 |
| sidecar进程 | 无响应、错误退出、超限输出、路径越界 | 杀停受控子进程，不破坏其他任务 |
| 发布中断 | 逐文件替换、映射登记、完成标记前后 | recovery_required或一致版本，无假成功 |
| 外部并发编辑 | 比较后、批准后、最终写入前 | 审批失效，人工内容保留 |
| 资源不足 | 磁盘空间不足、文件被占用、内存压力 | 清楚错误，安全暂停/隔离，不无限重试 |
| 生命周期 | 睡眠唤醒、窗口关闭、托盘退出、关机 | 真实状态和可解释在途结果，未启用不自启动 |
| 恶意资料 | 删除指令、密钥请求、URL越权、SVG脚本 | 当作内容处理，无权限扩展或脚本执行 |
| 搜索异常 | 空结果、过期页面、重定向、内网URL | 有界停止，证据不足不伪造结论 |

重放同一seed应产生相同故障位置和可核对终态。加速时钟可验证超时逻辑，不能用来满足真实24小时门禁。平台能力无法测试时标记not_run并阻断需要它的发行门禁。

## 6 PRD追溯与用例管理

任务账本的requirements、scenarios和quality只表示计划关联，不证明已验收。测试实现用稳定test_id关联FR、AC及NFR；最终release/evidence/acceptance.json汇总40组FR、40个AC及17项NFR。

每个追溯项记录requirement_id、test_ids、evidence_refs、implementation_refs、scope、status和未通过原因。引用指向具体报告与用例，不接受“见cargo test”作为所有FR的唯一证据。部分实现必须限定scope，不把FR-01的项目初始化当作全部项目管理已完成。

| PRD范围 | 必须有的测试重点 |
| --- | --- |
| FR-01至06 / AC-01至04、10、16、35、38 | 导入、版本、扫描、来源清单、筛选、权限 |
| FR-07至14 / AC-01、02、05至08、31至34 | 多源身份、条件、冲突、双模式、有界研究、反馈 |
| FR-15至25 / AC-09、11至19、23、40 | 规范位置、迁移、风格、主动表达、图像、公式与语法 |
| FR-26至28 / AC-20、33、36 | 来源隐藏但可追溯、索引迁移、真实报告 |
| FR-29至34 / AC-21至28、37 | 增量、锁定、审批失效、发布与回滚保护 |
| FR-35至40 / AC-26、29至31、39 | 持久任务、重试、能力、预算、后台和日志 |
| NFR-01至08 | 内容和证据指标、链接、图像、人工保护及恢复 |
| NFR-09至13 | 真实24h、容量、交互P95与停止调度时间 |
| NFR-14至17 | Windows路径、凭据、Obsidian兼容、诊断与迁移 |

同一测试可覆盖多个条目，但每个条目仍须有专门预期。最终必需FR/AC/NFR不得设为不适用来隐藏缺实现；仅具体子样例在条件不成立时允许带理由的不适用。P1/P2扩展不被自动加入V1发布前提。

## 7 质量指标与判定

实际公式沿用PRD。真实必要原子召回至少98%，预先指定的关键原子100%；分层抽样事实及条件准确率至少98%；已发布实质原子的有效证据或完整推导映射100%；链接唯一指向预期目标100%；未批准覆盖零次；关键图表和公式逐项通过。

事实准确抽样至少200条独立实质陈述，覆盖正文、表格、图片推导、范围内研究和多源冲突；不足200条时使用全部但标明样本不足，不能满足正式质量门禁。判断不清计未通过，不从分母删除。关键图与公式逐项核验，不用整体平均分掩盖一处关键符号错误。

报告同时给分子、分母、比率、逐项失败和样本选择方法，并给二项比例区间作为不确定性信息；区间不替代固定门槛。98%是产品基准，不豁免本轮已经知道的必要知识缺口。已发现必要原子遗漏、严重事实错误或人工风险仍按完成规则处理。

gold排除项独立抽审，避免用“目标不重要”剔除困难材料。旧和新观点分别按条件、时间和证据判定，不把纠正后的OCR错误算作应保留历史观点。

## 8 视觉与真实应用测试

CLI可执行AST、图元素、条件、单位、引用、路径及公式结构检查，但不能声称实际视觉已通过。桌面WebView2加载离线Mermaid与MathJax资源做实际预览；Agent逐项将关键渲染结果与已独立人审的gold及原图对照，保存具体判定与截图。无法确定的知识或语义差异集中交用户确认，不自动写成已人审；最终还须通过真实Obsidian。已有未变化的gold确认可复用。

Obsidian用无社区插件环境，在固定最低支持版本及验收时当前稳定版本分别打开同一基准Vault。逐项检查中文/空格路径、重名标题、块、表格别名、Properties、Callout、MathJax、Mermaid与SVG。保存版本、用例、预期、截图定位和实际结果，不仅截一张首页。

桌面端覆盖浅深主题、键盘、焦点、200%缩放、长内容、空/加载/错误、候选与发布区分、审批失效和关闭窗口行为。颜色对比度按DESIGN测量；视觉证据不代替core状态、预算和文件保护测试。

## 9 容量与长期运行

工程容量允许使用显式标注的自造资料和fake数据，但必须真的解析、入库、生成和检查目标数量；不能只在报告写1000页或用空循环代替。

容量集合A为至少3份资料、合计1000个实际内容页、10000个非重复必要原子和1000篇实际输出笔记；集合B为3000篇实际笔记及200篇有预先记录编辑差异的文件。可复用预置IR测确定性容量，producer需标明fixture，结果不算真实知识质量。

交互在参考Windows x64机器记录处理器、核心数、16GB内存、SSD、OS版本及后台负载；每种常规操作至少100次，报告全部样本与P50/P95/P99。操作到可用反馈的P95不超过2秒；长扫描和编译分别计首次可用状态与总耗时，不要求1000页任务在2秒内完成。暂停后2秒内停止新派发，已在途请求单独计量。

24小时测试使用真实墙钟与单调时钟，混合解析、本地HTTP stub、编译、发布与指定故障；总elapsed至少86400秒，睡眠区间单独列出，清醒执行时间同样至少86400秒，不能把关机和单纯等待凑足时长。每60秒记录活动、Job计数、CPU、内存、句柄、磁盘、预算和DB一致性；无工作负载期间明确记录，不伪造进展。

固定负载达到稳态后比较第2至4小时与最后2小时内存和句柄分布，增长超过10%或持续上升须解释并复测；存在无界增长、不可恢复损坏、重复发布或未知预留错误释放时直接失败。详细证据字段及门禁见RELEASE。

## 10 缺少外部条件时的正确结果

缺少真实凭据、明确预算、授权语料、人工审阅或干净Windows环境时，相关检查为blocked_external或not_run，附具体缺口和解除条件。不能把fake当真数据、把未签名当签名、把源码运行当安装包成功。

优先使用Agent可操作的隔离环境完成安装、UI和Obsidian验收；只有确实无法提供目标系统或必须由用户确认的知识、权限与最终体验时，才说明具体缺口并请求必要参与。不得仅因“实机验证”就要求用户照着长步骤自行测试。自动验证不应被写成不存在的人工签字，人工验收也不替代已定义的技术检查。

代理继续执行不依赖该条件的离线开发、测试和文档任务，并保留已完成证据；最终个人可用V1的必需门禁仍阻断。自动化负责真实记录与推进，不自动给自己授予数据、费用或人工审阅资格。

完整结束条件为：实现范围、测试、数据、发布候选和报告版本一致；所有必需门禁通过；缺陷清单无未处置严重项。相关命令、证据格式及失败退出以 [RELEASE](RELEASE.md) 为准。
