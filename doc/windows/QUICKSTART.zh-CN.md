# Noetome 0.2 Windows 11 x64 操作指南

本指南对应 0.2.0 的「真实 PDF → 持久整书任务 → 未核验知识 → 新 Obsidian Vault」流程。安装包包含桌面程序、CLI、锁定的 PDF Python 环境、运行库、模型辅助程序和离线作者样例，无需另装 Rust、Node 或 Python。具体构建的源提交、安装器摘要和实际验证范围，以随包 `delivery.json`、`SHA256SUMS.txt` 及 Release 说明为准。

## 安装与离线自检

1. 将安装包和 SHA256SUMS.txt 下载到本机。在 PowerShell 执行 `Get-FileHash -Algorithm SHA256 -LiteralPath '安装包完整路径'`，与下载清单比对。
2. 双击 Noetome-0.2.0-…-windows11-x64-setup.exe，按安装向导操作。默认安装到当前用户目录，从开始菜单中的 Noetome 快捷方式启动桌面。本测试包没有 Noetome 代码签名证书；Windows 若显示发布者未知，请先核对下载来源和摘要。
3. 在首页「离线安装自检」点击「运行离线样例」。结果应给出新的测试输出目录和 Vault 路径。该流程使用作者 fixture，模型调用和网络请求均为 0，只验证安装与本地编译链。

samples/single-page.pdf 是可提取文字的作者 PDF，samples/scanned-page.pdf 是扫描状态样例，二者不代表真实模型质量。payload-manifest.json 记录安装资源摘要，runtime-receipt.json 记录 PDF 环境来源和版本。

## 建立项目与保存整本 PDF

1. 在项目入口点击目录选择按钮，选择专用测试父目录，输入新的项目名称。首次建议建立自己的测试项目，例如 `D:\Noetome 实测\教材-01`。
2. 进入资料库，使用文件选择按钮明确选定一份 PDF，导入并保存原件。核对文件名、原件 SHA256、完整物理页数和预检结果。原书的印刷页码可能与物理页号不同。
3. 根据预检结果处理文字页。来源库按页保存进度，暂停或重开项目后可以继续。加密、损坏、待 OCR、空白与需复核页面分别显示，不能当作已确认知识。
4. 扫描页需要可用的本机 OCR worker。本次 OCR 接入复用已配置的锁定 Windows 环境，安装包不包含所有 OCR 模型；未配置或失败时保留待识别状态。先用文字 PDF 完成主流程更方便核对。

整书任务消费资料库中已保存的 PDF 版本。旧的 MD/TXT 和少量片段候选预览入口继续保留；使用整书整理时从 PDF 资料库选择来源。

## 开始、暂停与恢复整书任务

1. 打开任务中心的「整理整本资料」，勾选所需 PDF。界面显示每份来源的全部物理页和合计范围，无需逐页勾选。
2. 点击「建立整书任务」，保存范围并固定当前累计预算权威。此时不发送模型请求。核对来源和范围，再查看「模型与累计预算」。
3. 点击「开始整理」。程序先准备固定页版本与片段，再自动逐批发送所选正文。单请求有大小和时间限制，完整任务范围不会因这些限制被截短。
4. 查看已准备页面、已确认单元、失败单元、待 OCR 页、未解决页面及概念/原子/证据计数。任务尚未准备完时，单元总数会随完整页面准备增加；物理页分母始终保持全部所选范围。
5. 点击「暂停整理」停止当前请求和后续调度。重新启动应用并打开同一项目，从已保存任务中选择该任务，点击「恢复整理」。已确认单元和知识身份保持，不重复发送已确认内容。
6. 若出现认证、限流、超时或协议错误，先检查错误原因。任务保留停止状态；点击「重试失败片段」只是重新排队，再点击开始或恢复才发送请求。每个失败片段最多发送第二次尝试。取消任务为终止操作，之后可以查询和导出已确认内容。

整本范围登记完成不表示整本知识完成。无候选、待 OCR、失败与尚未准备/确认的片段都保留明确位置；预算不足或错误停止后也可以导出已有结果和未处理清单。

## 模型服务与累计预算

当前入口复用已授权的糖猫兼容 API、deepseek-flash 和本机当前用户加密凭据。实际整理需要联网及有效密钥。保存凭据时使用 Windows 遮蔽输入窗口，网页界面不接收密钥明文。

生产整书任务沿用累计 10,000,000 Token 权限。建立首个整书任务时，既有完整 JSON 历史固定迁入同目录 SQLite 权威，原账本保留原字节并设为只读。界面显示累计已核算、待核算预留和当前可用额度；不会创建新空账本恢复余额。原有十次调用基线为 33,185 已核算，但后续使用必须以当前完整权威记录为准，不能用基线覆盖。

每次请求先预留再发送。暂停、退出、超时或响应不完整时，无法确认的费用继续占用预留，不自动退款；显式重试保留旧请求的未知记录。缺失或损坏账本需要检查，不会自动追加请求。读取已有知识和再次导出不产生模型调用。

点击开始整理表示允许将所选范围内的正文发送到当前服务。模型结果都是未核验候选，原文引用有效、结构校验通过也不能证明科学正确率。

## 查询知识与固定来源证据

在任务中切换「概念」「知识原子」「来源证据」，使用搜索和上一页/下一页查看结果。原子保留正文、适用条件和证据身份；点击「查看来源证据」或「跳转到来源原页」查看抽取时的固定页面和原文。

证据绑定原件摘要、物理页、当时页版本摘要及 UTF-8 区间。后续 OCR 更新来源页不会替换旧证据；缺失或改变的原件/资产会显示错误。所有生成知识保持未核验，科学质量显示尚未测量。

## 导出并在 Obsidian 阅读

1. 在任务的「导出未核验笔记」选择专用测试父目录，输入一个尚不存在的新文件夹名，再点击「导出到新目录」。已存在的目录和 Obsidian Vault 祖先目录会被拒绝。
2. 在 Obsidian 选择「打开文件夹作为仓库」，打开刚生成的目录本身。
3. 从学习笔记.md 总览进入知识/ 下的概念笔记，阅读完整说明、条件和单位。文件名使用稳定身份，笔记标题显示概念名称。
4. 阅读处理范围.md 和处理范围.json，核对全物理页分母、确认/失败/未处理片段及待 OCR 问题。部分结果不会显示成整书已完成。
5. .noetome-index/ 保存知识、证据、全部页面和片段、来源与笔记块索引；export-manifest.json 记录导出文件的实读摘要和字节数。私人原始 PDF 不自动复制进 Vault。来源原件与完整运行材料保存在原项目中，桌面证据入口可以重查。

首次使用新的测试 Vault，不选择正在使用的生产 Vault。导出只是未核验结果的阅读副本；人工修改后的 Vault 不作为后续自动覆盖目标。分享前检查正文、原文引用和索引中是否包含私人资料。

## 卸载与反馈

在 Windows「设置 → 应用 → 已安装的应用」卸载 Noetome。安装资源移除，你选择的项目、导出目录和外部累计用量记录由你保留。反馈时提供构建源提交、操作步骤、错误码和经检查的日志，勿提供 API 密钥。

本次实际安装、模型调用、恢复及 Obsidian 版本检查分别记在 Release 验证说明中。未执行的全书 OCR、独立 200 原子/98% 科学门槛、24 小时运行、跨电脑部署与生产 Vault 保护仍保持未验收，不能由作者样例或成功导出推定完成。
