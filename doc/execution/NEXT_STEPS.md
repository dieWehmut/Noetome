# 近期开发步骤

此文件描述工作内容，真实状态请查看 [STATUS](../../dev-log/STATUS.md) 与 [TODO](../../dev-log/TODO.md)。B00仅建设规范与日志；首个产品开发批次为B01，只有下面3项。按依赖顺序每轮做1项。

## B01 T01 Rust CLI最小骨架

**单一结果**：在Windows x64上能重复构建并运行Noetome CLI的帮助和版本命令。

**依赖**：B00-T01。关联性质：开发基础能力，不代表任何完整产品功能验收通过。

### 操作顺序

1. 检查已有Rust、Cargo及Windows链接工具，记录实际版本；已有合适环境直接复用。缺失时按官方来源核实安装方法，不顺手安装前端、OCR和模型环境。
2. 新建最小Cargo workspace，起步只有 `crates/noetome-cli`。提交锁文件并用 `rust-toolchain.toml` 记录本轮验证过的工具链；不要凭记忆预填“最新版本”。
3. 实现 `noetome --help` 和 `noetome --version`。帮助使用面向用户的语言，列出当前实际支持项；不存在的功能不能显示为可用。
4. 未知参数返回非零退出码和可操作的提示。帮助、版本、无效参数路径均不得创建数据库、Vault或用户配置。
5. 加入少量进程级CLI用例，验证退出码、必要输出及无文件副作用；不要只测试字符串拼接函数。
6. 执行格式、构建和测试，更新日志及README运行说明，小步提交并推送后汇报结果。

**预期文件**：`Cargo.toml`、`Cargo.lock`、`rust-toolchain.toml`、`crates/noetome-cli/Cargo.toml`、CLI源文件及针对性测试；这些现在尚未创建。

**验收命令**：

```text
cargo fmt --all --check
cargo check --workspace
cargo test --workspace
cargo run -p noetome-cli -- --help
cargo run -p noetome-cli -- --version
```

未知参数用例由测试明确检查非零退出码，不能将预期失败混作构建失败。工具链缺失时记录实际阻塞，不将未运行命令写为通过。

**本轮边界**：不引入SQLite、文档解析、Python侧车、模型SDK、Tauri或插件系统。

**停止点**：上述结果可复现，日志与提交齐全。T02属于下一轮，不因T01完成顺手启动。

## B01 T02 空项目初始化与只读检查

**单一结果**：CLI能创建一个可识别的空项目，并只读显示其实际状态。

**依赖**：B01-T01。关联需求：FR-01、FR-35的最小基础，尚非完整项目管理与持久任务实现。

### 操作顺序

1. 根据 [数据契约](../technical/DATA_CONTRACTS.md) 定义Project最小字段，规范项目路径和版本。只抽出本轮需要的核心模块；不预建全套空crate。
2. 定义 `noetome project init <path>` 与 `noetome project inspect <path>`，先把命令行为和错误写入测试。
3. 在新目录创建配置和SQLite基础结构，保存项目ID与Schema版本。只创建初始化必需的表，不一次建完PRD中的全部实体。
4. 已有项目、非空未知目录和不可写路径必须明确拒绝，不复用或覆盖不明文件。初始化使用临时工作和明确完成标记处理半成品；失败清理只能触及本次创建的路径。
5. inspect只读展示ID、Schema和“空项目”等实际状态；不修改数据库、不制造“覆盖完成”或“知识已验证”。
6. 在隔离临时目录验证重复初始化、只读检查、占用或写入失败及重试行为，完成最小回归后记录、提交、推送。

**验收**：成功项目可重新打开；两次inspect前后内容指纹一致；未知目录没有未批准变更；半初始化状态有明确恢复方式。

**检查**：沿用T01的格式、构建与测试命令，增加项目初始化集成用例；真实运行一次init和inspect，将退出码及内容对照记入日志。

**本轮边界**：不导入资料，不实现知识图谱、检索或通用迁移框架。

## B01 T03 单份文本来源与覆盖清单

**单一结果**：导入一份UTF8 Markdown或TXT，能够核对来源身份、位置和待处理清单。

**依赖**：B01-T02。关联需求：FR-01、FR-02、FR-04的文本原型范围。

### 操作顺序

1. 添加小型自有fixture，包含中文、标题、空行和不同换行；人工列出预期来源单元。样例必须说明用途，不复制用户私有教材。
2. 实现 `noetome source add <project> <file>` 与 `noetome source list <project>`；显式仅支持首批文本格式。
3. 保留原始字节SHA256和可验证原文件引用；将编码、换行规范化结果单独保存，来源定位基于规范化快照并记录转换规则。不能混用原始和规范化偏移。
4. 按最小确定性规则切分SourceSpan，记录位置、类型和待抽取状态；报告数量能与fixture人工清单一致。此处使用最小导入记录，完整Run和CoverageRecord留到B02，不提前构建整条编译流水线。
5. 相同内容再次导入复用版本；同名不同内容生成可区分版本。原文件不变，未启用模型时不凭空生成Concept、Claim或“已验证”知识。
6. 验证无效UTF8、空文件、不支持扩展名、读取失败、重复导入、内容换版和中文定位。对账通过后记录、提交、推送。

**验收**：输入文件与来源清单可核对，重复导入不膨胀，变更版本可追溯；报告清楚显示“来源已登记或切分，知识尚未抽取”。

**检查**：沿用Cargo检查；在临时项目运行add/list并二次导入，检查版本数和来源文件指纹。失败fixture必须有明确失败结果。

**本轮边界**：不宣称支持PDF，不接OCR、真实API，不把普通文本切分结果冒充全部知识覆盖。
