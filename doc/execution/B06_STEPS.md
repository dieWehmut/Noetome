## B06-T01 从已核对知识主动生成有据比较表

**单一可见结果**：输入只有文字的多个对象及可比属性时，普通 CLI 从实际已核对知识选择比较表，生成有据预览并说明选择理由；无需表格时仍可用正文。

**依赖**：B05-T03 已完成；使用已经验证的 Rust/Python 环境。关联 FR-21、FR-23、FR-25、FR-26、NFR-03、NFR-06，仅覆盖有界比较表达。

### 范围

消费当前版本真正成功保存的协调 IR，重验其原来源/九件依据/身份和原子链，再通过表达规划入口提交 NotePlan 候选。至少实跑 `source_review → coordinate → 表达规划 → 新测试 Vault 预览`。作者输入只提供原文、身份与独立预期，不指定成品表格；不把现有 fixture NotePlan 重命名为主动规划。

先限定明确对象/属性、原值与单位的比较；沿用当前 2 至 3 份各含一个原子的来源边界。例如三份有据事实形成两对象、两属性，其中一项选定事实未给出，必须显示明确缺失。完整条件、例外、来源版本及支持保留；不换算单位、不填推测值。纯排版标签与实质单元格区分，实质标签也须有知识依据。

现有 NotePlan v1 只有 fixture 来源的段落、有序列表、表格。新入口所需 producer、规划理由及原出现映射应显式版本化并独立核对，不放宽旧 schema，也不将 pending 协调原子伪装成 fixture_reviewed 或 published。未决冲突或没有成功 IR 的输入阻断成功预览。

预期修改 CLI 表达规划、现有 NotePlan/渲染映射、独立 Python 核对和新作者 fixture；按调用点增加模块，不提前建立流程图/公式空框架。

### 顺序与验收

1. 冻结公开自造无图文字、原子/行列/单元格独立 expected，再通过普通 CLI 取得真实 RED。至少包括有意义比较、单概念正文、缺失值和未决协调输入。
2. 实现确定性表示选择与完整语义保留，输出计划、预览文件和 JSON/Markdown 双报告；选择理由、每个单元格及必要正文均可回到原出现、原子和出处。
3. 独立从来源/expected 重建实际行列、值、单位、条件、例外与映射。同步篡改两报告/文件/指纹时，删条件、错行列、填零、丢来源或假成功仍须拒绝；实际验证新根、祖先链接、碰撞与外部哨兵。
4. 源码稳定后运行 `cargo fmt --all --check`、完整 `cargo check/test --workspace`、完整 Python unittest、相关 B02/B05 回归和新鲜独立审查。在记录版本的干净 Obsidian 实际打开新 Vault，核对表格、中文路径和表内链接，保存原始输出/渲染与未运行项。

**停止与交接**：全部必要检查通过才 complete、提交推送并核对远端；下一入口为 B06-T02。科学准确率、任意文字理解及生产发布没有在本项验收。

## B06-T02 把有依据的步骤与分支编译为流程图

**单一可见结果**：仅有文字的有据步骤与条件分支，可主动编译为方向和条件正确的流程图；渲染能力不足时保留等效有序文字表示。

**依赖**：B06-T01；关联 FR-21、FR-23、FR-25、FR-26、NFR-06，仅覆盖有界步骤/关系表达。

### 范围

来源先明确步骤顺序、输入输出、分支条件，以及确有依据的因果或正负调控；不从相关性推定因果。每个实质节点、边、方向和条件定位原子或经过独立核对的关系，重要例外进入图或配套正文，不为缩小图形省略。

现有原子仅支持 definition/statement/comparison_value，不能把作者图当作已实现的关系抽取。先为实际需要的过程/关系定义严格版本化的来源表示和独立核对，再接表达规划；旧 B05 v1/v2/v3 保持其语义。不引入通用知识图谱、自动全局实体识别或任意自然语言因果推断。

选择目标 Obsidian 实际支持的有界 Mermaid 流程类型，保留正文中的普通关联。类型/宏不能可靠渲染时回退有据有序列表并记录理由；未支持的循环、方向歧义、无依据或缺关键关系时阻断受影响表达，不以“语法有效”计为成功。

### 顺序与验收

1. 冻结公开自造步骤原文、明确关系依据及独立节点/边/顺序/条件 expected，取得普通 CLI 新行为 RED。
2. 实现受控来源核对到主动流程规划、编译与回退，生成新测试 Vault 和双报告；至少覆盖线性过程、条件分支及不能升级为因果的相关性输入。
3. 独立实际解析节点与边，拒绝同步篡改后的反向箭头、丢负号/分支/例外、虚构因果、丢边依据及假成功。保存至少一次实际渲染回退和一次语义阻断；新根与源文件保护不变量保持。
4. 记录干净 Obsidian 版本及实际 Mermaid 能力，实测图、正文关联和文字回退；完整 Rust/Python、比较表和协调回归、新鲜独立审查通过后保存真实原件。

**停止与交接**：complete、分步提交推送后交接 B06-T03；不把渲染成功当作流程科学正确率。

## B06-T03 保真输出原始 TeX 及公式原图回退

**单一可见结果**：已选取公式的原始 TeX 保真编译；原生表达不能保真时使用可核对的公式原区域，未知关键语义明确阻断成功。

**依赖**：B06-T02；关联 FR-22、FR-24、FR-25、FR-26、NFR-06，仅覆盖明确公式源码/原区域的保真编译与回退，FR-22 为公式原图这一部分。

### 范围

首先使用自造 TeX、符号定义/前提、公式原图及明确选取的区域。保存原始源码字节和指纹；兼容改写另存，来源对照核查上下标、正负号、范围、单位、符号和前提。只有可渲染语法不算语义正确，未确认符号不能替换为常见猜测。

公式原生表达不能保真时，保存可核对公式原图/区域、来源映射、回退原因与必要说明。原区域无法辨认时仍保存原件，但受影响表达需复核或阻断成功。没有原始数据的实验曲线作为禁止虚假重绘的保护输入，不在本卡增加一般图像重现交付。公式原图回退不能洗白未知信息。

只接收已明确选取的本地附件，在新测试 Vault 编译 MathJax 和相对资源引用；不扫描私人目录，不在本项实现 OCR、扫描公式重建或推定 PDF 作者的原始 TeX。资源及表达扩展显式版本化，不放宽既有契约。

### 顺序与验收

1. 先冻结原始 TeX/公式区域、符号/前提及独立 expected，包含不兼容表达、未知符号、可用原图和不可辨原区，再取得普通 CLI 真实 RED。
2. 实现源码/附件保留、有据渲染和回退，并保存来源指纹、编译表达、决策及双报告；原件字节不变，不把未知标为已验证。
3. 通过实际 CLI 和独立矩阵拒绝负号/下标替换、删前提/单位、附件替换/越界、虚假重绘及同步伪造成功。实测资源祖先路径、碰撞、外部哨兵保护，原图不可辨时没有受影响成功记录。
4. 在记录版本的干净 Obsidian 中实际检查 MathJax、图像和本地附件回退，保存语义对照与渲染原件；完整 Rust/Python、表格/流程图回归和新鲜独立审查通过后 complete、提交推送。

**停止与交接**：本批三项全部真实验收后，先按剩余视觉目标滚动细化下一批，再判断 B07 进入条件。一般来源图像重现/重绘、扫描重建、最低/当前稳定版发布兼容矩阵及正式知识质量基准仍是后续必要工作；公式回退不等于整个视觉阶段完成。
