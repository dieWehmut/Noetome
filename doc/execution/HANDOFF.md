# 给后续Agent的接手指南

本仓库已预先定义V1需求、架构、协议、数据、设计与全部任务。这是开发蓝图，实时能力只认账本状态与可复核证据。

用户只说“继续这个项目”也表示执行下面的完整自动循环。测试和技术验收由Agent负责，用户只在必要配置、知识确认和最终体验时参与，见[自动测试安排](AUTOMATED_TESTING.md)。

## 可直接使用的开发指令

> 按AGENTS.md和doc冻结规范，全自动逐项实现Noetome V1。先运行scripts/plan.py next，再show对应任务。每次只做一个任务，完成真实验证、日志和分步commit后推送，再继续下一项。使用已定技术栈和接口，不删需求，不跳过人工保护、真实质量、安装或24小时门禁。按FAILURE_PLAYBOOK有限修复并保留证据；缺凭据或环境时完成可独立进行的工作，准确记录阻塞，不把未运行算通过。不要重新发起架构设计，不增加V1之外功能。

## 第一轮

1. 检查Git状态，读[AGENTS](../../AGENTS.md)。
2. 读[架构](../technical/ARCHITECTURE.md)、[选型](../technical/STACK.md)、[当前状态](../../dev-log/STATUS.md)。
3. plan next选择当前动作，再show对应任务，只加载任务所需标准。
4. start、实现、verify、complete、commit/push、next。

## 固定终点

V1完成多源PDF/文本、可追溯IR、两种模式与有界研究、教材式Obsidian Vault、安全增量维护和Windows桌面版，并通过正式门禁。

P1不阻塞V1：完整阅读器、习题、教学PPT、Agent适配、本地模型部署、云同步、多人协作、新文档格式。扩展接口由技术文档约束，不把这些功能追加为无尽发布前提。

mock可验证工程；真实Provider、独立gold、实机Obsidian、24h不能替代。学科正确性无法由软件测试完全保证，无法确认的事实/图/公式保持问题状态或回退。

## 版本与粒度

库及主系列已定，引入时仅解析官方兼容patch、提交lock和实际版本记录。用户的API服务/model、额度、授权语料与真实环境不能猜测，缺失返回blocked_config。

64张任务卡按一个模块行为或一个正式门禁拆分；若单项过大可以进一步拆小，但保持父验收和全部依赖。每批3–4项，批次通过才进入下批；当前批次可先完成不依赖阻塞项的其他任务。

正式外部质量门禁集中在末期，早期可持续完成离线工程。任务中的产品命令是未来必须达到的要求，不是已实现或已运行的证据。
