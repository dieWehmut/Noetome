# 失败处置与设计修订

防止无限循环、跳过质量门槛与反复重写。失败必须保存输入、实际/期望结果、版本和最小复现，不能提交密钥或私有资料。

| 故障 | 固定处理 | 禁止的捷径 |
| --- | --- | --- |
| 构建/类型错误 | 核对锁文件与接口，局部修复并跑原反例 | 升级整栈、删类型检查 |
| 依赖安装失败 | 按STACK官方渠道、已选系列解析兼容patch | 换框架、非官方二进制 |
| 解析不足 | 原区域保留，needs_review或已定OCR/原图回退 | 空页算覆盖、静默丢图 |
| 模型结构错误 | 按MODEL_CONTRACTS有界纠错、隔离失败 | 无界重试、放宽schema |
| 模型事实错误 | 独立gold反例，修证据/条件/融合链 | 改gold迎合模型 |
| 缺密钥/预算 | blocked_config，继续同批独立本地任务 | 猜密钥、购买额度、fake冒充真实 |
| 发布冲突/占用 | 保存candidate/journal，停该ChangeSet | force覆盖、撤掉锁 |
| 发布中断 | 按PUBLICATION逐hash恢复；未知需复核 | 全库盲回滚、虚报成功 |
| 报告过期 | 保留源码变更，重新verify | 手改report hash |
| 缺gold/实机/安装证据 | 明确未运行与所需环境，保留恢复命令 | 用静态检查替代 |
| 24h/容量失败 | 保存资源时间序列，修后按原规模重跑 | 缩短时间/规模仍称达标 |

## 三轮纪律

一轮包括新假设、最小变更、可反驳测试与观察。同一根因最多连续3轮；无任何新变化的重跑不算进展。

仍失败，在 `dev-log/blockers/<ID>.md` 保存复现、三轮证据、未验证假设、推荐动作和解除条件，devlog block引用该文件。同批独立项可继续；无可执行项时明确报告。不得换模块名掩盖同一故障。

不能因执行能力不足取消人工保护、来源证据、98%门槛、24h或发布事务。

## 必须修订规范时

建立 `doc/decisions/ADR-YYYYMMDD-topic.md`，记录可复现事实、旧规则冲突、最小变更、不变量、迁移兼容、影响任务与新增验证。补正矛盾属于必要工作；重大选型或范围变化先形成可审查方案，再按用户授权处理。

状态历史不改写。已完成任务受影响时，从下游reopen或新增修复任务，保留旧证据；更新定义后重新生成任务卡、追溯和日志。拒绝不影响V1交付的顺手新功能。

## 阻塞报告

列出当前任务、已验证部分、精确阻塞、需要的输入/环境、恢复命令、后续可继续项。缺外部条件不是完成，也不抹去已有成果。
