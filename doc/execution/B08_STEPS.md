# B08 有界研究执行卡

本批从已验收的CLI确定性闭环与可靠维护推进有界研究。进入依据为[B07-T03验收](../validation/B07-T03.md)与[路线图中B08行](ROADMAP.md)：预算、证据、失败隔离已经可测，才允许先候选队列、再批准范围内检索、再写作反馈重编译。任务状态只由账本维护；三张卡依次验收，切批次不自动start。未通过人工保护前持续只写新的测试项目/Vault。

本批把研究限定在"有界"上：不新增通用网络爬取、不接入新的模型提供商、不自动扩充学科分支、不把研究候选当成已完成知识。科学金标准、通用OCR、完整多教材知识编译、生产Vault人工保护与24小时/千页规模仍是独立门槛，下述小型工程验收不宣布个人版或生产发布就绪。

## B08-T01 研究候选队列、授权边界与拒绝记忆

单一可见结果：一轮工作发现越界主题时，新主题只作为候选进入持久队列，本轮已授权目标与必做集合不变；用户对候选的接受、拒绝、延后、合并与改范围被记住，无新理由的重复重提被明确挡回。

依赖：B07-T03。关联FR-11、FR-12、FR-13、FR-28、AC-32、AC-33；仅覆盖候选队列与授权状态的持久化与CLI可解释行为，不表示外部检索、模型研究或科学正确率已支持。

范围：冻结一个公开自造fixture，内含本轮已授权目标、已授权必需前提，以及若干远离批准范围的新主题。候选按FR-13八项字段严格记录（主题、发现原因、与当前目标关系、可能收益、来源线索、预估代价、依赖、状态），并区分"已授权目标／已授权必需前提／新发现可选主题"三类。队列提供列出、登记、审批、合并去重、状态查询的CLI入口；状态机只由显式动词推进，相关性分数只用于排序。

顺序：先以冻结fixture与现有CLI跑出真实RED（当前无候选队列命令）；再定义候选、授权范围与状态转换合同；实现持久队列与去重归并；用越界、重复发现、拒绝后重提、带新理由重提四类样例验证；更新标准、日志、提交推送。

验收：

- 越界新主题只进入候选队列，本轮必做集合与授权范围不被改写；`research_status` 不再是固定值，而是由实际队列结果给出，未启用时仍如实显示未请求。
- 重复发现同一候选归并为同一条并保留两次发现证据（发现原因与来源线索均可追溯到各自的发现事件）；接受、拒绝、延后、合并与修改范围分别可追溯。
- 被拒绝的主题在无新理由时重提失败并留下被拒计数与原因；带新理由重提可以重新进入队列，理由与新证据一并落盘。
- 队列写入可跨进程重读；未知、损坏、非本产品创建或外来替换的根被拒绝并保留现场；队列操作不发起任何检索或模型调用，也不写托管Vault。
- 四维状态与报告能单列研究候选数量与状态，不把候选计入本轮完成或失败（AC-33）；新测试根原件、路径/owner与哨兵在成功和失败后重验。

停止：以上有界行为、独立队列审计和完整Rust/Python回归实际完成后complete、提交并推送。下一入口T02；不直接扩大到真实网络检索、真实模型研究、生产Vault或学科分支扩张。

## B08-T02 批准范围内的有界检索与终止理由

单一可见结果：只对已授权候选在明确范围内检索，检索前先持久预留预算，到限或满足条件时以七类终止理由之一停止，中断后恢复不重复结算同一检索；关闭外部检索时零网络请求。

依赖：B08-T01。关联FR-11、FR-12、FR-13、FR-36、FR-38、NFR-15、AC-31、AC-32；只接一个明确的本地合成语料检索适配器，不接真实互联网抓取。

范围：使用冻结的本地合成语料（自造公开短材料，非用户私人资料）作为唯一检索源，检索单位、查询、命中与代价均可独立核对。预算维度为次数、字节与耗时，写入前持久预留。终止理由是显式枚举的七类：目标满足、无可靠新证据、边际收益不足、预算不足、用户暂停、网络受限、需要人工判断。资料驱动模式关闭外部检索时，检索适配器必须被真正禁用而不是被绕开。

顺序：先冻结合成语料、检索语义与预算expected，并用现有CLI记录真实RED（无检索入口）；再定义检索范围、预算预留与终止理由合同；接入唯一适配器并复用既有预算存储语义；实际测量近限额并发、七类终止、中断恢复与关闭外部检索；完整回归、标准与日志收束。

验收：

- 只有已授权候选进入检索范围；越界主题即使被检索命中也不扩大授权，只回到候选队列并记录新证据线索。
- 每次检索先持久预留（次数/字节/耗时）；至少两个并发单元近限额时不能各取全部剩余额度；到限停止新调度，在途与未完成状态明确显示，不以预算耗尽报告研究完整。
- 关闭外部检索时实际网络请求为0，缺口保留为待核验项且报告可见；联网失败同样归入网络受限理由，不静默降级为"没有新证据"。
- 七类终止理由每类至少实际产生一次并落盘；真实中断后从检查点恢复，同一逻辑检索只结算一次，不同检索即使命中正文相同也分别计量。
- 检索结果只作为候选与目标的证据线索，不直接写知识库、不写托管Vault、不把外部材料当可信指令（NFR-15）；通过独立预算/证据审计与完整Rust/Python回归。

停止：限定适配器与持久预算闭环完成后complete、提交推送，下一入口T03。接入真实互联网检索、真实付费模型或扩大语料范围须另行明确小预算与验证，不由此卡自动授权。

## B08-T03 写作反馈缺口回到修订与依赖重编译

单一可见结果：写作、表格或绘图阶段发现的必要缺口被记录为带来源与影响范围的问题并回到修订流程，修订生成新IR版本后重编译所有声明依赖的表示，未受影响的表示字节不变。

依赖：B08-T02。关联FR-14、FR-28、FR-35、AC-34；限定一个明确的小型表示集合（一个反应原子、一张表、一段正文和它们的追溯关系），不扩大到全部知识命令或完整知识图谱。

范围：以现有fixture编译流程为基础，增加缺口问题持久记录（来源、影响范围、发现阶段、状态）与修订循环计数。缺口问题与B08-T01的研究候选是不同实体，不能互相顶替：缺口必须由证据修复，不能用"再研究一下"无限延期，也不能用无来源补句直接发布。

顺序：先冻结一份已知缺参数的表示集合与修订expected，用现有CLI跑出真实RED（缺口不会自动回到修订流程）；再定义缺口问题、修订版本与依赖重编译合同；实现修订经核验生成新IR版本并重编译依赖表示；验证无来源补句被标待核验、循环上限升级与未受影响表示字节不变；完整回归、标准与日志收束。

验收：

- 表格/正文发现必要参数缺失时创建带来源与影响范围的问题，修复同时更新反应原子、相关表格、正文和追溯关系，而不是只改一份笔记（AC-34），缺口位置与受影响集合可独立核验。
- 无来源支持的"为顺畅而补"事实被标为待核验，不发布为结论；缺口未修复前相关表示状态如实显示为不完整，不以重编译成功代替知识正确。
- 修订经核验生成新的IR版本，依赖重编译只触及声明依赖的表示，未受影响表示保持原字节；旧版本与修订原因/结果保留可追溯。
- 同一问题反复修订记录版本、原因和结果，超过可配置上限时自动升级问题等级；无新证据时拒绝再次推翻已核验结论，不进入无限循环（FR-35 检查点与未完成目标保留）。
- 四维状态与报告同时反映缺口、修订和重编译结果，且JSON与Markdown表达相同计数；通过独立审计与完整Rust/Python回归。

停止：本表示集合的缺口—修订—重编译闭环验收后complete、提交推送，再依据真实剩余研究与表达质量问题滚动规划下一批；不直接宣布完整个人版发布、接管用户生产Vault或宣称科学正确率达标。
