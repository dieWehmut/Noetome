## 一个明确来源与一个识别方案

独立作者先制作公开自造、CC0 的单页扫描样例：有界标量分式及真实页上符号定义、单位、前提、范围和例外。清晰页、负号缺损页和下标缺损页是同一个作者用例的三个扫描状态；不是三份真实文献或科学准确率分母。原页 PNG、确切裁剪区域、归档 PDF 和独立 expected 必须先冻结，再取得普通 CLI RED，最后才运行识别。修改原件或预期须先说明理由，保留旧版本和失败。

最初固定 pix2tex 0.1.4、依赖、四份模型文件和实际策略，在冻结清晰页上经过六轮有据修复、十二次实际调用仍有额外横线、错误变量或关系；没有等价重建通过。原响应、策略源码、派生像素诊断、锁定环境和失败全部封存。作者页与 expected 没有改动，没有删符号或以安全阻断代替清晰成功。

最终唯一活动方案替换为已授权的同一糖猫云 `deepseek-flash` Chat 视觉接口，不保留自动第二模型回退。当前 DeepSeek 官方资料已声明该别名支持图像，见[能力页](https://api-docs.deepseek.com/quick_start/pricing)与[视觉协议](https://api-docs.deepseek.com/guides/vision)。客户端接口/别名/策略与实际请求字节固定，网关底层权重和精确版本未独立证明，不能虚称权重锁定；实际视觉识别仍必须验收。

真实请求前复用已有累计 10M Token 授权和明确凭据引用，逐次预留、实际 usage 结算，不批量或自动重试。原位置的设置、累计账本和 DPAPI 三文件曾实测缺失；用户现已指示未知新增用量按0处理并重新输入密钥。按[恢复依据](../requirements/MODEL_SERVICE.md)完整保留六笔累计30,097记录，外部文件实际恢复、真实凭据零请求解密预检通过后才继续有界请求。恢复基线明确是用户指示下的假设，不声称缺失期间用量或服务端余额已独立核实，不新建假零使用量或重置10M。

## CLI 与来源边界

```text
noetome knowledge scan-formula <scan-case目录> <api-config.json> <profile.json> <尚不存在的新测试Vault>
```

scan case 使用独立 Schema1，明确 selection、整页 PNG、页号/画布、区域 PNG 与矩形、可辨性、手工来源语义及可选归档 PDF。清单严格且所有附件为普通直接子文件，拒绝未知字段、重复键、链接、硬链接、越界、碰撞、身份及字节变化。

定位以实际整页 PNG 像素坐标为依据，区域 PNG 必须逐解码像素等于该页矩形。可选 PDF 保存原始字节；本入口不把调用者的页号和 PNG 声明当成通用 PDF 页面解析验证。独立作者审计另行检查本用例归档 PDF 与原页的一致性，并明确此层证据的范围。

api config 为严格独立 Schema，明确同一服务/别名/外部凭据引用、视觉能力、时间/字节与单请求 Token 上限。模型请求只包含固定转写任务和明确区域 PNG 的内联图像，不携带来源手工语义、独立 expected 或生成样例的源码。来源声明中的表达是手工语义转写，不能称为识别结果或作者原始 TeX。

## 识别、核对与表达

单个有界 HTTP 请求返回未经手工修补的识别文本与原响应，实际状态、finish、返回 model 和有效 usage 分别核对。复用现有 Rust HTTP 的无重试/重定向、时间和字节保护；本地数字环回假服务与真实提供商/计量分开，不能将 fake 或接口预检计成模型成功。缺用量保留未知预留，费用未知不填零。

Core 在识别返回后才按既有有界数学语法核对手工来源语义，保留负号、变量、分子/分母、上下标和关系方向。只允许明确检查的等价规范化，例如单操作数脚标的括号形式；记录每项改写，不用外观相似或模型自信通过。

清晰且语义一致时才选择已验收 Obsidian 1.6.7 / MathJax 3.2.2 的重建表达，或在目标能力不足时使用原区域图片。来源关键符号不可辨、语义未知或识别不一致时阻断受影响表达；即使识别器猜出清晰页答案，也不能把缺损页洗成成功。

新测试 Vault 保存原件、来源声明、profile、实际请求/原响应/诊断和 JSON/Markdown 双报告。成功另存识别表达、等价编译表达、计划和预览；阻断保留原区域及问题，不留下成功计划或编译预览。输出保持知识 pending、科学验证 not_run、published=false。
