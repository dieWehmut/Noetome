# B07 有界可靠维护执行卡

本批从已验收的CLI确定性闭环推进可靠维护。进入依据为[B06V-T03验收](../validation/B06V-T03.md)及[独立进入评估](../validation/assets/B06V-T03/review/b07-entry-assessment.md)。任务状态只由账本维护；三张卡依次验收，切批次不自动start。未通过人工保护前持续只写新的测试项目/Vault。

科学金标准、通用OCR、完整知识编译、多教材规模和个人桌面长任务指标仍是独立门槛。下述小型工程验收不宣布个人版或生产发布就绪，不新增模型提供商或审批GUI。

## B07-T01 一个固定有限流程的持久检查点与恢复

单一可见结果：一个明确冻结的确定性fixture流程被强制终止后，可从持久检查点继续，已确认单元不重复产生结果，暂停和取消状态可解释。

依赖：B06V-T03。关联FR-35、FR-40、NFR-08、NFR-13、AC-26；仅覆盖明确小型CLI流程，不表示全部知识命令或24小时任务已支持。

范围：先冻结一个有限工作图及独立输出expected，复用现有fixture校验、编译和结果核对。新增严格版本化Run/WorkUnit持久状态、输入/依赖/策略/编译版本与输出指纹、阶段检查点，提供该流程的启动、状态、暂停、继续和取消入口。Run与已有fixture compile及项目Schema的关系必须明示，未知或无owner的旧残留不自动接管。

顺序：先保存普通现有CLI无法从旧运行现场继续的实际RED；定义合同及有限图；实现必要状态机与持久边界；完成真实中断/恢复及独立审计；更新标准、日志、提交推送。预期修改集中在noetome-cli执行/存储及相应测试，不建立通用调度框架。

验收：

- 在每个可提交边界真实终止进程，重启后复用已经确认的单元，规范内容文件和稳定知识/计划ID与从头确定性执行一致；run/release UUID、时间及attempt审计记录分别保留，不要求非确定审计字节相同，不重复创建确认结果或发布成功。
- 暂停按NFR-13在2秒内停止新单元调度；在安全边界落盘，已在途单元及安全落盘状态明确显示。取消保留已确认结果；暂停/取消请求与进程退出分别保存，不以单个内存flag充当恢复证据。
- 输入、配置或版本变化使依赖结果失效；损坏、未知、外部替换或不可信检查点明确拒绝并保留现场。输出原件、所有权、祖先/碰撞、外部哨兵在成功和失败后重验。
- 失败/未验证与发布状态分开；新测试根中逐项比较恢复结果，执行完整Rust/Python、必要旧行为回归和独立源码/状态机审查。

停止：以上有界行为及实际检查完成后complete、提交和远端核对。下一入口T02；不直接扩大到真实批量API、生产Vault、睡眠恢复或性能规模。

## B07-T02 持久预算预留下的有界重试与隔离

单一可见结果：同一既有单请求适配器在持久预算约束下重试允许的故障，恢复不重复结算，未知远端完成保留承诺，不依赖坏单元的工作可继续。

依赖：B07-T01。关联FR-36、FR-38、D08、AC-29、AC-30；仅一个明确适配器和固定数字环回测试服务。

范围：使用人工凭据及synthetic HTTP响应测试429/5xx、超时、断连、结构错误与有效响应。保存attempt/预留/结算/未知状态，重试次数、Token、耗时及退避均有上限。真实模型和付费调用为0，既有累计授权不重置；价格未知保持null。

顺序：冻结故障策略、响应与预算expected；定义Run预算和attempt合同；接入一个既有单请求适配器；实际HTTP时序、并发近限额及中断/恢复审计；完整回归、标准和日志收束。

验收：

- 发请求前持久预留；至少两个并发单元的近限额场景不能各取全部剩余额度。到限停止新调度并保留在途/未完成状态。
- 只有策略允许的故障重试；退避、次数和独立预算实际测量。未知远端完成不报告零计费或释放全部承诺，错误JSON不进入知识库。
- 同一逻辑attempt/请求的确认响应在重复交付、重启、结算边界中断后只结算一次；不同请求即使响应正文SHA相同也分别计量。单元重试上限耗尽可隔离，不阻断仍有全局预算的独立单元；Run或全局预算到限则停止所有新请求。
- 原请求、响应和用量可由独立审计重建；输入/预算/哨兵保护及完整Rust/Python通过。离线结果不代替真实网关恢复或供应商账单保证。

停止：限定策略与持久预算闭环完成后complete、提交推送，下一入口T03。扩大模型/网关或真实重试另行明确小预算及验证，不以本卡自动授权。

## B07-T03 明确托管测试集合的人工审批与可恢复发布

单一可见结果：一个小型明确托管笔记/附件/链接集合更新时保护人工改动，审批绑定当前字节，发布中断后恢复为可核对一致版本或明确待恢复。

依赖：B07-T01、B07-T02。关联FR-29至FR-34、NFR-07、NFR-08、NFR-14、AC-21/22/24/25/27/28；限定新的小型测试Vault及CLI/机器可读审批，不接管生产Vault。

范围：至多两笔记、一个PNG及明确列出的链接、修改、删除、重命名操作集合。保留上次发布基准、当前磁盘、新候选三方字节和完整影响清单。记录明确批准/拒绝，批准绑定磁盘指纹、候选/配置版本及影响范围；写前再读使后续人工编辑令批准失效。发布暂存重验资源/链接/索引，以可恢复日志逐项落盘，只有一致性确认后标成功。已有或陌生Vault没有可信旧基准时仍只读；新的owner测试集合先以现有新根编译流程建立并独立验证初始基准，再提出更新，不把陌生内容导入当成本卡能力。

顺序：冻结有限托管集合和人工编辑/附件/重命名/陌生文件expected；定义基准、差异、审批及发布合同；实现一个小型CLI闭环；逐发布边界真实进程终止、文件占用/外部写入与恢复验证；独立三方原件审计、完整回归、标准及日志收束。

验收：

- 未批准覆盖次数为0；人工结构、正文、位置、链接、删除和附件影响均进入候选隔离。拒绝可追溯且重试不自动重新应用，无关明确安全工作可继续。
- 审批后再次编辑使批准失效；陌生笔记、插件/Obsidian配置、无关附件保持原字节。候选依赖未批准时不先移走目标或留下假成功断链。
- 每个落盘边界实际故障后恢复为一致版本或待恢复；回滚也识别发布后的人工改动并绑定针对性批准，不覆盖整库。
- 新测试Vault完整原件、路径/owner/哨兵和三方审批审计通过，执行完整Rust/Python及受影响表达回归。生产人工保护、千页/万原子、3000笔记/200人工改动和24小时规模仍另行实测。

停止：本集合的批准和恢复发布全部验收后complete、提交推送，再依据真实剩余维护/质量问题滚动规划下一批；不直接宣布完整个人版发布或接管用户生产Vault。
