## 判定规则

- `confirmed`：有实际失败、直接运行结果，或历史验证明确限定的已确认能力缺口。证据须说明是哪一种；“确认尚未验收”不等于“运行后必定失败”。
- `staticrisk`：从当前代码路径或上限识别的风险，尚未完成对应真实操作复现。不得写成已发生的数据损坏、费用丢失或科学错误。
- 已有单元测试、确定性作者样例、环回假服务和有界真实 API 是不同证据。样例及假服务仍保留，不改写成真实教材金标准。
- 原件获取、页面解析、知识覆盖、研究候选和发布分别计量。`acquired` 不等于解析成功，生成候选不等于知识核验通过，失败或待复核不计为已完成覆盖。
- 一项在支持范围内运行失败时，保留失败及恢复现场。资源控制应作用于分批、并发和暂停；不能把全书截断为样例上限后报告成功。
- 原子召回、科学事实及图示语义的独立验收仍按 [PRD](../requirements/PRD.md) 和 [TESTING](../standards/TESTING.md)，不能用模型自评或代码作者自己的输出作唯一判据。
