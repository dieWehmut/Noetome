# 从当前测试版到完整个人版的 Release 路线

采用日期：2026-11-12。依据用户已批准的连续推进计划：先整合既有成果与已知问题，再修复真实整书链路；直接采用成熟 PDF/OCR 系统，使用当前电脑的 GPU；允许中间版本功能不完整，但最终保留 [PRD](../requirements/PRD.md) 的全部原始产品目标。当前任务与状态仅见 [tasks.json](../../dev-log/tasks.json)，已知问题和能力证据见 [KNOWN_GAPS](KNOWN_GAPS.md)。

本路线补充 [滚动批次路线](ROADMAP.md) 的产品交付视角。历史批次完成代表当时限定范围的工程验收，不代表真实教材、完整 GUI 或全部 P0 已通过。未来阶段只定义目标与放行条件；每批最多展开三个详细任务，同时仅一个 `in_progress`。

## 产品目标不变

Noetome 的目标是把真实资料编译成适合用户水平与风格、可追溯并可长期维护的知识笔记。书、章、页和区域用于解析与调度；稳定概念、条件化原子及证据用于融合与编译。最终按概念关系、教学顺序、阅读目的组织笔记，同一概念保留一个完整规范解释位置，其余位置链接或同源嵌入。

因此，整书自动处理不能止于逐章摘要，也不能把每次模型响应独立导出后拼接成库。概念身份、原子条件/单位/例外、来源版本、全局页号和区域坐标必须贯穿来源层、生产 IR、NotePlan、正文、主动图表、查询与后续修订。少字风格不得减少必要知识；图片必须检查，识别不确定的公式/图示保存原区域并进入明确问题，不能因为保留了原图就标为已经理解。

原件获取、页面处理、知识覆盖、研究候选、发布状态分别显示。困难页面可以使中间测试版保持“部分完成/待处理”，但必须全量入队并对账，不能静默遗漏。支持范围内的真实操作应有可重复闭环；损坏、密码、服务故障及无法核验内容应有明确失败/恢复方式。任何版本都不以有限测试保证任意文件必然识别正确。

## 现成 PDF/OCR 的已采用方向

**首测基线为 MinerU 4.2.1，Windows 原生 ONNX + llama.cpp，使用 `standard`；同一批代表页以 PaddleOCR 完整布局 + VL-1.6 管线对照。Docling 保留为备选，本批不另建第三套接入。** 这是进入实测的决定，不是质量、吞吐或资源占用的既成结论。官方当前版本与接口在 2026-11-12 查证；后续安装时记录精确依赖和模型 revision，不使用漂移的 `latest` 作为验收身份。

| 方案 | 已核实官方事实 | 对本机选择的影响 |
| --- | --- | --- |
| MinerU 4.2.1 | 基础包为 ONNX + llama.cpp；`standard/advanced` 官方表列约 2 GB 模型、8 GB RAM、CPU 可运行且建议 Vulkan。Torch 高吞吐路线要求 16 GB RAM、8 GB 以上可用 VRAM；Windows full 使用 LMDeploy、Linux 使用 vLLM。[固定版本说明](https://github.com/opendatalab/MinerU/blob/mineru-4.2.1-released/README.md)、[扩展后端](https://github.com/opendatalab/MinerU/blob/mineru-4.2.1-released/docs/en/quick_start/extension_modules.md) | 原生 Windows 路线避免占用当前紧张的 WSL 内存；先测实际 ONNX provider 与 llama.cpp GPU 后端，失败/回退 CPU 要明确记录。官方资源表没有给该基础组合统一最低 VRAM，不能直接声称 12 GB 已通过。 |

第三方解析结果通过 Noetome adapter 进入来源层：保留不可变原件 SHA、parser/模型/参数版本、全局页号、页尺寸、旋转/裁剪变换、区域 bbox、阅读顺序、原图资产、文本/公式/表格结构和原始诊断。MinerU Middle JSON 的 `page_idx` 从 0 开始，而 CLI 页范围从 1 开始；服务输出和 Noetome 定位必须显式归一化并用叠框核对。独立分批不得把批内页号当原书页号。[MinerU 输出契约](https://github.com/opendatalab/MinerU/blob/mineru-4.2.1-released/docs/en/reference/output_files.md)

## 32 页比较与整书来源闸门

B16-T02 从用户已选目录冻结 **32 个代表页**，列表绑定源 SHA 和物理页号，同一页可属于多类。样本覆盖中文/英文扫描、原生文字、双栏/复杂阅读顺序、低清/歪斜、密集上下标/希腊字母/负号、化学反应箭头、表格表头/合并格/单位/脚注、跨页表格相邻页、带图内标注的科学示意图、流程图、图注与正文对应。不得只挑有文本层的容易页。

在运行候选前冻结人工检查项及“关键”内容，两个候选使用相同原件和页面条件。记录正文漏字/漏行与顺序，公式关键符号，表格单元格关系/数值/单位，图内文本与图注归属，全局页号和 bbox 叠框。错误合并、缺负号/下标、换单位、丢条件不能被整体平均分掩盖。若不能准确恢复，必须保留原区域并有问题状态；这种正确隔离是工程通过，不是识别正确。

同时记录冷启动与模型准备时间、逐页耗时、峰值 RAM/VRAM、实际 GPU provider、渲染 DPI/批大小、输出及缓存大小、失败/超时/取消/重启结果。先串行文档、小批页面；根据真实资源记录调整并发，避免每本书常驻一套模型。不能在未测前承诺“每本几分钟”或固定成本。

32 页合格后，再对原报错 1227 页教材、722 MiB 扫描本和 3648 页文字本逐本做整书来源处理，核对以下分母：

1. 原件选择数、可打开/不可打开数量、物理页总数、入队页数和每页最终状态一致。
2. 每页文字/表格/公式/图片区域都有可追溯结果或明确未解决问题，任何空结果都有可审计依据。
3. 暂停、强制结束 worker/CLI、退出应用再恢复后，已持久页可复用，没有重复计数、丢页或坏缓存被当成功。
4. 下游读取、模型选择、导出大原件和移动输出的策略一致，不能只测解析命令成功。

目录的 75 份先逐文件预检并保留结果，后续按队列推进；不要求将 75 本全文一次载入内存或模型上下文。正式知识编译对每个项目定义目标和范围，不因 OCR 处理了全页就声称必要知识已全部覆盖。

## 每个 Release 的真实使用循环

每个版本沿同一循环执行：**冻结输入和预期 → 构建安装 → 原生操作 → 独立核对 → 记录问题 → 修复 → 用原失败输入重跑 → 通过该版门槛后交付。** 自动化用于重复真实操作和检查；脚本直接调用 CLI 或填入结果路径时必须标清，不能替代用户会走的原生按钮链。

1. **冻结与预检。** 保存源码 SHA、配置/模型/解析器版本、输入 SHA、页清单及独立检查项。应用页面在动作前显示实际格式、密码、大小/资源、OCR/模型能力和预算限制，不能依赖用户读开发文档猜边界。
2. **安装后首次使用。** 用本次安装器安装，在当前用户环境普通启动；从系统选文件器新建项目并选择真实资料。确认无开发工作区隐式资源依赖。离线自检单列为样例检查，不替代真实资料。
3. **运行真实链。** 预检、整书分批处理、必要模型调用、生产 IR、规划/正文/图表、问题与覆盖账本均通过应用入口；检查进度持续可见，失败可解释。请求沿用已授权服务及累计 10M Token，未知价格不虚构费用。
4. **主动打断与恢复。** 在解析、请求在途、结果落盘和编译阶段暂停/退出/结束进程，重开项目继续；记录停止新调度时间、已确认产物、未知用量预留、重试上限和重复工作量。
5. **独立读回与阅读。** 检查原件/IR/笔记之间的事实、条件、单位、公式、图示、来源定位和链接；导出新测试 Vault，在干净 Obsidian 的最低支持版与发布时稳定版实际打开/点击，保留精确版本和产物指纹。新增知识与界面不能仅沿用旧截图。
6. **问题闭环。** 给每个失败关联 GAP ID 或新增 ID，区分已复现与静态风险；修复后先重跑同一失败输入和相关回归，再继续下一步。必要图文无法核验时仍保留问题，不能改预期、减少分母或将待核验写成成功。
7. **交付与回溯。** 发布安装器、SHA256 清单、源码锚、简明操作步骤、实测范围和未闭合清单；附可核验日志/清单的归档入口。仓库提交摘要和指纹，大型构建/截图/日志/数据保存在忽略目录或版本归档。对历史失败和旧报告只追加说明，不覆盖原件。

0.4 起循环还包含真实笔记人工编辑、差异审批/审批过期、来源换版、归并撤销、发布故障、回滚及非托管内容保护；0.5 起包含禁外部检索、范围控制、真实研究终止和写作反馈修订。所有阶段都使用新的选定测试 Vault，未完成对应人工保护验收前不接管用户生产 Vault。

## 完整个人版放行条件

[PRD 第 16 章](../requirements/PRD.md) 的 AC-01–40 和全部适用 P0 必须在集成版本中验收，且保留各条的模块、真实资料、GUI 与独立验收证据，不能以历史任务数量代替。正式基准按同学科部分重叠三份资料建立，含扫描、复杂图、表格、公式和另一个数学推导领域；至少 200 原子、20 组身份/冲突、20 个图表/公式作为起始独立基准，并随失败持续扩充。

必要原子召回至少 98%、关键原子 100%，事实和适用条件抽样准确率至少 98%；所有已知必要遗漏仍阻止该轮覆盖完成。已发布实质原子的证据映射完整率和范围内链接有效率均为 100%；关键图表/公式逐项通过或按规则回退/阻断，严重事实错误零未处置。人工改动未批准覆盖零次，检查点/发布恢复/回滚符合声明范围。

容量与运行须真实达到三份资料合计 1000 页、10000 原子、1000 笔记端到端；3000 笔记含 200 人工修改的真实界面影响/差异分页；常规交互 P95≤2 秒、暂停/退出≤2 秒停止新请求；连续 24 小时解析/API/编译混合运行及睡眠恢复，无不可恢复损坏和无界资源增长。兼容版本、设备、网络/提供商和成本分别记录，未测平台不计通过。

这些条件是原始产品目标的验收依据。中间版可以提前交付以便用户测试，最终不得把尚未完成的要求从路线或分母中删掉。
