# 分阶段开发路线

本计划追求每轮有小成果且不破坏已验证能力。它把 [PRD里程碑](../requirements/PRD.md) 拆成可滚动细化的批次，不一次展开全产品任务树。

## 执行节奏

- 一次普通开发请求默认完成一个近期任务；可以包含必要的实现、测试、修复和提交子步骤。
- 同时最多一个任务进行中。可并行做同任务内的独立审查或实现，不能让多个代理各自启动下一阶段。
- 一个批次最多3个详细任务。当前批次全部验收后，根据实际结果展开下一批，不提前锁死远期接口。
- 用户明确要求连续推进时，可顺序执行多个任务；每个任务仍独立验收、记录、提交，不能跳过失败点。
- 不用固定小时数承诺进度。任务一旦需要多个独立能力或大量跨模块修改，先拆成更小任务卡。

## 阶段目标

| 批次或阶段 | 小成果 | 进入条件 | 不在该阶段提前做的事 |
| --- | --- | --- | --- |
| B00 开发工作基础 | 标准文件、AGENTS、可校验任务账本 | 当前用户授权 | 不启动产品代码 |
| B01 CLI与可安装桌面骨架 | 帮助与版本、空项目、使用指定图标的Windows桌面骨架及本地安装实测 | B00完成；用户明确要求提前桌面交付 | 不接模型、PDF或完整知识生成 |
| B02 第一个确定性输出闭环 | 先补单份UTF8文本来源清单，再接少量IR fixture、NotePlan、输出到新临时Vault | B01完成，实际契约复查 | 不宣称AI抽取和增量维护成熟 |
| B03 文本PDF验证 | 一页到多页的解析、定位、重复导入和失败记录 | 本地闭环可重复 | 不同时实现扫描OCR和全部格式 |
| B04 第一次真实知识抽取 | 先fake契约，再小文本真实API，再证据核对 | 来源链可靠，模型配置和预算具备 | 不立即长时间批量调用 |
| B05 跨资料知识协调 | 先重复和互补，再条件差异，再真实冲突 | 单来源可准确追溯 | 不先做复杂自主研究 |
| B06 表达和视觉保真 | 先主动表格，再流程图，再公式与图像回退；扫描PDF分独立任务 | 知识和计划契约稳定 | 不以漂亮输出代替语义校验 |
| B07 可靠维护 | 先检查点，再预算重试，再人工差异和安全发布 | 已有闭环稳定，测试资产足够 | 人工保护通过前不写生产Vault |
| B08 有界研究 | 先候选队列，再批准范围内检索，再写作反馈重编译 | 预算、证据、失败隔离已经可测 | 不无限扩张范围 |
| B09 完整个人桌面版 | 在已有桌面骨架上依次接项目、配置、任务、来源与审批界面，完成个人版打包验收 | CLI关键P0用例通过 | 不同时做完整阅读器 |
| B10 后续扩展 | 新格式、Agent、领域包、教学输出等 | 个人版质量与长期使用反馈 | 不把远期目标自动放入当前批次 |

B02之后是滚动规划目标，不是可以直接启动的大任务。下一批创建时按 [任务模板](../templates/TASK.md) 拆到单一可验证行为，再加入账本。每批结束最多展开下一批3项；超出部分继续保留在本表。

2026年11月1日的[用户指令调整](../requirements/DECISIONS.md)将可安装桌面骨架提前到B01。B01-T03尚未启动时重新定义为该交付，B01-T02空项目继续保留，原单份文本导入进入B02阶段目标。这个顺序调整不取消文本、PDF和完整个人桌面版的验收要求。

## 每个阶段的继续条件

1. 当前任务卡中的验收和必要回归都已实际运行；失败已修复或如实标为阻塞。
2. 开发日志与文件产物一致，未把计划、fake、跳过测试或未运行工具算作完成。
3. 新增Schema、接口或用户行为已更新对应标准，不靠聊天历史维护隐性决定。
4. 工作形成明确提交，工作区没有不明改动；检查完成后推送当前分支。
5. 下一步基于实际剩余问题选择；若存在影响正确性或数据安全的回归，先修复，不叠加功能。

在真实PDF与API阶段逐步建立正式基准资料包，最终仍需通过PRD规定的质量、人工保护和长任务门槛。早期小批次验收不能替代个人可用版的完整验收。
