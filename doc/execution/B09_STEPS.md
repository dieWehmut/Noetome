# B09 完整个人桌面版执行卡

本批从已验收的 CLI 确定性闭环、可靠维护与有界研究推进桌面个人版。进入依据为[路线图中 B09 行](ROADMAP.md)与已验收的[B08 三项](../validation/B08-T03.md)：CLI 关键 P0 用例已通过，桌面骨架（工作台、运行检查、设置、托盘与关闭行为）已安装可用，才允许依次接项目入口、任务中心与打包验收。任务状态只由账本维护；三张卡依次验收，切批次不自动 start。

本批只做"把已验收的 CLI 能力如实接到桌面"，不同时做完整阅读器、不做编辑器、不新增模型提供商、不写生产 Vault、不扩展学科分支。桌面前端只能投影 Rust 侧真实返回，不允许在 TypeScript 里重算状态、推测成功或伪造进度。科学 200 原子/98% 基准、通用 OCR、完整多教材知识编译、生产 Vault 人工保护与 24 小时/千页规模仍是独立门槛，下述工程验收不宣布个人版就绪或生产可用。

## B09-T01 桌面项目入口与真实工程状态

单一可见结果：工作台可以从桌面新建一个项目，并在随后重新打开它时显示实际的项目 ID、结构版本、创建时间、初始化状态与数据库文件名；已存在、未初始化完成、损坏或外来的目录被拒绝并保留现场。

依赖：B08-T03。关联 FR-01、FR-06、FR-27、NFR-14、NFR-17；只覆盖项目根的新建与只读检查，不覆盖资料导入、来源登记或知识生成，也不把资料处理状态当作已实现。

范围：新增一组受限的 Tauri 命令，把 `noetome_cli::project::initialize` 与 `noetome_cli::project::inspect` 的真实结果投影给前端。路径由系统文件选择器给出，Rust 侧仍走既有 `check_components` 规范化与符号链接/越界拒绝，不新增写入路径、不新增目录权限、不写用户原文件。前端新增"项目"页与工作台入口，替换当前"建立学习项目：尚未接入"的空状态。新建成功后显示真实字段；失败显示既有错误码与原因，不猜测可修复。

顺序：先以当前桌面构建跑出真实 RED（工作台无项目入口、`runtime_info.capabilities` 只有 `help`/`version`）；再定义命令签名与返回结构（成功字段、错误码原样透传、路径只作显示）；实现两条命令并在 Rust 单测里覆盖新建/已存在/未初始化/外来布局四类真实返回；接前端项目页、空状态与错误显示；用 `tsc --noEmit`、`vite build` 与既有 workspace 测试验证；更新标准、日志、提交推送。

验收：

- 新建项目只接受尚不存在的新目录，实际生成 `project.json` 与 `project.sqlite`；返回的 `project_id`、`schema_version`、`created_at`、`state`、`database` 与磁盘内容一致，前端不做二次拼装或生成。
- 打开已有项目走 `inspect`：未知目录、未初始化完成（残留标记）、损坏配置、外来布局分别返回既有错误码（如 `PROJECT_PATH_EXISTS`、`PROJECT_INCOMPLETE`、`PROJECT_INVALID_CONFIG`、`PROJECT_UNSAFE_PATH`）并保留现场，界面显示可定位原因。
- 桌面层不新建写入路径：命令只调用既有函数，不自行 `create_dir`、不删除、不移动、不写日志含路径以外的敏感信息；不联网、不调用模型、不创建 Vault。
- 前端 `tsc --noEmit` 与 `vite build` 实际通过，Rust 单测覆盖四类结果且测试根外哨兵在成功与失败后都复验；`cargo fmt --all --check`、`cargo check --workspace`、`cargo test --workspace` 结果如实记录。
- 验证记录明确列出未运行项（本环境未运行 Windows 原生安装内的交互测试）；通过后 complete、提交并推送。

停止：项目入口与真实状态投影、Rust 单测与前端构建实际完成后 complete、提交推送。下一入口 T02；不直接扩大到资料导入、来源登记、知识生成、GUI 审批或生产 Vault。

## B09-T02 桌面任务中心只读投影

单一可见结果：任务中心能列出 run、research、retrieve、revision 四类既有根的真实状态；未建立显示未建立，损坏显示实际错误码，研究候选、检索终止理由、缺口与修订结果分别单列而不计入主任务完成或失败。

依赖：B09-T01。关联 FR-28、FR-35、FR-39、AC-33；只读投影，不新增调度、不新增持久化、不改变任何账本格式。

范围：新增只读命令，复用 `fixture_run::status`、`research_store::list/status`、`retrieval_store::list/status`、`revision_store::list/status` 的既有返回；前端解析其中的 JSON 与文本摘要，显示四维状态、计数与终止理由，不重算阈值。四维状态口径必须与 CLI 报告一致：分母为零显示"不适用"，未启用研究显示"未请求"或"不适用"，不显示 0 或百分比。任务中心提供根路径选择与刷新，不做后台轮询。

顺序：先以当前桌面构建跑出真实 RED（无任务中心入口）；再定义只读命令与返回结构（成功、未建立、损坏三类显式区分）；实现命令并在 Rust 单测里对四类根分别覆盖成功/缺失/损坏；接前端任务中心页并复用既有 `StateBadge`、`console-panel` 视觉；用 `tsc`、`vite build`、workspace 测试验证；更新标准、日志、提交推送。

验收：

- 四类根的状态显示与 CLI 一致：run 显示阶段/进度/控制状态，research 显示必做集合和候选五态，retrieve 显示预算使用与七类终止理由，revision 显示 IR 版本、缺口状态与修订次数。
- 未建立、损坏、外来布局三类分别显示真实错误码（如 `RESEARCH_UNKNOWN_ROOT`、`RETRIEVAL_UNKNOWN_ROOT`、`REVISION_UNKNOWN_ROOT`、`PROJECT_INVALID_DATABASE`），不显示成空任务或成功。
- 只读投影零写入：读取前后对每个根做快照比对，字节与条目集合不变；不调度新请求、不调用模型、不写 Vault。
- 四维状态与报告口径一致：候选、终止理由、缺口与修订结果单列；分母为零显示不适用；不出现百分比代替计数。
- Rust 单测覆盖四类根 × 成功/缺失/损坏，前端 `tsc --noEmit` 与 `vite build` 实际通过；验证记录列出未运行项（Windows 原生安装交互）；通过后 complete、提交推送。

停止：只读任务中心与四类状态投影、零写入验证与前端构建实际完成后 complete、提交推送。下一入口 T03；不直接扩大到后台调度、GUI 审批写入、发布或回滚操作。

## B09-T03 个人版打包配置与安装验收清单

单一可见结果：仓库里有一份可复现的打包配置说明与一份安装后验收清单，逐项写明操作、期望与实际记录位置；本环境可执行的部分（前端构建、Rust release 构建、打包前置检查）实际运行并留下原件，Windows 原生 NSIS 安装与卸载未运行时单列而不声称通过。

依赖：B09-T02。关联 NFR-16、NFR-17、AC-39；只覆盖打包配置与验收清单，不新增功能、不改安装模式、不动用户既有安装。

范围：核对并冻结 `crates/noetome-desktop/tauri.conf.json` 的打包目标、图标集合、NSIS `installMode: currentUser` 与语言；任何修改都要在文档里逐条说明效果与理由。新增 `doc/standards/DESKTOP_ACCEPTANCE.md`，列出安装后必须人工执行的检查项：窗口与装饰、导航与菜单、Rust 通信、帮助与版本、项目入口、任务中心、关闭行为与重启后设置保留、托盘退出。明确静态前端预览与浏览器预览不能替代安装后测试；记录每项的记录位置（截图/日志路径约定）。

顺序：先跑一遍现状（`npm run web:build`、`cargo build --release -p noetome-desktop` 或如实记录不可用原因、`desktop:build` 的可行性）；再核对配置并写验收清单文档；再补一条 `scripts/verify_desktop_package.py` 只读审计（配置取值、图标文件存在且 SHA256 冻结、CSP 取值、清单字段完整性），在真实仓库上跑出通过与失败两种结果；最后更新标准、日志、提交推送。

验收：

- 打包配置的每个取值都能在文档中对应到说明；图标文件存在且指纹冻结；CSP 与既有取值一致，不放宽到 `unsafe-eval` 或远程源。
- `doc/standards/DESKTOP_ACCEPTANCE.md` 的检查项覆盖窗口、导航、通信、帮助/版本、项目入口、任务中心、关闭/重启、托盘；每项含操作、期望、记录位置；明确安装后测试不可被静态预览替代。
- `scripts/verify_desktop_package.py` 在真实仓库通过，并对篡改（改 CSP、删图标、改 installMode）分别报出失败项；文档与脚本不自称 Windows 原生安装已通过。
- 本环境实际执行的构建与检查留下原件（构建日志、审计输出）；`npm run web:build` 与可用的 Rust 构建结果如实记录，不可用项写明原因。验证记录列出未运行项：Windows 原生 NSIS 安装、卸载、安装后人工交互检查。
- 通过后 complete、提交并推送；本批次不宣布科学质量、生产 Vault 或长期规模门槛达标。

停止：打包配置核对、验收清单文档与只读审计脚本实际完成后 complete、提交推送。B09 三张卡收束后按真实剩余差距滚动规划下一批，不直接宣布个人版发布或生产可用。
