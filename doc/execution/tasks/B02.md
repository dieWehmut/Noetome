依赖：B01-T03

关联：FR-08、FR-09、FR-17、FR-35、NFR-17

**先读规范**

- [doc/technical/DATA_CONTRACTS.md](../../../doc/technical/DATA_CONTRACTS.md)
- [doc/technical/ARCHITECTURE.md](../../../doc/technical/ARCHITECTURE.md)

**实现步骤**

1. 将schema.sql转换为编号迁移001，schema0迁移前备份，初始化新schema1。
2. 实现ULID、revision、typed value、Source/Concept/Claim/Atom/Plan序列化与外键校验。
3. 加入迁移前后重开、损坏/未来版本拒绝写入、无效引用与唯一位置测试。
4. 按DATA/CONFIG/MODEL/RUNTIME字段生成四份Draft2020-12 JSON Schema；Rust验证合法/非法fixture，禁止只写type=object空schema。

**必须交付的文件**

- crates/noetome-core/src/contracts.rs
- crates/noetome-core/tests/contracts.rs
- crates/noetome-store/migrations/001_full.sql
- crates/noetome-store/tests/migrations.rs
- schemas/ir.schema.json
- schemas/config.schema.json
- schemas/model-candidate.schema.json
- schemas/ipc.schema.json

**验收结果**

- 迁移成功后integrity_check与foreign_key_check正常，失败保留可恢复旧库。
- 不存在身份按标题重新生成、悬空证据或同计划双canonical位置。

**本任务边界**

- 创建完整契约，不实现所有领域算法。

**失败处理**

- 先保留最小复现与实际错误；同一根因最多连续修复3轮，每轮只改变一个可检验假设。
