# B14 执行卡：可审计日志与问题定位

本批只展开三张卡，全部围绕 PRD FR-40（可审计日志与问题定位）与 NFR-15（凭据不入日志）。
三项都是确定性只读诊断层：只读已冻结的事件与索引声明，零模型调用、零网络请求，只写新
测试根，不碰生产 Vault，不做界面。

## 为什么是这三张

FR-40 的验收写的是三件事：①一次失败能在应用内定位并局部重试；②导出诊断不含明文凭据；
③清理缓存不破坏已发布版本的必需索引。三张卡一一对应，不合并也不扩张：

- **B14-T01 事件日志与四层定位**：把「定位到任务、来源范围、知识对象、受影响文件」做成
  可查询的结构，而不是让人去 grep 日志。
- **B14-T02 带范围与预览的诊断导出**：导出必须有边界（选了哪些、排除了哪些），并把
  凭据与绝对路径当硬错误拒绝，而不是过滤后照样导出。
- **B14-T03 保留与清理策略**：清理计划必须先给出影响说明，并且已发布版本必需的索引与
  追溯条目是**整条拒绝**的保护，不是「跳过继续」。

## B14-T01 可定位任务的审计事件日志与凭据过滤

- 单一可见结果：`journal` 动词（`adopt` / `build` / `list` / `status`）产出确定性事件流与
  四层定位查询结果。
- 依赖：B13-T03。
- 范围：冻结声明含任务、来源、知识对象、受影响文件与错误分类；事件按只追加记录时间、
  版本、错误分类与处理动作；凭据样式字符串出现即整包拒绝。
- 验收：见账本卡片四条。

## B14-T02 带范围与内容预览的诊断导出

- 单一可见结果：`diagnose` 动词产出带范围、条目数、字节数、内容预览与排除项说明的导出包。
- 依赖：B14-T01（复用事件流）。
- 范围：默认排除原文与来源正文；未勾选类别如实标为未导出；凭据与绝对路径出现即拒绝且
  不写任何字节；导出清单无时间戳。
- 验收：见账本卡片四条。

## B14-T03 保留与清理策略及已发布索引保护

- 单一可见结果：`retention` 动词产出清理计划与影响说明，保护集合命中即整条拒绝。
- 依赖：B14-T02。
- 范围：保留策略与可清理类别由声明给出；已发布版本必需索引与追溯条目受保护；影响说明
  必须写清会丢什么恢复能力、追溯链会短多少。
- 验收：见账本卡片四条。

## 顺序

严格 T01 → T02 → T03：后一张复用前一张的产物形状，避免三张卡各自发明一套事件表示。

## 停止条件

一项完成后即验收并提交，不连带开启下一项。三张卡全部完成后按工作流切批次，不在本批
顺手做界面、生产 Vault 写入或真实凭据处理。

## 本批不做

- 不做桌面界面内的日志浏览与局部重试（属于界面层）。
- 不导出真实用户凭据或真实生产日志。
- 不实现存储后端的自动清理守护进程。
- 不宣称科学正确率门槛（200 原子 / 98%）已达标。
- 不改动 workspace 既有的 sidecar/pdf 宿主边界失败。
