## B01 T01 Rust CLI最小骨架

**单一结果**：在Windows x64上能重复构建并运行Noetome CLI的帮助和版本命令。

**依赖**：B00-T01。关联性质：开发基础能力，不代表任何完整产品功能验收通过。

### 操作顺序

1. 检查已有Rust、Cargo及Windows链接工具，记录实际版本；已有合适环境直接复用。缺失时按官方来源核实安装方法，不顺手安装前端、OCR和模型环境。
2. 新建最小Cargo workspace，起步只有 `crates/noetome-cli`。提交锁文件并用 `rust-toolchain.toml` 记录本轮验证过的工具链；不要凭记忆预填“最新版本”。
3. 实现 `noetome --help` 和 `noetome --version`。帮助使用面向用户的语言，列出当前实际支持项；不存在的功能不能显示为可用。
4. 未知参数返回非零退出码和可操作的提示。帮助、版本、无效参数路径均不得创建数据库、Vault或用户配置。
5. 加入少量进程级CLI用例，验证退出码、必要输出及无文件副作用；不要只测试字符串拼接函数。
6. 执行格式、构建和测试，更新日志及README运行说明，小步提交并推送后汇报结果。

**产物范围**：`Cargo.toml`、`Cargo.lock`、`rust-toolchain.toml`、`crates/noetome-cli/Cargo.toml`、CLI源文件及针对性测试。实际执行证据见 [B01-T01验证记录](../validation/B01-T01.md)，任务状态仍以账本为准。

**验收命令**：

```text
cargo fmt --all --check
cargo check --workspace
cargo test --workspace
cargo run -p noetome-cli -- --help
cargo run -p noetome-cli -- --version
```

未知参数用例由测试明确检查非零退出码，不能将预期失败混作构建失败。工具链缺失时记录实际阻塞，不将未运行命令写为通过。

**本轮边界**：不引入SQLite、文档解析、Python侧车、模型SDK、Tauri或插件系统。

**停止点**：上述结果可复现，日志与提交齐全。T02和T03分别验收，不因T01完成顺手启动。

## B01 T02 空项目初始化与只读检查

**单一结果**：CLI能创建一个可识别的空项目，并只读显示其实际状态。

**依赖**：B01-T01。关联需求：FR-01、FR-35的最小基础，尚非完整项目管理与持久任务实现。

### 操作顺序

1. 根据 [数据契约](../technical/DATA_CONTRACTS.md) 定义Project最小字段，规范项目路径和版本。只抽出本轮需要的核心模块；不预建全套空crate。
2. 定义 `noetome project init <path>` 与 `noetome project inspect <path>`，先把命令行为和错误写入测试。
3. 在新目录创建配置和SQLite基础结构，保存项目ID与Schema版本。只创建初始化必需的表，不一次建完PRD中的全部实体。
4. 已有项目、非空未知目录和不可写路径必须明确拒绝，不复用或覆盖不明文件。初始化使用临时工作和明确完成标记处理半成品；失败清理只能触及本次创建的路径。
5. inspect只读展示ID、Schema和“空项目”等实际状态；不修改数据库、不制造“覆盖完成”或“知识已验证”。
6. 在隔离临时目录验证重复初始化、只读检查、占用或写入失败及重试行为，完成最小回归后记录、提交、推送。

**验收**：成功项目可重新打开；两次inspect前后内容指纹一致；未知目录没有未批准变更；半初始化状态有明确恢复方式。

**检查**：沿用T01的格式、构建与测试命令，增加项目初始化集成用例；真实运行一次init和inspect，将退出码及内容对照记入日志。

**本轮边界**：不导入资料，不实现知识图谱、检索或通用迁移框架。

## B01 T03 Windows桌面骨架、图标与本地安装验收

**单一结果**：带用户指定图标的Windows桌面应用能够本地安装，并在安装后的窗口实测已有Rust帮助和版本能力。

**依赖**：B01-T01。关联性质：用户明确要求的桌面交付基础，不代表核心知识功能或完整个人桌面版通过验收。

**计划调整依据**：2026年11月1日用户要求使用 `sample/icon.png`、忽略整个 `sample/` 并在搭建应用后本地安装测试。原T03未启动的文本导入计划转为后续阶段目标，见[路线](ROADMAP.md)和[决策记录](../requirements/DECISIONS.md)。

### 操作顺序

1. 核对已有Windows x64 Rust/MSVC、Node.js和WebView2环境，按官方来源核实Tauri依赖与打包行为，锁定本轮实际选用版本。
2. 将整个 `sample/` 加入Git忽略，只读取用户明确指定的图标。生成ICO和所需PNG，保存原图指纹与派生资源清单；不更改原图，构建不依赖本地样例目录。
3. 新建Tauri入口与React TypeScript工作台，前端只调用共享Rust帮助、版本和运行信息接口；不执行任意shell参数、不提前启用文件或模型插件。
4. 提供工作台、运行检查和关于页面。项目和资料功能保持真实空状态，连接和执行结果来自实际调用，错误显示稳定错误码。检查导航、焦点和较窄窗口下的可用性。
5. 生成Windows当前用户模式的NSIS安装包，使用 `scripts/prepare_desktop_installer.ps1` 在正常用户目录准备字节一致且标签可用的副本，再通过 `scripts/install_desktop.ps1` 本地实际安装。核对安装文件、版本、应用图标、快捷方式和包指纹；安装后运行窗口、导航、Rust通信、帮助和版本，并验证关闭与重启。启动目录或窗口失败必须给出用户可见错误。
6. 执行前端类型检查、Rust格式/构建/测试、CLI回归和开发日志检查，记录实际安装测试及未运行项，小步提交并推送。

**验收**：指定图标进入应用及安装资源；`sample/` 被忽略、原图不变；Windows当前用户安装与安装后运行检查真实通过；未实现能力显示清楚。

**产物范围**：`apps/desktop`、`crates/noetome-desktop`、共享CLI接口、根npm配置与锁文件、图标派生资源和生成脚本、安装包及 `doc/validation/B01-T03.md`。安装包和临时验证产物保存在忽略的构建目录，不进入Git。

**验收命令**：

```text
npm ci
npm run web:check
npm run web:build
npm run desktop:build
./scripts/install_desktop.ps1
cargo fmt --all --check
cargo check --workspace --locked
cargo test --workspace --locked
python -m unittest discover -s tests -p "test_*.py"
python scripts/devlog.py check
git diff --check
```

构建成功不能代替本地安装和窗口实测。完整检查需记录实际Windows环境、安装路径、退出或运行结果、资源及包指纹；环境或工具未执行时明确记为未运行。

**本轮边界**：不实现空项目持久化、资料解析、模型调用、知识生成或Vault写入；不把桌面壳验收扩展为完整桌面版或科学正确率验收。

**停止点**：桌面骨架安装与实测完成，验证证据、日志和提交齐全。之后回到B01-T02，原文本导入按下一批规划再展开。
