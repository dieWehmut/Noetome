# Active Presentation Legacy Author Fixtures

These two public, self-authored engineering cases are frozen before candidates or CLI calls. They reuse byte-identical signed raw comparison sources from `active-presentation-v1`; `source_origins` records each original repository path and its SHA-256 and length. They do not establish scientific accuracy, general text planning, or production publication.

- `legacy_v1_two_objects` sends two explicit objects and one shared property through strict coordination schema 1. No independent applicability/time declaration exists, so presentation fact applicability and time remain `null` despite the raw source's visible background sentence.
- `legacy_v2_two_objects` sends the same original values, units, complete conditions and exceptions through strict schema 2, with explicit, source-backed applicability and year-precision time.

Each input retains the existing Gold2 source-review contract. Input `a` additionally links the exact source exception `结冰时不适用` as `qualifies`, independently of its full `supports` quote. The presentation provenance must preserve this additional original link and evidence, even when the old coordination occurrence only lists supporting evidence.

`authors.json` contains the independent identity and version-specific coordination expectation. The two `expected-*.json` files describe representation, labels, facts, cells, source atom references and missing meaning; they supply no NotePlan, generated IDs, or final Markdown. `frozen-sha256.json` pins every other file. The original 40-file author package remains unchanged.
